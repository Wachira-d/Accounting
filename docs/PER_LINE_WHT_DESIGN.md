# หัก ณ ที่จ่าย "ตามรายการ" (per-line WHT) + ฐานบาทของใบต่างสกุล — ทีม F

> สถานะปัจจุบัน (2026-10-22) · ป้าย ✅ มีจริง (โค้ด+เทสต์) / 🔨 บางส่วน / 📋 ออกแบบไว้ (backlog)
> ตัวคำนวณกลาง: `Helpers/PerLineWht` · ตัวตัดสินอัตรา: `Helpers/DocumentFx.Decide` · OCR: `Helpers/OcrLineWhtPlan` + `Helpers/OcrThbEquivalent` ·

## 1. คำขอ

ผู้ใช้: ในการตั้งค่าบริษัทมีสวิตช์ "หัก ณ ที่จ่ายรายบรรทัด" — เปิดแล้วการสร้างเอกสาร (ขาย/ซื้อ/ใบสำคัญจ่าย) และ OCR รองรับหัก ณ ที่จ่าย
ต่างประเภท/ต่างอัตราในแต่ละบรรทัด (ค่าบริการ 3% + ค่าโฆษณา 2% + ค่าสินค้า 0% ในใบเดียว) ⇒ 50 ทวิ แยกประเภทเงินได้ · ภ.ง.ด.3/53/54 ถูก ·
ใบแจ้งหนี้ต่างสกุลที่ **พิมพ์ยอดแปลงเป็นบาทไว้แล้ว** ⇒ ยึดยอดบาทนั้นเป็นฐาน WHT/VAT · ไม่มียอดบาท ⇒ ต้องออกแบบ (อัตรา ธปท. · ผู้ใช้ยืนยัน/แก้ ·
บันทึกที่มา · ปัด 2 ตำแหน่ง AwayFromZero · ผลต่าง FX ตาม TFRS for NPAEs บทที่ 19)

## 3. กติกา (ตัวตั้งเดียว `Helpers/PerLineWht`)

1. **ฐาน = ก่อน VAT** (`DocumentLine.Amount` หลังส่วนลด) — VAT ไม่ใช่เงินได้ (ท.ป.4/2528 ข้อ 12)
2. **ยอดต่อบรรทัดเก็บเป็นสกุลเอกสาร** (สูตรเดิม) · ผู้อ่านที่ส่งออกเป็นแบบภาษีแปลงเป็น **บาท** ผ่าน `PerLineWht.ForDocument` เท่านั้น
3. **ฐานบาท**: `DocumentThbBase` (ยอดบาทที่พิมพ์ — เฉลี่ยลงบรรทัดตามสัดส่วน เศษไปบรรทัดยอดสูงสุด ⇒ Σ = ยอดบนกระดาษ) ชนะ ·
   ไม่มี/ใช้ไม่ได้ ⇒ `DocumentFx.ToBaht(ฐาน, ExchangeRate)` (ตัวเดียวกับ JE) · ยอดบาทใช้ได้เฉพาะเมื่อ |ฐาน × อัตรา − ยอดบาท| ≤ 0.01
   (`DocumentFx.PrintedBahtRoundTrips` — ฝ่ายค้านข้อ 1: เดิม 1 บาท/0.1% ⇒ VND 98,765,432 ↔ 135,432.10 บาท อัตรา 0.001371 คูณกลับ 135,407.41 ผ่าน ⇒ 50 ทวิ ≠ GL) ·
   ตอนสร้าง: ยอดบาทที่แปลงกลับไม่ได้ ⇒ 400 ให้เว้นยอดบาทแล้วกรอกอัตราเอง · ผู้ใช้แก้บรรทัดจนฐานเปลี่ยน ⇒ ตกไปใช้อัตรา
4. **ภาษีบาท** = `round(ฐานบาท × อัตรา, 2, AwayFromZero)` (นิยามตามกฎหมาย) · ใบออกภาษีแทน ⇒ แปลงยอดที่เก็บไว้ตามสัดส่วน ·
   Σ ผูกกับยอดหนี้ GL `PerLineWht.DocumentWhtThb(WHT ของใบ/งวด, อัตรา)` ด้วย `PerLineWht.TieOut` (เศษ ≤ 0.05 × บรรทัด) — ทั้งใน `ForDocument` (ทุกผู้อ่าน:
   สรุปต่อประเภท · แถวเตือน ภ.ง.ด.) และใน 50 ทวิ (ต่อผู้ถูกหัก/งวด) · `DocumentWhtThb` เป็นเป้าเดียวของ 50 ทวิ · JE ตอนจ่าย (`CreatePaymentJournalAsync`) ·
   หน้านำส่ง/ปฏิทิน (`StatutoryRemittanceService`) · ตัวกระทบ GL (`TaxGlReconciliationService`) — ล็อกจุดเรียกด้วย `tools/required_call_site_check.py` กลุ่ม `_PLWHT`
5. **ใบบาท** ⇒ คืนยอดที่เก็บไว้ตรงตัว (ไม่คำนวณใหม่) — ปิด/เปิดค่าตั้งไม่ทำให้สตางค์ไหนขยับ (เทสต์ทิศตรงข้าม `Thb_document_returns_stored_amounts_exactly…`)
6. **เกณฑ์ 1,000 บาท** ดูทั้งการจ่าย/ทั้งสัญญา **ไม่ใช่ต่อบรรทัด** — ตัวคำนวณ/แผน OCR ไม่ตัดสินเกณฑ์ใหม่ต่อบรรทัด (ค่าโฆษณา 600 ในใบที่หักอยู่แล้วก็หัก) ·
   ด่านเกณฑ์ระดับใบ/คู่สัญญาเป็นตัวเดิม (ข้อ 2 ตาราง)
7. บรรทัดหักแต่ไม่ระบุประเภท ⇒ รหัส `"8"` (ค่าตั้งต้นเดียวกับ 50 ทวิ ที่ใช้มาตลอด)

## 4. อัตราแลกเปลี่ยน — ตัวตัดสินเดียว `DocumentFx.Decide` (ตอนสร้าง หลังคิดยอดบรรทัด)

| เคส | อัตรา | `ExchangeRateSource` | `DocumentThbBase` |
| --- | --- | --- | --- |
| ใบบาท | 1 | null | null (ส่งมา = 400) |
| ส่งยอดบาทตามเอกสาร | `round(ยอดบาท ÷ ฐานสกุลเอกสาร, 6, AwayFromZero)` | `Document` | ยอดที่ส่ง (≤ 0 / ฐาน 0 = 400) |
| ใบลด/เพิ่มหนี้ · ใบที่แปลงมา (อัตราเท่าใบต้นทาง) + ส่งยอดบาท | คงอัตราใบต้นทาง (ตัดหนี้ต้องเท่ายอดที่ตั้ง) | ของใบต้นทาง | ยอดที่ส่ง |
| แปลงมาเต็มจำนวน (ฐานเท่ากัน) จากใบที่มียอดบาท | ของใบต้นทาง | ของใบต้นทาง | **สืบทอด** (กฎ #4 A เอกสารลูก) |
| ส่งอัตรามา | ที่ส่ง | `User` (หรือ `BOT` ถ้าผู้เรียกบอก) | null |
| ไม่ส่งอัตรา | ธปท. วันที่เอกสาร | `BOT` | null |

- OCR (เปิดค่าตั้ง): `OcrThbEquivalent.Read` อ่านอัตราที่พิมพ์ ("1 USD = 36.50 THB" · "Exchange rate" · "อัตราแลกเปลี่ยน") + ยอดบาท (ก่อน VAT / VAT / ยอดรวม /
  "เทียบเท่าเงินบาท"/"คิดเป็นเงินบาท") เฉพาะบรรทัดที่มีคำบ่งบาท+ป้ายยอด (ข้าม "…บาทถ้วน") → `Plan` ตรวจความสอดคล้อง (ฐาน · ยอดรวม · อัตราที่พิมพ์ ห่าง ≤ 0.5%) ·
  ใช้ได้ ⇒ `[FX-DOC]` + อัตรา/ฐานบาทตามกระดาษ · ขัดกัน/แปลงกลับไม่ได้ ⇒ `[FX-DOC-CONFLICT]` (หยุดอนุมัติเอง) + ใช้ ธปท. · **หลักฐานแหล่งเดียว**
  (ตัวเลขบาท/อัตราที่พิมพ์อิสระกัน < 2 ตัว) ต้องห่างอัตรา ธปท. ≤ 3% ไม่งั้น `[FX-DOC-UNVERIFIED]` + ใช้ ธปท. (ฝ่ายค้านข้อ 2) · ปิดค่าตั้ง ⇒ ธปท. เหมือนเดิม (ที่มา `BOT`)
- ฟอร์ม: ช่อง "ยอดบาทตามเอกสาร (ก่อน VAT)" ใต้อัตรา (ใบต่างสกุล · ตอนสร้าง) · แก้ไข = แสดงอ่านอย่างเดียว + ที่มาอัตรา (ตรึงเหมือนอัตรา — ไม่มี silent no-op)
- หน้ารายละเอียด: ที่มาอัตรา (ป้ายจากเซิร์ฟเวอร์ `ExchangeRateSourceLabel`) + ฐานบาทตามเอกสาร
- **หลักกรมสรรพากรเรื่องอัตรา** (📋 รอนักบัญชียืนยัน — ห้ามฝังเป็นกฎแข็งจนกว่ายืนยัน): VAT ใช้อัตราตามประกาศ ธปท. (อัตราซื้อถัวเฉลี่ยของธนาคารพาณิชย์)
  ของวันทำการก่อนวันที่ความรับผิดเกิด (§79/4 · tax point) · WHT ใช้อัตรา ณ วันจ่าย (เงินได้ที่จ่ายเป็นเงินตราต่างประเทศ ม.3 เตรส/ม.70) ⇒ ใบที่ตั้งหนี้วันหนึ่ง
  แล้วจ่ายอีกวัน 50 ทวิ ควรใช้อัตรา ณ วันจ่าย — ดู backlog B-3

## 5. OCR ต่อบรรทัด — `Helpers/OcrLineWhtPlan` (เปิดค่าตั้งเท่านั้น · ไม่มี AI · local-first)

- จัดประเภทต่อบรรทัดด้วยกฎชุดเดียวกับทั้งใบ `ExpenseCategoryResolver.ClassifyLineForWht(คำอธิบายบรรทัด)` — ไม่ใช้ชื่อผู้ขาย/ข้อความทั้งหน้า ·
  ผล: หักได้ (รหัส ม.40) / ไม่อยู่ในข่าย (สินค้าล้วน · หมวดไม่มีรหัส) / ตัดสินไม่ได้ (ตามหัวใบ — ไม่แต่ง)
- ใช้เฉพาะเมื่อหัวใบมีหักอยู่แล้ว (กระดาษพิมพ์/ผู้ใช้ยืนยัน) — แผน **กระจาย** ยอดเดิม ไม่ได้ตัดสินว่าต้องหักไหม
- Σ ตามแผนต้องอธิบายยอดหัวใบได้ (± 1.00 **บาท** — ใบต่างสกุลแปลงด้วยอัตรา ธปท. · ไม่รู้อัตรา = ± 0.01) ⇒ ใช้ (เศษไปบรรทัดภาษีสูงสุด · ยอดใบ/ยอดจ่าย/JE ไม่ขยับ) + `[WHT-LINE]` ·
  ไม่ได้ ⇒ คงแบบเดิม + `[WHT-LINE-MISMATCH]` · **ทั้งสองแท็กหยุดการอนุมัติเอง** (`OcrPostingReadiness.BlockingTags` — LINE/auto-approve ต้องมีคนยืนยัน) และถูกคำนวณใหม่ทุกครั้งที่สร้างบรรทัด (`OcrLineBuildNotes`)
- อัตราที่ขึ้นกับชนิดผู้รับ (ดอกเบี้ย 15%/1%) + ไม่รู้ชนิด ⇒ ตามหัวใบ (ไม่เดา)
- กฎเหล็ก #1: ไม่มีการเรียก AI ใหม่ — ตัวจัดประเภทเป็นกฎ (rule resolver) ⇒ kill-switch ผ่านโดยโครงสร้าง

## 6. สรุปต่อประเภท (server computes · page displays)

- `DocumentResponse.WhtByIncomeType` = `PerLineWht.GroupsOf(doc)` (บาท · ต่อ (ประเภท, อัตรา)) — หน้ารายละเอียดแสดงเมื่อ ≥ 2 กลุ่มหรือใบต่างสกุล
- กระดาษ (HTML + QuestPDF คู่กัน): แถวย่อย "— หัก n%" ใต้ "ภาษีหัก ณ ที่จ่าย" เมื่อใบมีหลายอัตรา (`PerLineWht.RateBreakdownForPrint` · ป้าย `DocumentLabels.TotalWhtAtRate`
  ไทย/อังกฤษ) · อัตราเดียว ⇒ กระดาษเหมือนเดิมทุกบรรทัด
