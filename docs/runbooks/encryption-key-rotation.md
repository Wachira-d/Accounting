# Runbook — หมุนคีย์เข้ารหัส (`ENCRYPTION_KEY`)

> รอบ 275 แพ็ก A (T4 H-1 · M-1 · M-4) · สำหรับผู้ดูแลแพลตฟอร์ม (ผู้ใช้ของบริษัทตั้ง env ไม่ได้ — ข้อความถึงผู้ใช้ชี้ไปหน้า "ตั้งค่า › สุขภาพข้อมูลเข้ารหัส")

## คีย์หนึ่งตัวคุมอะไรบ้าง

`ENCRYPTION_KEY` (หรือ `Security:EncryptionKey`) ใช้ทั้ง
- **คอลัมน์ PII** (`EncryptedColumnConverter`): เลขบัตร/เลขผู้เสียภาษี/เลขบัญชี/เลขประกันสังคม/พาสปอร์ตพนักงาน · แถวนำเข้า · โปรไฟล์ผู้ลงนาม
- **ความลับใน DB** (`SecretProtector`): SMTP/Microsoft 365/Gmail · LINE OA · e-Tax (รหัสใบรับรอง + RD secret) · ช่องทางชำระ (Omise ฯลฯ) · webhook · bank feed · ลิงก์ชำระ · LINE id ของผู้ติดต่อ
- **HMAC** ที่ derive จากคีย์ (OTP ผู้ลงนาม · `SubjectKey` โปรไฟล์ผู้ลงนาม · `TaxSlipRefHash`) — **ไม่มีคีย์เดิม**: หมุนแล้วค่าเดิมเทียบไม่ตรง (OTP ที่ค้างต้องขอใหม่ · โปรไฟล์ผู้ลงนามเดิมหาไม่เจอ · ใบขอชำระภาษีที่ออกก่อนหมุนจับคู่สลิปไม่ได้ — ออกใบขอชำระใหม่)

ทั้ง PII และความลับใช้ **ห่วงโซ่คีย์ถอดตัวเดียว** `EncryptionKeyResolver.DecryptKeyChain`: คีย์ปัจจุบัน → `ENCRYPTION_KEY_PREVIOUS` (หรือ `Security:EncryptionKeyPrevious`) → `ENCRYPTION_KEY_PREVIOUS_2` … `_9` → config เดิม/dev key · เขียนด้วยคีย์ปัจจุบันเสมอ

## ขั้นตอน (ห้ามข้าม)

1. **สร้างคีย์ใหม่** (สุ่ม ≥ 32 ตัวอักษร) · เก็บคีย์เดิมไว้ในที่ปลอดภัย
2. **ทุกเครื่องพร้อมกัน**: ตั้ง `ENCRYPTION_KEY=<คีย์ใหม่>` และ `ENCRYPTION_KEY_PREVIOUS=<คีย์เดิม>`
   - หมุนซ้ำโดยงานย้ายรอบก่อนยังไม่จบ ⇒ ใส่คีย์เก่ากว่าใน `ENCRYPTION_KEY_PREVIOUS_2` (… `_9`) หรือใส่หลายคีย์ใน `ENCRYPTION_KEY_PREVIOUS` คั่นด้วย**ขึ้นบรรทัดใหม่**
   - **ห้าม**ให้เครื่องใดยังรันด้วยคีย์เดิมเป็น `ENCRYPTION_KEY` — ระบบตรวจลายนิ้วมือคีย์ (`SiteSettings.EncryptionKeyFingerprint`) แล้ว**หยุดงานย้ายคีย์**บนเครื่องที่ไม่ตรง (K6)
3. **รีสตาร์ต** · ข้อมูลทุกอย่างอ่านได้ทันทีผ่านคีย์เดิม (ไม่มีอะไรดับ)
4. **รอทั้งสองงานสำเร็จ** (หลังบูต 3 นาที แล้วทุก 6 ชั่วโมง · ใต้ JobLock · audit ต่อแถว): `PiiReprotect` และ `SecretReprotect` ใน admin › งานเบื้องหลัง
5. **ตรวจหน้า admin › งานเบื้องหลัง › 🔐 สุขภาพคีย์เข้ารหัส**:
   - ผลลายนิ้วมือ = `Match` (หรือ `Rotated` ครั้งแรก)
   - ความลับ "ยังอยู่บนคีย์เดิม" = 0 · "ใช้ไม่ได้" = 0 (ถ้าไม่ 0 = ค่าที่เข้ารหัสด้วยคีย์ที่ไม่มีในห่วงโซ่ ⇒ หาคีย์นั้นมาใส่ PREVIOUS_n หรือให้ผู้ใช้กรอกใหม่)
   - บรรทัด "✓ ไม่มีข้อมูลบนคีย์เดิมเหลือ — ถอด ENCRYPTION_KEY_PREVIOUS ออกได้"
6. **ถอด `ENCRYPTION_KEY_PREVIOUS`** แล้วรีสตาร์ต (แนะนำเก็บคีย์เดิมไว้อย่างน้อยหนึ่งรอบสำรองข้อมูล — restore ฐานสำรองเก่าต้องใช้คีย์นั้น)

## เมื่อหน้า admin ขึ้น ⛔ คีย์ไม่ตรง

| ผล | ความหมาย | ทำอะไร |
|---|---|---|
| `Mismatch` | ฐานบันทึกคีย์ที่เครื่องนี้ไม่รู้จัก | ตรวจ `ENCRYPTION_KEY` ทุกเครื่องให้ตรงกัน · restore ฐานจากที่อื่น ⇒ ตั้งคีย์ของฐานนั้น · แน่ใจแล้วกด "ยืนยันคีย์ปัจจุบัน" (audit + เหตุผล) |
| `RotatedBack` | เครื่องนี้ใช้คีย์ที่เพิ่งหมุนออกไป | มีเครื่องที่ยังไม่ได้ตั้งคีย์ใหม่ — ตั้งให้ครบ · ตั้งใจย้อนกลับจริง ⇒ กด "ยืนยันคีย์ปัจจุบัน" |

ระหว่างไม่ตรง งานย้ายคีย์**ไม่เขียนแถว** (กันย้ายข้อมูลไปคีย์ที่เครื่องอื่นอ่านไม่ได้) · JobRunLog บันทึก "ไม่ย้ายคีย์: …" · log ระดับ Error รหัส `SEC-KEY-FINGERPRINT`

## ความลับที่ใช้ไม่ได้ทำอะไรบ้าง (ล้มดัง ไม่ใช้ค่าว่าง)

ตัวตัดสินเดียว `Helpers/SecretUse` — ตั้งไว้แต่ถอดไม่ได้ ⇒ ไม่ส่ง/ไม่ยืนยันตัวตนด้วยค่าว่าง และบอกเหตุจริง:
webhook ขาออกไม่ส่ง (แถวประวัติการส่งบอกเหตุ) · webhook CMS ขาเข้าไม่ตรวจลายเซ็นด้วยกุญแจว่าง · e-Tax ไม่เซ็น/ไม่ส่งพร้อมเหตุบนแถว · อีเมลตอบล้มพร้อมเหตุ ·
Omise/ธนาคารบอก "ที่บันทึกไว้ใช้ไม่ได้" แทน "ยังไม่ได้ตั้งค่า" · Google/LINE/Facebook login ปฏิเสธพร้อมเหตุ (Facebook ไม่ข้ามการตรวจ app id อีก) · LINE OA ของบริษัทบอกเหตุจริงในผลส่ง

ผู้ใช้ของบริษัทเห็นรายการทั้งหมดที่ **ตั้งค่า › สุขภาพข้อมูลเข้ารหัส** (`/pages/encryption-health.html`)
