## 6. ทางเข้าอื่นที่แตะข้อมูลชุดเดียวกัน (F3 ข้อ 8)

- `DocumentPaymentHandler` (portal ลูกค้าจ่ายใบแจ้งหนี้): ใช้ `GatewayPaymentRecord.Reference` ตัวเดียวกัน (รูปเดิมทุกตัวอักษร — มีเทสต์ล็อก) · หาเอกสารไม่พบ ⇒ โยนแทน return เงียบ
- `PosOrderPaymentHandler` / `AddOnPurchasePaymentHandler` / `SubscriptionPaymentHandler`: นอกขอบเขต CMS — ไม่ได้แตะ (ล้มแล้วได้แจ้งเจ้าของจาก G-1 ด้วย)
- `CmsWebhookController` (webhook รูปแบบเดิมของหน้าร้าน · HMAC ของเรา) และปุ่มยืนยันของพนักงาน (`CmsCommerceController` confirm-payment): ยืนยันด้วย `PaymentId` ที่ส่งมา — ไม่ผ่าน handler ใหม่ แต่ผ่านด่านรับเกินยอด `SITE-ORDER-OVERPAY` ใน `ConfirmPaymentAsync` เดียวกัน
- `SyncBookingToErpAsync` (ทั้งเส้นแขกและปุ่ม sync-erp ของพนักงาน): query การจองมี `CompanyId` แล้ว (กฎ M · ฝ่ายค้าน ข้อ 7)
