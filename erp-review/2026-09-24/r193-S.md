### 1.1 G2-01 / ข้อ 37 — คีย์ integration (`int_`)

| ส่วน | ก่อน | หลัง |
|---|---|---|
| ออก/แก้/ลบ/สร้างคีย์ใหม่ (`POST/PUT/DELETE /integrations…`, `regenerate-key`) | `[Authorize]` = ใครล็อกอินก็ได้ | `RequireOwnerAsync` — `CompanyUser.Role` Owner/SystemAdmin (กลไกเดียวกับ `OwnerConfigController`) · **ปฏิเสธเสมอเมื่อเข้าด้วย API key** (คีย์ออกคีย์ไม่ได้) |
| ผูก/ลบผู้ใช้ที่คีย์สวมได้ (`user-mappings`) | ไม่มีด่าน · ไม่ตรวจว่า integration เป็นของบริษัท | Owner เท่านั้น + ตรวจ `ExternalIntegrations.CompanyId == companyId` (กฎ M) |
| Account Mapping (`mappings` POST/PUT/DELETE) | ไม่มีด่าน | `CompanySettings.Edit` (คีย์เดิม · Owner ผ่านอัตโนมัติ) — ไม่ใช่การให้สิทธิ์คีย์ จึงไม่บังคับ Owner |
| สิทธิ์ของคีย์ | middleware ตั้ง `ApiKeyCanRead/Write/Delete = true` ตายตัว | คอลัมน์ใหม่ `CanRead/CanWrite/CanDelete` + `IsLegacyKey` + `LegacyDeprecatesAt` · middleware อ่านจาก DB ผ่าน `IntegrationKeyPolicy.EffectiveScopes` |
| คีย์ใหม่ | สิทธิ์เต็ม | ค่าเริ่มต้น **อ่านอย่างเดียว** · เจ้าของเลือกเขียน/ลบเองในฟอร์มสร้าง (`ScopesForNewKey`: ไม่ส่ง = read-only ไม่ใช่ "ทั้งหมด") |
| คีย์เดิม (TakeTime) | — | migration ติด `IsLegacyKey=true` + `LegacyDeprecatesAt = now + 90 วัน` (`IntegrationKeyPolicy.LegacyGraceDays` ตัวตั้งตัวเดียว) · ในช่วงผ่อนผัน = **สิทธิ์เต็มเหมือนเดิม** · หลังวันนั้นใช้ค่าที่เก็บ (= อ่านอย่างเดียว) ⇒ เขียนได้ 403 พร้อมข้อความชี้ทาง (ไม่เงียบ) |
| `X-Acting-User` | แถว mapping → **email match สมาชิกคนไหนก็ได้** (รวมเจ้าของ) | คีย์ใหม่: **เฉพาะแถว `IntegrationUserMapping`** · คีย์รุ่นเก่าในช่วงผ่อนผัน: email match ยังได้ แต่ `LogWarning` + แถว `AuditLog` (`EntityType=IntegrationActingUser`, `Action=ApiAccess`) **ทุกครั้ง** · response header `X-Acting-User-Resolved: mapping|legacy-email-match|unmapped` บอกคู่ค้าตรง ๆ |
| ทางเข้า `X-Integration-Key` (`/api/integration/*`, `[AllowAnonymous]`) | ไม่ผ่าน `ApiKeyScopeFilter` เลย | `ExternalIntegrationController : IAsyncActionFilter` ตรวจ `IntegrationKeyPolicy.Allows` ก่อนทุก action (R5 — ไม่งั้นคีย์ read-only ยังสร้างใบกำกับ/void/กลับ JE ผ่านทางนี้ได้) · `ValidateApiKeyAsync` คืนสิทธิ์จริงด้วย |
| method → สิทธิ์ | ตารางใน `ApiKeyScopeFilter` | `IntegrationKeyPolicy.RequiredScope` ตัวเดียว (ฟิลเตอร์ของ `acc_` ใช้ตัวเดียวกัน · method ไม่รู้จัก = เขียน · fail closed) |
| หน้า `integrations.html` | — | ฟอร์มสร้าง/แก้มีช่องสิทธิ์ (แก้: ส่งสิทธิ์เฉพาะเมื่อผู้ใช้แตะ — แก้ชื่อคีย์รุ่นเก่าต้องไม่เสียสิทธิ์เงียบ · แตะแล้วยืนยันการย้ายนโยบาย) · แผง "สิทธิ์ของคีย์" (ใช้ได้ตอนนี้/ที่ตั้งไว้ — ค่าจากเซิร์ฟเวอร์) · **ประกาศคีย์รุ่นเก่า + วันเลิกใช้** · แผง "ผู้ใช้ที่คีย์สวมได้" (เดิมมี endpoint แต่ไม่มี UI ⇒ คีย์ใหม่จะไม่มีทางผูกผู้ใช้ได้) · ป้าย "คีย์รุ่นเก่า" ในรายการ · หนี `systemName/systemType` ที่ฝังใน innerHTML |

## 4. ข้อที่ต้องให้เจ้าของรู้/ตัดสิน
- **วันเลิกใช้ = วันที่ deploy + 90 วัน** (ค่าที่เสนอ · เปลี่ยนที่ `IntegrationKeyPolicy.LegacyGraceDays` ที่เดียว — แต่ค่าที่ migration เขียนลงแถวแล้วจะไม่เลื่อนตาม ต้อง UPDATE มือถ้าเปลี่ยนหลัง deploy)
- **สร้างคีย์ใหม่ (regenerate) ของคีย์รุ่นเก่า ไม่ย้ายนโยบาย** — สิทธิ์/ธงเป็นของ integration ไม่ใช่ของ secret (ไม่ทำ TakeTime พังเมื่อเจ้าของแค่หมุนคีย์) · การย้ายนโยบายเกิดเมื่อเจ้าของ "แก้สิทธิ์" เท่านั้น
- หลังวันเลิกใช้ คีย์รุ่นเก่า**ยังอ่านได้** (ไม่ตัดขาดทั้งดอก) — การเขียนได้ 403 พร้อมข้อความ
- `GET user-mappings` ยังเปิดให้สมาชิกทุกคนอ่าน (เห็นอีเมลผู้ใช้ที่ผูก) — ไม่ใช่ขอบเขตรอบนี้
