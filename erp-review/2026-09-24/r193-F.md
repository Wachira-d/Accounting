## สรุป

ทุกข้อ verify กับโค้ดปัจจุบันก่อนแก้ — A01/A02/A03/A04/A06/A08/A09/A10 **ยังเปิดอยู่จริง** (รอบ 187–189 ไม่ได้แตะ DTO เหล่านี้)
ส่วน A14 (checker มองไม่เห็น record หลายบรรทัด) ปิดไปแล้วที่ `fb42474` (ตอนนี้นับได้ 636 ชนิด) — ไม่แตะ

หลักที่ใช้ตัดสิน "แก้ฟอร์ม หรือแก้ DTO":
- **ค่าที่ derive ได้** → DTO เป็น `string?` + ค่าเริ่มต้นฝั่ง service (ReportType จาก chart · ชื่อสกุลเงินจากรหัส · ฐาน FP&A = Actual)
- **ค่าที่เป็นนโยบายธุรกิจ** (วิธีรับรู้รายได้ · ฐาน/วิธีคำนวณคอมมิชชัน) → ขึ้นฟอร์มเป็น dropdown ป้ายไทย **และ** DTO `string?`
  (null จาก API = ค่าเริ่มต้นเดียวกับ entity) · ชุดค่า + ป้ายอยู่ใน `Helpers/` ตัวเดียว หน้าเว็บดึงผ่าน endpoint (ไม่มีสำเนาใน JS)
- **ค่านอกชุด = `BusinessRuleException` ไทย** ไม่ใช่เก็บเงียบ ๆ
- ช่องที่ Update ไม่รับ → **ล็อก + บอกเหตุผล** (ห้าม silent no-op) · ช่องตัวเลขว่าง → ตัดคีย์ / ฟ้องไทยก่อนยิง
