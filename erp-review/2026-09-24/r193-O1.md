### ข้อ 10 — e-Tax XML จริงของ Shopee (`ETDA-invoice.xml` ใน PDF จาก pdfmake)
ช่องว่างที่พบและแก้ใน `Services/Implementations/Ocr/EtaxPdfXmlExtractor.cs`:
1. `FindFilespecXmlRef` — `IndexOf(b, −1)` โยน exception เมื่อ Filespec ตัวแรกไม่ใช่ .xml ⇒ ทั้งไฟล์ตกไป OCR เงียบ ๆ
2. ชื่อไฟล์ hex UTF-16 (`<FEFF…>`) ที่ PDFKit ใช้ — อ่านไม่ได้
3. `FindFilespecPointingTo` — regex ไม่เคยแมตช์ ⇒ ชื่อไฟล์ "embedded.xml" เสมอ
4. `ReadStream` — หาคำ "stream" ตัวแรก ⇒ dict ที่มี `octet-stream` ตัดสตรีมผิดตำแหน่ง
5. ยอดบรรทัดอยู่ใน `NetLineTotalAmount` (ไม่มี `LineTotalAmount`) ⇒ ยอดบรรทัดว่างทุกบรรทัด
6. BOM นำหน้า ⇒ `XDocument.Parse` ปฏิเสธ
7. `T03` (ใบเสร็จ/ใบกำกับ) ถูก map เป็น Receipt ⇒ กระดาษถูกตีว่าไม่ใช่ใบกำกับ → ตาราง ETDA ครบ (`MapTypeCodeToInternal` เปิดเป็น `internal` ให้เทสต์)

ยอด XML เป็นตัวตั้งที่แข็งที่สุด (ไม่ผ่านขั้นยึดยอด) · ข้อความหน้า PDF (`PdfTextLayerExtractor`) ใช้หา**เฉพาะ**การปรับตอนชำระที่ XML ไม่มี
(`OcrService.cs:331` + `ApplyEtaxSettlement` `:7221`) ⇒ ใบ Shopee ที่เป็น XML ได้ `[PAY≠TOTAL]` + `[PAY-PLAN]` เหมือนใบ PDF

## 5. คำถามค้าง / ความเสี่ยงที่ต้องให้เจ้าของหรือทีมอื่นตัดสิน

1. **`ApprovalService` (workflow อนุมัติหลายขั้นบนเว็บ)** ส่ง `acknowledgeWarnings:true` ภายใน ⇒ คำเตือน [Σ-GAP] ไม่ขึ้นบนเส้นนั้น (ตามโจทย์ "ภายในคงเดิม") — ต้องการให้ขึ้นไหม
2. **ใบตั้งหนี้ (PI/Expense) จากสแกน** ยังติด [PAY≠TOTAL] (ไม่อนุมัติเอง) จนกว่าจะบันทึกการชำระ — เพราะบรรทัดปรับอยู่ที่การชำระ ไม่ใช่ที่เอกสาร · ถ้าต้องการ 1-click ต้องตัดสินว่า "ข้อเสนอที่รอชำระ" ปลดได้ไหม
3. **กระทบยอดธนาคาร**: PV จ่ายในตัวยังมี `TotalAmount`/`PaidAmount` = 536 ขณะที่เงินออกจริง 438 (JE ถูก — ขาเงินสดสุทธิ 438) — ตัวจับคู่ statement ที่เทียบยอดเอกสารจะเห็น 536 ≠ 438 · ควรให้ตัวจับคู่อ่าน `ActualPaidAmount` (ทีม F/E)
4. **พรีวิว JE ก่อนอนุมัติ (projected GL)** ไม่รวม adjusting lines/ขาส่วนต่าง/ขาปัดเศษ — ผู้ใช้จะเห็นพรีวิวต่างจาก JE จริงเศษ/ส่วนต่าง
5. **`TaxService` ฐาน VAT ใช้ `SubTotal`** — ถูกตามกระดาษแล้ว (4,695.33) แต่รายงานที่รวมจาก `Σ Line.Amount` จะต่าง 0.01 ต่อใบที่มีผลต่างปัดเศษ — ควรตรวจรายงานที่อ่านรายบรรทัด
6. **เส้น UI handoff/สร้างจากหน้าอื่น** (เช่น convert/clone/recurring) — `RoundingAdjustment`/`ActualPaidAmount` **ไม่สืบทอด** ไปเอกสารลูก (ตั้งใจ: ผลต่างปัดเศษเป็นของบรรทัดชุดนั้น · ยอดชำระจริงเป็นของการจ่ายครั้งนั้น) — ยืนยันว่าถูกต้องตามกฎ #4 A "เอกสารลูกสืบทอด"
7. ผัง 51150 มีเฉพาะบริษัทที่มี 11500 (migration เดิม) + บริษัทใหม่ — บริษัทเก่าที่ไม่มีจะได้ข้อความ "ไม่พบผังบัญชี 51150" ตอนบันทึก (ทางไปต่อ: เพิ่มผัง) · ต้องการ migration ใส่ให้ทุกบริษัทเหมือน 54960 ไหม
8. `MapTypeCodeToInternal` เปลี่ยนเป็น `internal` (เดิม `private`) เพื่อเทสต์ · ฝั่งขาออก `EtaxDocumentTypeMap` ส่ง `Receipt → T03` — ETDA T03 = ใบเสร็จ/ใบกำกับภาษี ถ้าเอกสาร Receipt ไม่ใช่ใบกำกับจริงควรเป็น T01 (นอกขอบเขต O1 — ฝากทีม E ตรวจ)
9. F3 ข้อ 11 (ฝ่ายค้าน): agent นี้ไม่มีเครื่องมือเรียก subagent — ตรวจเองตาม 3 คำถาม (ทางเข้าอื่น · ทิศตรงข้าม · สถานะประทับเอง) แล้วบันทึกข้างบน · **ขอให้ main agent ส่ง diff เงิน/ภาษีรอบนี้ให้ฝ่ายค้านอีกรอบ**
