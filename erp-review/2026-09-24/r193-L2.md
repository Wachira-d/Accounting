## 1. สรุปสิ่งที่เปลี่ยน

### 1.1 วิธีบันทึกเงินมัดจำ (#34) — `Helpers/DepositPolicyResolver.cs` (owner file เดียว)
| โหมด (`DepositVatTreatment`, ชื่อ enum ใน API) | ใบมัดจำ | JE (มัดจำ 1,000 รวม VAT) | ใบสุดท้าย |
|---|---|---|---|
| `FullDeposit` = 1 รับเป็นมัดจำเต็มยอด ไม่แยก VAT | ใบเสร็จ (VAT บรรทัด 0 + ธงพัก) | Cr 217xx 1,000 | ใบเต็มราคา + ตัดชำระด้วยมัดจำ (`ApplyDepositToInvoiceAsync`) |
| `VatPendingUndue` = 2 แยก VAT รอเรียกเก็บ | ใบเสร็จ (ไม่ใช่ใบกำกับ) | Cr 217xx 934.58 + Cr 21913 65.42 | ใบเต็มราคา + ตัดชำระ (Dr 217xx + Dr 21913 / Cr ลูกหนี้) |
| `VatImmediate` = 3 ออกใบกำกับ VAT ทันที (§78/1) | ใบกำกับภาษี/ใบเสร็จ (เลขชุด TIV เมื่อผู้ซื้อครบ §86/4) | Cr 217xx 934.58 + Cr 21911 65.42 (ภ.พ.30 เดือนที่รับ) | **หักฐานมัดจำออกจากฐานภาษี** + `RealizeDepositAsync(ฐาน)` |

- ลำดับชั้น: ที่พักตั้งทับ (`LodgingProperty.DepositVatTreatment`) → บริษัท (`CompanySettings.DepositVatTreatment`, NULL = ไม่เคยตั้ง) → ประเภทธุรกิจ (`Company.IndustryType` → `NatureOf`: บริการ/สินค้า/ไม่ทราบ)
- ค่าเริ่มต้นเมื่อยังไม่มีใครตั้ง = `VatImmediate` ทุกประเภท — บริการ = กฎหมาย · สินค้า/ไม่ทราบ = พฤติกรรมเดิมของทุกทางเข้า (radio ฟอร์มเอกสาร, ที่พัก false, integration false) ⇒ **ไม่เปลี่ยนใครเงียบ ๆ** · ไม่ทราบประเภท → `NeedsOwnerChoice` หน้าตั้งค่าแสดงเด่น
- บริการเลือกโหมดที่ไม่ใช่ VAT ทันที → คำเตือน `RD-78/1-DEPOSIT-VAT` (หน้าตั้งค่าบริษัท · หน้าตั้งค่าที่พัก · หมายเหตุภายในใบมัดจำ · หมายเหตุการจอง · audit) · สินค้า → แจ้ง `RD-78-DEPOSIT-VAT`
- **วิธีหักที่ใบสุดท้ายไม่ใช่ค่าตั้งแยก** — ตามมาจากโหมดของใบมัดจำ (อ่านย้อนจากช่องที่ตรึงบนใบ `OfDocument`) จึงไม่มีคู่ที่ผิดกฎหมายให้เลือกได้ (ตอบ audit §5 ข้อ 3)
- ตัวเลขใบสุดท้าย 7,450 − มัดจำ 2,000 (VAT ทันที): ฐาน 6,962.62 − 1,869.16 = 5,093.46 · VAT 356.54 · เก็บ 5,450 · VAT รวมทั้งเรื่อง 130.84 + 356.54 = 487.38 ครั้งเดียว · PDF พิมพ์แถว "หักมูลค่ามัดจำ (ก่อน VAT) ตามใบกำกับภาษี {เลข}" (ทั้งสอง renderer · `DocumentLabels.TotalDepositTaxInvoiced` · ตัวตัดสิน `BillDeductionIsTaxedDeposit`)
- ตาข่าย: VAT ใบสุดท้ายไม่ตรง `FinalInvoiceVat` (มีบรรทัดอัตราอื่นปน) → หมายเหตุเตือนบนการจอง

### 1.3 ยกเลิก/no-show (F-03 + P0-2) — `CancelCoreAsync` + `RecordRefundPaidAsync` ใหม่
- ยกเลิก **ไม่ลง JE คืนเงิน/ใบลดหนี้อีกแล้ว** — ตั้ง `RefundAmount` = ยอด "ต้องคืน" · `RefundPaidAmount` = ยอด "คืนแล้วจริง" · สถานะ `RefundState` (None/Pending/Paid) คำนวณจากสองตัวเลขนี้เท่านั้น
- ส่วนที่ริบ → `RealizeDepositAsync(ฐาน)` (เดิมส่ง gross เข้าช่องฐาน ⇒ ล้มทุกครั้งเมื่อจด VAT) · ฐานที่ริบ = ฐานคงเหลือ − ฐานที่จะคืน (สูตรเดียวกับ `RefundDepositAsync`) ⇒ คืนภายหลังไม่ติดด่าน
- ลำดับใหม่: บันทึกสถานะยกเลิก + ยอดค้างคืนก่อน แล้วค่อยลงบัญชีส่วนที่ริบ (~~กดซ้ำถูกด่านสถานะกัน~~ **ไม่จริงสำหรับเส้นแขก `CancelByTokenAsync`** — ฝ่ายค้าน C3 · แก้แล้วใน §9: ด่านย้ายเข้า `CancelCoreAsync`)
- `POST /lodging/reservations/{id}/refund-paid` (สิทธิ์ `LodgingManage`) — พนักงานยืนยันว่าโอนคืนแล้ว → `RefundDepositAsync` (JE + ใบลดหนี้) **จากบัญชีที่เงินเข้า** (อ่านขา Dr ของ JE รับมัดจำ เช่น 11340 gateway) หรือบัญชีธนาคารที่เลือก · หาไม่ได้ = ปฏิเสธให้เลือก ไม่เดา 111 (`RefundDepositRequest.MoneyAccountId` ใหม่ · null = 111 เดิม)
- บันทึกทีละใบมัดจำ (ใบถัดไปล้มแล้วกดซ้ำ ไม่คืนซ้ำ) · หน้า front desk: ป้าย "ค้างคืน" ในรายการ · มุมมอง "ต้องคืนเงินแขก" · ปุ่ม "💸 ยืนยันคืนเงินแล้ว" · หน้าแขก: "รอที่พักโอนคืน ฿X" / "ที่พักโอนคืนแล้ว"

### 1.4 ด่านทั่วระบบใน DocumentService (แก้เล็ก เฉพาะจุด)

## 3. ข้อมูลเดิม (ไม่เขียนเอกสาร/JE ย้อนหลัง)
Migration (`DatabaseMigrationHelper` · รันซ้ำได้):
- `CompanySettings.DepositVatTreatment` integer NULL (ไม่ UPDATE)
- `LodgingProperties.DepositVatTreatment` integer NULL + `UPDATE … = 2 WHERE DepositOutputVatDeferred = true AND DepositVatTreatment IS NULL` (หน้าตั้งค่าเขียนธงเดิมตามโหมดทุกครั้ง ⇒ ไม่ทับสิ่งที่ผู้ใช้เลือกทีหลัง)
- `LodgingReservations.RefundPaidAmount/RefundPaidAt/RefundPaidBy/RefundReference` + ประทับแถวยกเลิกเดิมที่โค้ดเก่า "ลงคืนเงินแล้ว" (`PaidAmount` ถูกหักไปแล้ว) ด้วยป้าย `legacy:posted-at-cancel` — ไม่แตะ JE/ใบลดหนี้ · **แก้ใน §9 (C10): ไม่ประทับ `RefundPaidAmount` แล้ว — สถานะ "ไม่มีข้อมูลการโอนคืน"**

Query ให้เจ้าของ/นักบัญชีไล่ตรวจ (แทน `:cid`):
```sql
-- P0-1: ใบเช็คเอาต์ที่พักที่ออกไปแล้วแบบ "หักมัดจำไม่มีผล" (เก็บเงินเต็ม + มัดจำค้าง + VAT มัดจำซ้ำ)
SELECT d."DocumentNumber", d."DocumentDate", d."TotalAmount", d."DepositAppliedAmount", d."DepositAppliedRef", d."PaidAmount"
FROM "Documents" d WHERE d."CompanyId" = :cid AND d."OriginModule" = 'Lodging' AND d."DocumentType" IN (2, 4)
  AND d."IssuedAsCashReceipt" = false AND d."DepositAppliedDrivesJournal" = true AND d."Status" <> 6 AND NOT d."IsDeleted";
-- F-03: การยกเลิกเดิมที่ระบบลง "คืนเงินแล้ว" ตอนยกเลิก — ต้องตรวจว่าโอนคืนจริงไหม
SELECT "ReservationNumber", "CancelledAt", "RefundAmount", "CancellationFee" FROM "LodgingReservations"
WHERE "CompanyId" = :cid AND "RefundPaidBy" LIKE 'legacy:posted-at-cancel%';
-- P0-2: มัดจำที่ยังค้าง (ยกเลิก/no-show ที่ล้มกลางทาง หรือ night audit บันทึก no-show แต่ไม่ริบ/คืน)
SELECT r."ReservationNumber", r."Status", r."DepositPaid", d."DocumentNumber", d."SubTotal" - d."DepositRealizedAmount" AS "BaseLeft"
FROM "LodgingReservations" r JOIN "Documents" d ON d."Id" = r."DepositDocumentId" AND d."CompanyId" = r."CompanyId"
WHERE r."CompanyId" = :cid AND r."Status" IN (4, 5) AND d."SubTotal" - d."DepositRealizedAmount" > 0.005 AND d."DepositRefundedAmount" = 0;
```

## 6. คำถามให้เจ้าของ/นักบัญชีตัดสิน (ห้ามเดาแทน)
1. **VAT ของมัดจำที่ถูกริบ** (audit §7 ข้อ 1): ตอนนี้ = "ค่าตอบแทน" (VAT คงไว้ในโหมดทันที · ย้ายเข้า 21911 ในโหมดรอเรียกเก็บ · โหมดเต็มยอด = รายได้ไม่มี VAT) — ถ้าเป็น "ค่าเสียหาย" ต้องออกใบลดหนี้คืน VAT ที่เคยออก ⇒ ต้องมีเส้นใบลดหนี้ไม่มีเงินคืน **ยังไม่ได้ทำเป็นค่าตั้ง** (ต้องเพิ่มเมธอดใน DocumentService)
2. ใบสุดท้ายของโหมด VAT ทันที: ทำ "หักฐานก่อนคิด VAT" (แนะนำ · ทำแล้ว) — ต้องการทางเลือก "ใบลดหนี้ใบมัดจำ + ใบเต็ม" เป็นค่าตั้งด้วยไหม
3. ผังพักมัดจำที่พัก: 21510 (ผังโรงแรม) หรือ 21713 — ตอนนี้ null → 21712 "ค่าสินค้ารับล่วงหน้า" ของเดิม (ไม่ได้เปลี่ยน)
4. แขกบุคคลที่ไม่ให้ที่อยู่: ใบมัดจำโหมด VAT ทันทีจะพิมพ์ "ใบเสร็จรับเงิน" (ข้อมูลผู้ซื้อไม่ครบ §86/4) แต่ VAT ยังเข้า ภ.พ.30 — ต้องการบังคับที่อยู่แขก/ใช้ใบกำกับอย่างย่อ (ภ.พ.06) ไหม
5. เงินประกันความเสียหายที่ต้องคืน (`SecurityDeposit` ในข้อเสนอ audit) — **ยังไม่รองรับ** (ไม่ได้เพิ่มเป็นโหมดที่ 4 เพราะต้องมีเส้นคืนตอนเช็คเอาต์) · ตอนนี้ใช้ "เต็มยอด" ได้แต่ระบบจะหักเข้าใบสุดท้าย
6. ลูกค้านิติบุคคลหัก ณ ที่จ่ายจากมัดจำ — **ยังไม่รองรับในโมดูลที่พัก** (หน้ายืนยันรับมัดจำไม่มีช่อง WHT) · audit P1-6 (WHT นับซ้ำตอนใบสุดท้าย) ยังเปิด
7. คืนเงินผ่าน gateway: ตอนนี้พนักงานคืนที่ `PaymentGatewayController.Refund` แล้วกด "ยืนยันคืนเงินแล้ว" ที่หน้าการจอง (บัญชีเงินออกอ่านจากขาเงินเข้า 11340) — ต้องการให้ refund สำเร็จของ gateway ลงยอดคืนที่การจองอัตโนมัติไหม

**SQL เพิ่ม (แทน `:cid`)**
```sql
-- C8: รายการ folio ของบริษัทที่ไม่จด VAT ที่เก็บ VatRate > 0 ไว้ (DDL default 7) — ไม่แก้ย้อนหลัง · เช็คเอาต์ใหม่ทับเป็น 0 ให้แล้ว
SELECT r."ReservationNumber", c."Description", c."VatRate", c."Status" FROM "LodgingFolioCharges" c
JOIN "LodgingReservations" r ON r."Id" = c."ReservationId" AND r."CompanyId" = c."CompanyId"
JOIN "Companies" co ON co."Id" = c."CompanyId"
LEFT JOIN "CompanySettings" s ON s."CompanyId" = c."CompanyId" AND NOT s."IsDeleted"
WHERE c."CompanyId" = :cid AND c."VatRate" > 0 AND NOT COALESCE(s."VatRegistered", co."IsVatRegistered");
-- C8: ใบเช็คเอาต์ที่พักที่ออกไปแล้วด้วยบรรทัด VAT ทั้งที่บริษัทไม่จด VAT
SELECT d."DocumentNumber", d."DocumentDate", d."VatAmount" FROM "Documents" d
JOIN "Companies" co ON co."Id" = d."CompanyId"
LEFT JOIN "CompanySettings" s ON s."CompanyId" = d."CompanyId" AND NOT s."IsDeleted"
WHERE d."CompanyId" = :cid AND d."OriginModule" = 'Lodging' AND NOT d."IsDeposit" AND d."VatAmount" > 0
  AND NOT COALESCE(s."VatRegistered", co."IsVatRegistered");
-- C1: ใบของ integration ที่ถูกบล็อก (ไม่ลงบัญชี · ห้ามรับชำระยอดค้าง) และใบที่ลงได้แต่ VAT มัดจำย้ายเดือน
SELECT "DocumentNumber", "DocumentDate", "InternalNotes" FROM "Documents"
WHERE "CompanyId" = :cid AND "InternalNotes" LIKE '%RD-86/4-DEPOSIT-TIV-DOUBLE%';
-- C2 (ก่อนแก้): การจองที่ค้าง "เช็คอิน" ทั้งที่ออกใบเช็คเอาต์แล้ว — ตอนนี้กดเช็คเอาต์ซ้ำเพื่อทำต่อได้
SELECT "ReservationNumber", "FinalDocumentId" FROM "LodgingReservations"
WHERE "CompanyId" = :cid AND "Status" = 2 AND "FinalDocumentId" IS NOT NULL;
-- C3 (ก่อนแก้): การจองที่ถูกยกเลิกซ้ำจากลิงก์แขก — audit มี action Cancel มากกว่า 1 แถวต่อการจอง
SELECT "EntityId", COUNT(*) FROM "AuditLogs"
WHERE "CompanyId" = :cid AND "EntityType" = 'LodgingReservation' AND "NewValues" LIKE '%"action":"Cancel"%'
GROUP BY "EntityId" HAVING COUNT(*) > 1;
```
