## 2. จุดที่พลาดกับกระดาษจริง — ไล่ให้เห็นว่าพลาดที่ขั้นไหน

### 2.1 ส่วนลดท้ายบิล (ใบร้านวัสดุ `OcrPaperSamples.HardwareBillDiscount`: 1,395 · ลด 5% 69.75 · VAT 92.77 · รวม 1,418.02)
- **ขั้น 3** regex เดิมข้ามป้าย "ส่วนลดท้ายบิล" (ไม่อยู่ในรายการป้าย) แล้วไปหยิบ "ยอด**หลังหัก**ส่วนลด **1,325.25**" เป็นส่วนลด
  (ล็อกด้วยตัวอ่านเดิมที่คัดลอกจาก `git show 75292cf` ใน `OcrBillDiscountTests`) · แบบอื่นที่ผิด: "ส่วนลด 10% 150.00" → 10 ·
  "ส่วนลดสมาชิก -38.70" → หาย · หัวคอลัมน์ "ส่วนลด⏎1 ปากกา" → ส่วนลด 1 บาท (`\s*` ข้ามบรรทัด)
- **ขั้น 6** ส่วนลด 1,325.25 ไม่อธิบายอะไร ⇒ ตกเคส B (Σ 1,395 = "รวมเงิน") **ไม่มีช่องว่าง** ⇒ บรรทัด 1,395 + VAT 92.77 = **1,487.77**
  ≠ กระดาษ 1,418.02 **เงียบ** (หัวเอกสาร Total 1,418.02 · DiscountAmount 1,325.25) ⇒ ไปแตกตอนอนุมัติ (JE ไม่สมดุล)
- **ขั้น 5** แม้อ่านส่วนลดถูก `Document.SubTotal` = 1,395 (ก่อนลด) ทั้งที่บรรทัดรวม 1,325.25 ⇒ **ฐานภาษีซื้อ §87** (`TaxService.VatableBase`
  อ่าน `SubTotal`) เกินจริง 69.75 และพอผู้ใช้เปิดแก้แล้วบันทึก `DocumentService` คิด SubTotal ใหม่ = "ยอดเปลี่ยนเอง"
- **ขั้น 2** ทุกใบที่มีส่วนลดท้ายบิลติด `[MATH]` "คณิตศาสตร์ไม่ตรง" (ใบถูก) ⇒ คำเตือนที่ผู้ใช้เรียนรู้ที่จะเมิน

### 2.2 ราคารวม VAT + ส่วนลด (ใบซูเปอร์มาร์เก็ต `SupermarketMemberDiscount`: 774 · ลด 38.70 · สุทธิ 735.30 · VAT 48.10)
- ขั้น 3 ส่วนลดหาย · และถึงอ่านได้ ขั้น 6 ก็ **ไม่มีเคสรองรับ** (C ต้องการ Σ − ส่วนลด = ยอดก่อน VAT · A ต้องการ Σ = ยอดรวม) ⇒ กำกวมทุกใบ

### 2.3 ใบผสม VAT/ไม่มี VAT (ใบค้าส่ง `WholesaleMixedVat`: ไข่ 125 N · หมู 189 N · ผัก 50 N · ของใช้ 428 V · VAT 28 · รวม 792)
- **ขั้น 6(ค)** ไม่มีใครอ่านสัญลักษณ์ `V/N` หรือ "ยอดที่ต้องเสีย/ไม่ต้องเสียภาษี" · ตัวเดาจากชื่อรู้จัก "ผัก" แต่ไม่รู้จัก "ไข่"/"หมู" ⇒ ไข่/หมูได้ 7%
- **ขั้น 6(ง)** เฉลี่ย VAT 28 ลงบรรทัดที่เดาว่ามี VAT ⇒ **Σ VAT ตรงกระดาษโดยการสร้างเสมอ** ⇒ ยอดรวม 792 "ตรง" ⇒ ไม่มีด่านไหนเห็น
  แต่ 7% × ฐาน 714 = **49.98 ≠ 28.00** ⇒ ฐาน §87 ผิด และเปิดแก้แล้วบันทึกเมื่อไร VAT กลายเป็น 49.98 = ยอดเอกสาร ≠ กระดาษ
- **ขั้น 6(จ)** กรณีเดาว่าไม่มี VAT ทุกบรรทัดแต่กระดาษมี VAT มีแค่ `LogWarning` (ไม่ใช่การดัง — F2 ข้อ 7)

## 6. คำถามเจ้าของ (ผลต่างกันคนละเรื่อง — ไม่เดาแทน)

1. **ส่วนลดท้ายบิลบนเอกสารจากสแกน ให้แสดงแบบไหน?** วันนี้ (คงเดิม) กระจายเป็น "ส่วนลดรายบรรทัด" (PDF โชว์คอลัมน์ส่วนลด + "รวมส่วนลด") ·
   (ก) คงเดิม — ปลอดภัยที่สุด ตัวเลขถูกทุกช่อง · (ข) ย้ายไปช่อง `BillDiscountAmount` (PDF โชว์แถว "ส่วนลดท้ายบิล" เหมือนกระดาษ) — ต้องแก้ DTO พรีวิว +
   ปุ่ม "แก้ในฟอร์มก่อน" + แปลงส่วนลดราคารวม VAT เป็นฐานก่อน VAT รายอัตรา (งานแยกคอมมิต)
2. **อัตรา 0 ในตารางสรุป VAT ของบิลในประเทศ** — ตั้งเป็น "ยกเว้น §81" (`-1`) (เหตุผล: อัตราศูนย์ §80/1 ใช้กับส่งออก/บริการใช้ต่างประเทศ) · ถ้าต้องการ
   "0%" แทน ⇒ รายงานภาษีซื้อแยกคอลัมน์ต่างไป
3. **ด่าน "ยอดไม่ตรงกระดาษ" ตอนอนุมัติด้วยมือ** (หน้าเอกสาร/มือถือ/API) — วันนี้ `[Σ-GAP]` หยุดแค่การอนุมัติ**อัตโนมัติ** · อยากให้ขึ้นเป็น approval warning
   (ต้องกด "รับทราบ") ด้วยไหม? ต้องแตะ `DocumentService.cs` (F4 ข้อ 7) จึงไม่ทำรอบนี้
4. **ค่าเผื่อยอดรวม ±1 บาท** (เท่ากับตัวกระทบยอดเดิม — ให้บิลที่ปัดเศษผ่าน) · บีบเป็น ±0.05 + อ่าน "ปัดเศษ" จากกระดาษ = ด่านเข้มขึ้นแต่ใบปัดเศษจะติดเตือนมากขึ้น
5. **ข้อมูลที่ persist ไว้แล้ว** (F3 ข้อ 10): สแกนที่ยังไม่สร้างเอกสารแต่ `ExtractedDiscountAmount` ถูกอ่านผิดด้วยตัวอ่านเดิม ⇒ ตอนนี้ตก `[Σ-GAP]` (ดัง ไม่เงียบ)
   แต่ไม่ถูกแก้ให้เอง · เอกสาร**ที่สร้างไปแล้ว**จากสแกนที่มีส่วนลดมี `SubTotal` = ยอดก่อนลด (ฐาน §87 เกิน) — ไล่ด้วย
   `Documents d JOIN OcrScanResults s ON s.CreatedDocumentId = d.Id WHERE s.ExtractedDiscountAmount > 0 AND d.SubTotal <> (SELECT SUM(Amount) FROM DocumentLines WHERE DocumentId = d.Id)`
   · ฉบับร่างแก้ได้ · ที่อนุมัติ/ยื่นแล้วต้องให้นักบัญชีตัดสิน (ใบลดหนี้/ยื่นเพิ่มเติม) — จะให้ทำ migration อ่านส่วนลดใหม่ให้สแกนค้างไหม?
