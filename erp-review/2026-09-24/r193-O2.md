## ข้อ 18 — ค้นทะเบียน RD แยกตามสาขา (ทั้งแถว)

- **`Helpers/RdVatBranchRecords.PickForBranch(xml, branch)`** = ตัวเลือกแถว**ตัวเดียว**ของทุกทางเข้าทะเบียน VAT (+ enum `RdVatRowBasis` · record `RdVatPick` ·
  `RdVatBranchRecord.Title` optional):
  1. `vBranchNumber` ตรง → ทั้งแถว (`BranchNumberMatch`) — สนญ. = 0 · สาขา N = N
  2. ถามสาขา N ไม่มีแถวตรง → `null` (ห้ามคืน สนญ. แทน — กติกาเดิมของทีม C)
  3. ถาม สนญ. + RD ไม่ส่งเลขสาขา + แถวเดียว → แถวนั้น (`SingleRow` = พฤติกรรมเดิมทุกประการ)
  4. ถาม สนญ. + หลายแถวที่อยู่เหมือนกัน → แถวแรก (`SameAddressAllRows`)
  5. ถาม สนญ. แต่ระบุแถวไม่ได้ (ไม่มีเลข 0 / ที่อยู่ต่างกัน / ลิสต์ยาวไม่เท่ากัน) → **ชื่ออย่างเดียว ที่อยู่ว่าง** (`NameOnly`) — ชื่อเป็นของเลขภาษี (ยืนยันตัวตนต่อได้) ·
     ที่อยู่ที่จัดแถวไม่ได้ = "ไม่รู้" (เดิม = ประกอบ "ค่าแรกที่ไม่ว่าง" ทีละช่อง ⇒ เลขบ้านสาขา + ตำบล สนญ.)
- ต่อสาย 3 จุด (รูปแบบเดิม "ค่าแรกที่ไม่ว่างทีละช่อง" เหลือ **0 จุด**): `DbdLookupService.LookupRdVatAsync` (สนญ. — ตัด `PickFirst` ทิ้ง) ·
  `DbdLookupService.GetBranchAsync` (สาขา N) · `ThaiGovIntegrationService.LookupBranchAsync` (สำเนาที่สอง — `ExtractXmlValue`/`BuildAddressFromXml` ถูกลบ;
  ผลข้างเคียง: ที่อยู่ของ endpoint `GET /api/.../tax/branch/{taxId}/{code}` มีคำนำหน้า "ตำบล/อำเภอ/จังหวัด" + หมู่บ้าน เหมือนเส้น DBD)
- แคช: `dbd:{tin}` (= สนญ.) · `dbd:{tin}:b{code}` (สาขา) — คีย์ (เลขภาษี, สาขา) อยู่แล้วจากทีม C ไม่ได้เปลี่ยน
- ⚠️ **รอยืนยันกับของจริง**: (ก) RD ส่ง `vBranchNumber` มาจริงไหม (ถ้าไม่ส่ง + มีหลายแถว = ได้ชื่ออย่างเดียว ที่อยู่ สนญ. หาย → Contact ใหม่ใช้ที่อยู่จากกระดาษ)
  (ข) `BranchNumber=0` ใน SOAP หมายถึง "สนญ." หรือ "ทุกสาขา" — ควรเก็บคำตอบจริง 1 ชุดเป็น fixture แล้วเพิ่มเทสต์
