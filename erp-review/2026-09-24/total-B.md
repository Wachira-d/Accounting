# ทีม B — โบราณคดีโค้ด: วันนี้ระบบ "เลือกยอดรวมทั้งสิ้น" อย่างไร (หลังรอบ 190 · `c31d787`)

> โจทย์เจ้าของ (รอบ 192): "หาว่าอันไหนคือยอด total ของเอกสาร ใส่ค่าตัวนี้ให้ตรงก่อน แล้วค่อยไล่ค่าอื่นให้รวมตรงยอดนี้"
> ทีมนี้ **ไม่แก้โค้ด** — ไล่ว่าโค้ดปัจจุบันตัดสินยอดทีละขั้นอย่างไร แล้วทำนายผลกับใบ M/U/S
> ป้าย: **[SIM]** = ยืนยันด้วย simulation Python ที่ลอก regex/สูตรจากโค้ดจริง · **[READ]** = อ่านโค้ดแล้วไล่ด้วยมือ ·
> **[สมมติ]** = ขึ้นกับค่าที่ Azure/XML คืนมา ซึ่งไม่มีไฟล์ผลจริงให้ตรวจ (บอกไว้ทุกจุด)
> simulation: `scratchpad/teamB/sim.py` (เส้นข้อความ) · `sim2.py` (เส้น Azure/XML ตามค่าสมมติ) · ข้อความกระดาษ `M.txt/U.txt/S.txt`
> (ถอดจาก BRIEF-TOTAL — M เป็นภาพถ่าย ข้อความจริงของ Tesseract จะเรียงต่างไป ⇒ ผล M เส้นข้อความ = "ถ้า engine อ่านได้ตามลำดับแถว")

## 0. คำตอบสั้น

1. **ไม่มีขั้นไหนในระบบที่ "เลือกยอดรวมทั้งสิ้น" จากผู้สมัครหลายตัว** — ยอดรวมคือ "ค่าแรกที่ engine คืนมา" (ป้ายตัวแรกที่ regex เจอ /
   ช่อง `InvoiceTotal` ของ Azure / `GrandTotal` ของ XML) แล้วชั้นถัดไปทำได้แค่ (ก) เติมเมื่อว่าง (ข) สลับป้าย Sub↔Total (ค) ทับเมื่อสามค่า
   ที่ลงตัว 7% **ตกลงกับยอดเดิม** — ไม่มีชั้นไหนถามว่า "ยอดนี้เป็นยอดก่อนหรือหลังส่วนลด" หรือ "ตัวอักษร/แถวชำระบอกยอดอะไร"
2. **หลักฐานที่แรงที่สุดบนกระดาษ (จำนวนเงินตัวอักษร) ถูกใช้แค่ "เติมเมื่อว่าง + ลดคะแนน"** — ขัดกันแล้วไม่ติดแท็กห้ามอนุมัติ
3. **ใบ M เส้นข้อความ [SIM]: ยอดรวม 24,110.00 (ก่อนลด) · VAT แต่งขึ้น 1,577.29 (กระดาษ 1,148.28) · ไม่มีแท็กห้ามอนุมัติเลย** ⇒ ปุ่ม
   "สร้าง + อนุมัติ" ลงบัญชีได้ทันที — ภาษีซื้อเกินจริง 429.01 · เจ้าหนี้เกิน 297.75
4. ใบ U [SIM]: ยอด 536.00 (ถูกในฐานะใบกำกับ) แต่ส่วนลดพิเศษ 98 ถูก**อ่านแล้วทิ้งเงียบ** ไม่มีที่ไหนบอกว่าจ่ายจริง 438
5. ใบ S [SIM]: ยอด 5,024.00 ถูก (รอดเพราะ AmountTriple) แต่**บรรทัดสินค้าหาย** (ด่านแตกบรรทัดไม่รู้จักส่วนลด) · เส้น Azure/XML
   [READ+SIM สมมติ] บรรทัดนมผงถูกเดาเป็น "ยกเว้น VAT" จากคำว่า "นม"

### 1.1 ใครทับใครได้ (สิทธิ์เขียน Total เรียงตามเวลา)
```
engine (XML > Azure > Python > Tesseract — ตัวแรกที่สำเร็จ ไม่มีการโหวตข้าม engine)
  → [Enrich] สลับป้าย (ทับ) → AmountTriple (ทับเฉพาะเมื่อ "ตกลง" กับยอดเดิม / ไม่งั้นเติมช่องว่าง)
  → ApplyAmountMath (เติมว่าง) → ตัวอักษร (เติมว่าง · ขัด = แค่ลดคะแนน)
  → ด่านคณิต (อ่านอย่างเดียว) → LearnedPatterns/Zone (เติมว่าง) → External override (ทับทุกอย่าง)
  → user correction OS:4557 (ทับ) → Create: NormalizeSwapped (ทับ) → Total = Extracted − WHT
  → Repopulate (คำนวณใหม่จากบรรทัด)
```
⇒ **ผู้ชนะจริงคือ "ป้ายแรก/ช่องแรกที่ engine หยิบ"** — ชั้นหลังทั้งหมดถูกออกแบบให้ "ห้ามทับค่าที่ engine อ่าน" (บทเรียน Makro 951/49 · RG-01)
จึงไม่มีช่องให้หลักฐานที่ดีกว่า (ตัวอักษร · แถวชำระ · Sub+VAT · ตารางรหัส ภ.พ.) มาแก้ยอดรวมที่เป็น "ยอดก่อนลด"

## 4. ต้นเหตุ (root causes) — เรียงตามผลต่อ "ยอดรวม"

- **RC-1 ไม่มี "ตัวเลือกยอดรวม" — มีแต่ "ตัวอ่านป้ายแรก"** (T1–T4) · ป้ายภาษาอังกฤษ `TOTAL` ถูกถือเป็นยอดสุดท้ายเสมอ ทั้งที่ Makro ใช้กับยอด**ก่อนลด**
  และแถวที่ตามมา (`AMOUNT`, `NET AMOUNT`, ตัวอักษร, แถวชำระ) ไม่มีใครอ่าน · regex ① ต้องการตัวเลขติดป้าย ⇒ ป้ายสองภาษา `…/ Total Amount` หลุดทั้งหมด (S)
- **RC-2 หลักฐานถูกจัดเป็น "ตัวเติมช่องว่าง" ไม่ใช่ "ผู้ลงคะแนน"** — ตัวอักษร (B4) · Sub+VAT · Total−ส่วนลด · ผลรวมตาราง VAT · แถวชำระ ต่างเป็นหลักฐาน
  อิสระของยอดเดียวกัน (M มี 5 ทาง = 23,812.25) แต่โค้ดไม่เคยนับคะแนนข้ามแหล่ง · ขัดกันแล้วไม่มีแท็ก (`[AmountWords]` ไม่อยู่ใน `BlockingTags`)
- **RC-3 ความสัมพันธ์ส่วนลด ↔ ยอดรวมมีทิศเดียว** — ด่านข้อ 0 (`GW:68`) · `NetSubTotal` · เคส C/E ล้วนสมมติว่า "ยอดรวม = หลังลด" · กรณี
  **ยอดรวมที่อ่านได้ = ก่อนลด** (M: Sub+VAT+ส่วนลด = TOTAL) และ **ส่วนลดหลังยอดรวม/หลัง VAT** (U) ไม่มีเคสรองรับ ⇒ M ได้ `[MATH]` แทนคำตอบ ·
  U ถูกตีเป็นเคส A/E ผิดความหมาย · `NetSubTotal` "Total − VAT เมื่อมีส่วนลด" จึงให้ 22,961.72 เมื่อ Total เป็นยอดก่อนลด
- **RC-4 "ตรงโดยการสร้าง" ยังเหลืออยู่ที่ยอดหัว** (ญาติของบทเรียนรอบ 190 เรื่อง Σ VAT) — back-calc 7/107 แล้ว AmountTriple ถือว่า "สอดคล้อง" จึงไม่ค้นต่อ
  (`SFE:885-896`) · บรรทัดสรุป = Total−VAT แล้ว `OcrAmountIntegrity` เทียบกับ Total ตัวเดิม · ทุกด่าน (T13) ใช้ `ExtractedTotalAmount` เป็นเป้า ⇒ **ถ้า Total ผิด ไม่มีด่านไหนเห็น**
  (ด่านเดียวที่เป็นอิสระคือข้อ 3 อัตรา × ยอด ซึ่งพ่ายต่อ VAT ที่แต่งด้วย 7%)
- **RC-5 back-calc 7/107 สองชุด** — `OS:5475` (ผ่าน `VatBackCalcGuard`) กับ `SFE:519-526` (ไม่ผ่านด่าน) · และ `VatBackCalcGuard` ให้ผ่านเมื่อเห็นคำ "รวมภาษีมูลค่าเพิ่ม"
  โดยไม่ถามว่ากระดาษพิมพ์ยอด VAT ไว้ที่อื่นไหม (M มีตาราง VAT 1,148.28)
- **RC-6 ตารางสรุปรหัส ภ.พ. แบบห้าง (รหัสตัวเลข + คอลัมน์จำนวนชิ้น) ไม่มีตัวอ่าน** — `OcrLineVatMarks` รู้จักแต่รหัสตัวอักษร ⇒ ตัวแยกยกเว้น/มี VAT ที่
  พิมพ์ไว้ครบถูกทิ้ง ⇒ ใบที่ไม่มีหน้ารายการ (M หน้า 3) ต้องแยกบรรทัดมือเสมอ
- **RC-7 ตัวแตกบรรทัดจากข้อความ**: (ก) SummaryMarkers ขาด `รวม` เดี่ยว · `รวมเป็นเงิน` · `ยอดเงินรวม` · `net amount` · ชื่อช่องทางชำระ (`CC_…`) (ข) `OcrLineSplitGuard`
  เทียบ Σ ราคาเต็มกับ Sub/Total โดย**ไม่หักส่วนลด** (ค) เส้น hybrid ส่งข้อความสองชุด (text-layer + Tesseract) ⇒ นับซ้ำ
- **RC-8 ช่องที่ engine ให้มาแต่ไม่ได้ใช้**: Azure `TotalDiscount` (ไม่ parse) · `AmountDue` (สำรองเท่านั้น) · `PreviousUnpaidBalance` (parse แล้วไม่มีผู้อ่าน —
  dead field) · XML: `ApplicableTradeTax` รายบรรทัด (หมวด VAT/E) + `SpecifiedTradeAllowanceCharge` ไม่อ่าน
- **RC-9 ตัวเดาอัตราจากชื่อ** `"นม"` ⇒ นมผงสูตรเด็ก (แปรรูป = 7%) เป็นยกเว้น · รายการยกเว้นไม่ถูกเทียบกับยอด "ยกเว้น 0.00" ที่กระดาษประกาศ
- **RC-10 regex VAT อ่านเลขอัตราเป็นยอด** (`OS:5444`: `(?:7\s*%?)?` เป็น optional ⇒ backtrack ได้ "7") — รอดใน S เพราะ AmountTriple ทับ แต่ถ้า Total ถูกอ่านได้
  และ Sub ว่าง จะได้ Sub = Total − 7

## 5. ข้อสังเกตต่อการออกแบบ "หา Total ก่อน" (สำหรับทีมออกแบบ — ไม่ใช่ข้อเสนอโค้ด)

1. ผู้สมัคร Total มีอยู่แล้วในโค้ดครบทุกตัว (T1–T8) แต่กระจายอยู่คนละชั้นและมีสิทธิ์ทับไม่เท่ากัน — ขั้นใหม่ควร**รวบผู้สมัครทั้งหมด + ป้ายที่มา** แล้วให้คะแนนด้วย
   หลักฐานอิสระ (ตัวอักษร · Sub+VAT · Total−ส่วนลด · ผลรวมตารางรหัส ภ.พ. · แถวชำระ) โดยวางไว้**หลัง** engine และ**ก่อน**ด่านคณิต `OS:655`
2. ต้องแยก "ยอดใบกำกับ (§86/4)" กับ "ยอดชำระ" ออกจากกัน (U) — ทุกด่านวันนี้ใช้ช่องเดียว `ExtractedTotalAmount`
3. ต้องไม่ทำลายบทเรียนเดิม: ห้ามให้ "เงินสดรับ/เงินทอน" (Makro 951/49/1,000) เป็นผู้ชนะ ⇒ แถวชำระนับเป็นหลักฐานได้เฉพาะเมื่อ**ตรงกับหลักฐานอื่นอย่างน้อยหนึ่ง** ·
   ป้ายสลับลักกี้เวย์ยังต้องผ่าน `OcrHeaderAmounts.IsSwapped` · ใบ IKEA/Wine Pro ราคารวม VAT ต้องได้เคส A เหมือนเดิม
4. ทุกด่านใน T13 ควรรับ "Total ที่ตัดสินแล้ว + ความมั่นใจ" ไม่ใช่อ่าน `ExtractedTotalAmount` ดิบ — และ `[AmountWords]` ที่ขัดกับ Total ที่เลือก ควรเป็นแท็กหยุดอนุมัติ
