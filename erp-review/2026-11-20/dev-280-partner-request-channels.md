# รอบ 280 — เลือกช่องทางแจ้ง "คำขอเชื่อมคู่ค้า" (กลุ่ม LINE / อีเมลของผู้ติดต่อ)

ปัญหาจากเจ้าของ (2026-11-20 · หน้า `pages/partners.html` ส่วน "📤 คำขอที่เราส่ง" — คำขอถึงเลข 0203562005871 สำนักงานใหญ่ สถานะ "ส่งแล้ว — รอคู่ค้าตอบรับ"):
"คำขอส่งไปทางไหน ไลน์ที่ผูกกันไว้ไม่เด้ง เมล์ไม่มี ปรับให้เลือกช่องทางการส่งแจ้งได้ด้วย" · ผู้ติดต่อ (หจก. แอม แฮปปี้เนส) มีกลุ่ม LINE ผูกผ่าน LINE OA กลางแล้ว
(เรื่องที่รับ: เอกสาร · ทวงชำระ/ใบแจ้งยอด · ใบเสร็จ · 50 ทวิ)

> ⚠️ คอมไพล์ + รันเทสต์ที่เกี่ยวข้องในเครื่องนี้แล้ว (.NET 8 + PostgreSQL 16 ฐาน `accounting_test_r280`) · ชุดเต็มรอ CI รวมของผู้ประสานงาน

## 1. วิเคราะห์ระบบเดิม (ยืนยันกับโค้ดจริง)

| เรื่อง | ระบบเดิม (รอบ 264) |
| --- | --- |

| คู่ค้ายังไม่ใช้ NextAcc | **ไม่แจ้งเลย** — มีแค่แถว "คำขอที่เราส่ง" ของผู้ขอ · และถ้าเขาสมัครทีหลังด้วยเลขเดิม ก็**ไม่เห็นคำขอ** (แถวคู่เกิดเฉพาะตอนกดส่ง) |
| กลุ่ม LINE / อีเมลของผู้ติดต่อ**ของเรา** | ไม่ถูกใช้ในเส้นนี้เลย ⇒ "ไลน์ที่ผูกไว้ไม่เด้ง เมล์ไม่มี" ตรงกับโค้ด (เลข 0203562005871 ไม่ได้ใช้ NextAcc หรือใช้แต่แจ้งเข้าช่องของผู้ดูแลเขา ไม่ใช่กลุ่ม) |
| ความเป็นส่วนตัว | คำตอบ `202 + InviteAckMessage` เท่ากันทุกไบต์ · "คำขอที่เราส่ง" มีแค่ รอตอบ/เชื่อมแล้ว/หมดอายุ · ไม่บอกการปฏิเสธ (264-1-2) — **คงเดิม** |

เส้นส่งข้อความถึงผู้ติดต่อที่ไม่ผ่านตัวหาผู้รับในรอบนี้ **0 จุด**

## 3. คำตัดสิน (280-1…280-9 ใน `erp-review/2026-09-29/DECISIONS.md`)
- 280-2 เรื่องใหม่ "คำขอเชื่อมคู่ค้า" **ไม่เปิดให้ปลายทางเดิมเอง** — กลุ่มของเจ้าของต้องติ๊กเรื่องนี้ที่หน้าผู้ติดต่อ 1 ครั้ง (ลิงก์อยู่ในช่องที่ปิด) · ปลายทางใหม่ได้เป็นค่าตั้งต้น ·
  เหตุ: ค่าเรื่องที่รับเป็นค่าที่เก็บของผู้รับ/ผู้ดูแล (เหมือนการส่งเอกสารเองที่เคารพเรื่องที่รับ) — แก้ค่าที่เก็บเงียบ ๆ = ผิดหลัก F2 ข้อ 9 · ข้อความเข้ากลุ่มที่มีสมาชิกหลายคนต้องเป็นเรื่องที่กลุ่มเลือกรับ

## 4. ตรวจแล้วไม่ใช่บั๊ก
- คู่ค้าที่ใช้ NextAcc **ได้รับแจ้งอยู่แล้ว** (ช่องของผู้ดูแลของเขา) — ไม่ใช่กลุ่มที่เราผูก · ระบบตั้งใจไม่บอกผู้ขอ (264-1-2)

## 5. เลื่อน / ข้อสังเกต
- คู่ค้าที่สมัครทีหลังเห็นคำขอเมื่อ**เปิดหน้าคู่ค้า** (ลิงก์ในข้อความพามา) — ยังไม่มีงานเบื้องหลังสแกนบริษัทใหม่ (ไม่ต้องการสำหรับเส้นลิงก์ · เพิ่มได้ถ้าต้องการกระดิ่งก่อนเปิดหน้า)
- LINE 1:1 ของผู้ติดต่อ (ไม่ใช่กลุ่ม) ยังไม่เป็นตัวเลือก — โจทย์คือกลุ่มที่ผูกไว้ · เพิ่มได้ด้วยตัวหาผู้รับเดิม

## 6. สิ่งที่เจ้าของต้องทำหลัง deploy
1. หน้าผู้ติดต่อ หจก. แอม แฮปปี้เนส → แท็บ "ช่องทางแจ้งเตือน" → กลุ่ม LINE → ติ๊ก **"คำขอเชื่อมคู่ค้า"** → บันทึก (ปุ่ม "เพิ่ม/แก้ช่องทาง" ในหน้าคู่ค้าพาไปตรงนั้น)
2. หน้าคู่ค้า → แถวคำขอ 0203562005871 → "ส่งแจ้งอีกครั้ง" → เลือกผู้ติดต่อ + ติ๊กกลุ่ม LINE/อีเมล → ส่ง (คำขอเดิมยังไม่ผูกผู้ติดต่อ)
3. ตรวจว่าตั้ง URL ของระบบแล้ว (แอดมิน → ตั้งค่าระบบ / `App:BaseUrl`) — ไม่ตั้ง ⇒ ช่อง LINE/อีเมลปิดพร้อมเหตุ
4. migration `Round280Migration` รันเองตอนบูต
