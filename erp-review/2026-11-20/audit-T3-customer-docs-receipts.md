## 4. ข้อค้น

### HIGH-1 — ค่าธรรมเนียมธนาคารทำให้ใบเสร็จของ "ใบแจ้งหนี้ + VAT ที่จ่ายเต็มงวดเดียว" ไม่ถือบทบาทใบกำกับ · และสี่ทางเข้าใช้สูตร "งวดเดียว" คนละตัว
- **โค้ด**: `DS:15795` `doc.PaidAmount += request.Amount + paymentFee + settleNet` แต่ `DS:15833` `priorPaidBefore = doc.PaidAmount − payment.Amount − payment.WithholdingTaxAmount` — ไม่ลบ `FeeAmount`/บรรทัดปรับ และลบภาษีหักที่ไม่เคยถูกบวกเข้า `PaidAmount`
- **เหตุการณ์**: INV บริการ 749,000 · ลูกค้าโอนเต็ม ธนาคารหัก 30 · พนักงานบันทึก 748,970 + ค่าธรรมเนียม 30 ⇒ `priorPaidBefore = 30` ⇒ ใบเสร็จ VAT 0 พิมพ์ "ใบเสร็จนี้ไม่ใช่ใบกำกับภาษี" · ภาษีขาย 49,000 ยังเข้า ภ.พ.30 ผ่านใบแจ้งหนี้ (`DS:15946`) แต่**ลูกค้าไม่มีใบกำกับภาษี** ณ จุดความรับผิด (§78/1 · §86) และขอคืนภาษีซื้อไม่ได้ · การชำระเดียวกันถ้าออกผ่าน A2 (`paymentCount == 1`) กลับถือ VAT = "ใบเดียวกันถือ VAT หรือไม่ ขึ้นกับปุ่มที่กด" ซึ่ง `SettlementReceiptPolicy` เขียนไว้ว่าห้ามเกิด
- **สูตรทั้งสี่**: A1 `DS:15833-15834` · A2 `DS:15472-15474` · A4 `DocumentService.ReceiptLink.cs:115` · ตัวประมาณอีเมล `PostPaymentAutomationService.cs:374-375`
- **แก้ (M)**: ตัวตัดสินเดียวใน `H/SettlementReceiptPolicy` เช่น `IsSingleShotFull(balanceDueAfter, settledByThisPayment, paidAfter)` โดย "ยอดที่ครั้งนี้ตัด" = เงิน + ค่าธรรมเนียม + บรรทัดปรับ (ตัวเดียวกับ `ThisSettlement.Settled`) · ทุกทางเข้าเรียก + ล็อกด้วย `required_call_site_check` · เทสต์สองทิศ (มีค่าธรรมเนียม ⇒ ถือ VAT · มีงวดก่อน ⇒ ไม่ถือ) · ข้อมูลเก่า: รายงานอ่านอย่างเดียวของ "ใบแจ้งหนี้ + VAT ชำระครบ · ไม่มีใบกำกับ/ใบเสร็จถือ VAT ที่ยังมีผล · การชำระมี FeeAmount > 0" ให้ผู้ทำบัญชีตัดสิน (ไม่แก้อัตโนมัติ — ใบที่ออกแล้วห้ามแก้ย้อนหลัง)

### MED-1 — การลบภาษีหักใน `priorPaidBefore` บังงวดก่อนหน้าที่ยอด ≤ ภาษีหักของงวดปิด
- เคส 7: ใบเสร็จงวดปิดถือ VAT ทั้งใบและ `TotalAmount = invoice.TotalAmount` (`DS:15233-15234`) ทั้งที่รับเงินเฉพาะส่วนที่เหลือ ⇒ ใบเสร็จสองใบรวมเกินหนี้ · ใบที่ถือ VAT อ้างยอดที่ไม่ได้รับในครั้งนั้น · เกิดได้เฉพาะเมื่องวดแรกเข้าทางที่ไม่ใช่ `Manual` หรือมีบรรทัดปรับ (ด่าน `DS:15635`) — **ต้องยืนยัน**ว่าทางใดรับบางส่วนของใบแจ้งหนี้ + VAT ได้จริงในระบบที่ใช้งาน · แก้พร้อม HIGH-1 (S)

### MED-2 — ออกใบเสร็จย้อนหลังหลังมีใบลดหนี้: "งวดเดียว" นับจำนวนการชำระ ไม่ดูยอดที่ถูกตัดก่อนหน้า
- เคส 8 (`DS:15472-15474`): ใบเสร็จถือ VAT คัดลอก `SubTotal/VatAmount/TotalAmount` และบรรทัดของใบแจ้งหนี้เต็มใบ (`DS:15231-15235` · `DS:15279-15300`) โดยไม่หักใบลดหนี้ ⇒ กระดาษใบกำกับ ณ วันรับเงินบอก VAT 49,000 ขณะที่ภาษีขายสุทธิของรายการ = 42,000 · ทาง A1 ของเหตุการณ์เดียวกันให้ใบรับเปล่า · **ต้องยืนยัน**: ภ.พ.30 นับ CN ของใบแจ้งหนี้แยก (`DS:18097-18104` ประทับ `OutputVatDueAt` ให้ CN) ⇒ ตัวเลขรายงานอาจถูก แต่กระดาษผิด · แก้ด้วยตัวตัดสินเดียวของ HIGH-1 + ตัดสินว่าใบที่มี CN ก่อนรับควรถือ VAT หรือไม่ (M · ถามนักบัญชี)

### MED-3 — ใบแจ้งหนี้ + VAT ที่รับหลายงวด: VAT ทั้งใบเข้าเดือนของงวดแรก และไม่มีเอกสารใดเป็นใบกำกับ
- `DS:15945-15946` เรียก reclass ทุกการรับ · `DS:18092` ทำครั้งเดียวทั้งก้อน ⇒ รับ 374,500 พ.ย. + 374,500 ธ.ค. = ภ.พ.30 พ.ย. 49,000 (ควร 24,500/24,500 ตาม §78/1) · ใบเสร็จทั้งสอง "ไม่ใช่ใบกำกับภาษี" · ทางมือกันไว้แล้ว (`VatInvoiceSettlementGate`) แต่ทางอัตโนมัติ (integration · นำเข้าไฟล์ · ธนาคาร) ปล่อยผ่านโดยตั้งใจ — ยื่นเร็วเกินไม่ถูกปรับ แต่ลูกค้าไม่มีใบกำกับ · **ต้องยืนยัน**ว่ามีคิว/ป้ายบนใบบอกผู้ขายให้ออกใบกำกับ (ไม่พบในเส้นที่อ่าน) · แก้ (L): ใบกำกับ ณ วันรับเงินต่องวด หรืออย่างน้อยป้าย + คิว "รับเงินแล้วยังไม่มีใบกำกับ" (M)

### MED-4 — วันที่ของการรับทาง gateway เป็น instant UTC ไม่ใช่วันที่ปฏิทินไทย (ต้องยืนยัน)
- `DocumentPaymentHandler.cs:124` ส่ง `intent.PaidAt ?? intent.ConfirmedAt ?? DateTime.UtcNow` · `CreatePaymentAsync` ไม่เรียก `ThaiDate.CalendarDateUtc` กับ `request.PaymentDate` (ใบที่สร้างจากฟอร์มเรียก — `DS:1461`) · ค่าเดียวกันเป็น `DocumentDate` ของใบเสร็จ (`DS:15228`) · วันที่ในเลขเอกสาร (`DS:15203-15204`) · วัน reclass ภาษีขาย (`DS:15946`) ⇒ เงินเข้า 00:00–06:59 น. ของวันที่ 1 อาจได้ใบเสร็จลงวันสุดท้ายของเดือนก่อน และภาษีขายเข้างวดก่อน · ยังไม่ได้ตรวจว่าตัวพิมพ์/รายงานแปลงเขตเวลาก่อนตัดวันหรือไม่ · แก้ (S): normalize ที่ต้นทาง `CreatePaymentAsync` + เทสต์ขอบเดือน

### MED-5 — ใบเสร็จรับชำระภาษาอังกฤษยังมีข้อความไทยที่ persist ไว้
- `DS:15312` บรรทัดรายการ "รับชำระเงินตาม{ใบกำกับภาษี}เลขที่ …" และ `DS:15241-15243` หมายเหตุ "รับชำระเงินตาม… (วันที่รับ …) — ทำหน้าที่ใบกำกับภาษี ณ วันรับเงิน (§78/1)" เป็น literal ไทยทุกภาษาเอกสาร (ใบเสร็จสืบทอด `DocumentLanguage` ของใบต้นทาง `DS:15223`) ⇒ กระดาษอังกฤษ: บรรทัดเดียวของใบเป็นไทย แต่แถวยอด/บรรทัดอ้างอิงเป็นอังกฤษ (กฎเหล็ก #4 A "ข้อความบนเอกสารผ่าน `DocumentLabels` เท่านั้น") · มีสำเนาข้อความชุดเดียวกันใน JS `documents.html:7633` · แก้ (S–M): คีย์ใน `DocumentLabels` เลือกตามภาษาของใบตอนสร้าง · ใบที่ออกแล้วคงเดิม (ห้ามแก้ย้อนหลัง) ⇒ ไม่มี migration

## 5. ฟีเจอร์/UX ที่ควรสร้าง
1. **ใบเสร็จรวมของการโอนครั้งเดียวหลายใบ** — `Decide` รับหลายใบต้นทางได้แล้ว (หนึ่งบรรทัดอ้างอิงต่อใบ) แต่ทุกทางเข้าส่งใบเดียว · ลูกค้าที่โอน 1 ก้อนจ่าย 3 ใบได้ 3 ใบเสร็จและไม่มีเอกสารที่ตรงกับยอดโอน (M–L)
2. **คิว "รับเงินแล้วยังไม่มีใบกำกับภาษี"** สำหรับใบแจ้งหนี้ + VAT ที่ใบเสร็จไม่ถือบทบาทใบกำกับ (ครอบ HIGH-1 เก่า · MED-3) + ปุ่มออกใบกำกับจากคิว (M)
3. **ใบกำกับ ณ วันรับเงินต่องวด** สำหรับบริการผ่อนชำระ (§78/1 ตามเงินที่รับ) แทนการห้ามรับบางส่วนทางมือ (L)
4. **ทางไปต่อของเงินซ้ำ** (บัตร + สลิปของใบเดียวกัน): ปุ่ม "พักเป็นเงินรอจัดสรร 21630 / คืนเงิน" บนเหตุการณ์ของ intent (M)
5. หน้าลูกค้าของใบแจ้งหนี้ที่ชำระแล้ว: แสดงประโยคเดียวว่า "ใบกำกับภาษีของรายการนี้คือเลขที่ …" (ใบไหนถือบทบาท) — ตอนนี้ลูกค้าต้องเปิดทีละใบ (S)
6. ปุ่มสลับภาษา ไทย/อังกฤษ ของ PDF บนหน้าลูกค้า (ป้ายมีครบสองภาษาแล้ว) (S)
