## HIGH

### H1 — แถว e-Tax เก่าที่ถูกประทับ "Submitted" ตอนกรมตอบ 4xx/5xx ไม่ถูก migrate (F2 ข้อ 9)
- **ที่:** `Helpers/Round259AutopilotMigration.cs` (ไม่มีคำสั่งนี้) · เทียบตัวอย่างเดิม `Data/DatabaseMigrationHelper.cs:7633` (ล้างแถว `OFFLINE-%`)
- **เกิดอะไร:** ก่อนรอบ 259 `SubmitToRevenueAsync` ตั้ง `Status = Submitted` + `SubmittedAt = UtcNow` + `SubmissionId = "ERR-{เวลา}"` + `ErrorCode = "RD_{http}"`
  ทุกครั้งที่กรมตอบไม่สำเร็จ คอมมิตนี้แก้ให้แถวใหม่ถูกต้องแล้ว แต่แถวที่ประทับผิดไว้ก่อนหน้ายังเป็น `SubmittedAt != null` ซึ่งมีผล 3 อย่าง
  (1) งานใหม่ `SubmitPendingPreviousMonthsAsync` กรอง `SubmittedAt == null` จึง**ไม่ส่งแถวพวกนี้ให้อีกเลย**
  (2) หน้า Autopilot ไม่แสดงแถวพวกนี้เป็นเรื่องค้าง
  (3) `DocumentService` (บรรทัด 8143/8486/9174/9389/9530) ล็อกเอกสารว่า "ส่ง e-Tax แล้ว — แก้ไม่ได้" และการยกเลิกเอกสารเดินด่าน "ถึงกรมแล้ว"
  ผลคือใบกำกับภาษีที่กรมไม่เคยรับยังถูกแสดงว่าส่งแล้ว ผู้ใช้จะรู้ก็ต่อเมื่อถูกตรวจ ปัญหานี้เป็นแบบเดียวกับ `OFFLINE-` ที่เคยมี migration แก้ไปแล้ว
- **แก้:** เพิ่มคำสั่ง idempotent ใน `Round259AutopilotMigration`
  `UPDATE "EtaxInvoices" SET "Status" = 5, "SubmittedAt" = NULL, "SubmissionId" = NULL, "ErrorCode" = 'SUBMIT_ERROR', "ErrorMessage" = '…(ล้างสถานะที่ระบบเคยประทับผิด)', "RdNextAttemptAt" = NULL WHERE "SubmissionId" LIKE 'ERR-%' AND "Status" = 2;`
  พร้อม Db test ทิศตรงข้าม: แถว `Submitted` ที่ `SubmissionId` เป็นเลขจริงต้องไม่ถูกแตะ
  (แถว `RD-{เวลา}` ที่ระบบแต่งเลขขึ้นเองตอนกรมตอบ 2xx ให้ล้างเฉพาะ `SubmissionId` เป็น NULL และคงสถานะไว้)

### H2 — 401/403/404 ถูกจัดเป็น "กรมปฏิเสธ" ทำให้ไม่มีทางไปต่อ และทั้งชุด 200 ฉบับตายพร้อมกัน
- **ที่:** `Helpers/EtaxRdSubmission.cs:30` (`Classify`) · `CanSubmit` · `EtaxInvoiceService.cs:591` · `EtaxInvoiceService.cs:124/281` (สร้างใหม่ได้เฉพาะเมื่อ `Status == Error`)
- **เกิดอะไร:** ทุก 4xx ยกเว้น 408/429 ถูกจัดเป็น `Rejected` ทั้งที่ 401/403 คือคีย์ RD หมดอายุหรือผิด และ 404/405 คือตั้ง URL ผิด ซึ่งเป็นปัญหาการตั้งค่าของเราเอง
  ไม่ใช่เนื้อเอกสาร ลำดับเหตุการณ์เมื่อคีย์หมดอายุ:
  1. วันที่ 1 งานประจำเดือนส่งได้ไม่เกิน 200 ฉบับต่อบริษัท ทุกฉบับได้ 401 แล้วถูกประทับ `Rejected`
  2. ทุกฉบับส่งกระดิ่ง เพราะ Rejected แจ้งทุกครั้ง จึงมีแจ้งเตือนถึง 200 รายการ
  3. ผู้ใช้แก้คีย์แล้วกด "ลองส่งใหม่" แต่ `CanSubmit` คืน false พร้อมข้อความ "กรมสรรพากรปฏิเสธเอกสารนี้แล้ว — แก้ข้อมูล/ออกใบใหม่"
  4. สร้าง e-Tax ใหม่ก็ไม่ได้ เพราะด่านรับเฉพาะ `Error`
  ทางเดียวที่เหลือคือยกเลิกใบกำกับแล้วออกใบแทนทั้งเดือน ซึ่งเป็นเหตุทางกฎหมายที่ไม่จำเป็น
  ข้อความ "ระบบไม่ลองซ้ำเอง · แก้ข้อมูลเอกสาร" ก็ผิดสาเหตุด้วย (F2 ข้อ 7)
- **แก้:**
  - `Classify`: 401/403/404/405 ให้เป็นผลใหม่ (`NotAuthorized`/config) แล้วประทับ `Error` + `ErrorNotConfigured`/`RD_AUTH`
    แจ้งครั้งเดียวต่อบริษัท และ**หยุดชุดที่เหลือในรอบนั้น** (ฉบับต่อไปจะล้มแบบเดียวกัน)
  - `Rejected` ให้เหลือเฉพาะ 400/409/422 (ข้อมูลเอกสาร)
  - เทสต์ทิศตรงข้าม: 401 แล้วแก้คีย์ ต้องส่งซ้ำได้ · 422 ยังคงเป็น Rejected

  ส่วนงวดที่ลงสำเร็จไม่มีข้อความเลย ทำให้เกิด 2 ปัญหา:

  - ผู้ใช้ไม่รู้ว่างบของเดือนที่ปิดในทางปฏิบัติแล้วเปลี่ยนไป ข้อนี้คือ "ล้มดัง" แบบกลับด้าน: ระบบทำของสำคัญเองโดยเงียบ
- **แก้:**
  - นับงวดที่ลงย้อนหลังแล้วต่อท้ายข้อความ เช่น `"ลงย้อนหลัง N งวด (ตั้งแต่ dd/MM/พ.ศ.)"` ผ่าน `AppendRunNoticeTextAsync` + facts แบบโครงสร้าง
  - เมื่องวดที่จะลงอยู่คนละปีบัญชีกับวันนี้ ให้หยุดรอคนยืนยัน (ข้ามแบบงวดปิด พร้อมเหตุ) แทนการ post ข้ามปีเอง

## LOW

### L1 — `RederiveAfterTotalEdit` คืนฐานติดลบได้
- **ที่:** `Helpers/OcrHeaderAmounts.cs:114`
- **เกิดอะไร:** OCR อ่าน VAT ได้ 700 แต่ฐานว่างหรือไม่ใช่ 7% แล้วผู้เบิกแก้ยอดรวมเป็น 500 สูตรจะได้ `SubTotal = 500 − 700 = −200`
- **แก้:** ถ้า `total < vat` ให้คืนค่าเดิม (ไม่ถอด) พร้อมหมายเหตุ "ยอดใหม่ต่ำกว่า VAT เดิม — ตรวจ" และเพิ่ม golden ไว้ใน P259D-10

### L2 — แก้เฉพาะยอดรวมแล้วบรรทัดรายการไม่ขยับตาม
- **ที่:** `OcrService.cs` (`SubmitCorrectionAsync`, ประมาณบรรทัด 5202)
- **เกิดอะไร:** ใบจากมือถือที่ engine อ่านบรรทัดมาแล้ว เมื่อหัวใบเปลี่ยนแต่ Σ บรรทัดยังเป็นยอดเดิม ตอนสร้างจะเข้า Case D พร้อม `[Σ-GAP]`
  และการอนุมัติ/JE อาจเด้งว่าไม่สมดุล ผู้เบิกที่ใช้มือถือมองไม่เห็นบรรทัด จึงไม่มีทางรู้หรือแก้เอง
- **แก้:** ถ้ามีบรรทัดเดียวให้ปรับบรรทัดนั้นตามยอดใหม่ ถ้ามีหลายบรรทัดให้มือถือแสดงหมายเหตุ `[TOTAL-EDIT]` + ลิงก์ไปหน้ารีวิว

### L3 — `OcrBlankLine.IsBlank` ไม่ดู ราคา×จำนวน
- **ที่:** `Helpers/OcrBlankLine.cs:14-15`
- **เกิดอะไร:** แถวที่ผู้ใช้กรอกจำนวน 2 กับราคา 100 แต่ยังไม่มีคำอธิบาย และ `Amount` ยังเป็น null (ไม่ได้คำนวณฝั่ง client) ถูกนับว่า "ยังว่าง" จึงได้ข้อความผิดสาเหตุ
- **แก้:** ใช้ `OcrDuplicateLineGuard.EffectiveAmount(amount, unitPrice, qty)` ซึ่งเป็นสูตรเดียวของโฟลเดอร์ OCR

### L4 — เมื่อตารางจากข้อความแทนตาราง engine คุณสมบัติ VAT ต่อบรรทัดหายไป
- **ที่:** `OcrService.cs` `ApplyTextTableFallback` (เรียกที่ 11177)
- **เกิดอะไร:** `data.Items.Clear()` แล้วสร้างบรรทัดใหม่โดยไม่มี `VatRate`/`PriceIncludesVat` ใบที่มีของยกเว้น VAT ปนอยู่ (ซึ่ง engine ติดป้ายไว้) จึงกลายเป็น VAT ตั้งต้นทุกบรรทัด
  ตัวเลขไม่ได้ถูกแต่งขึ้นเพราะด่าน Σ ±1 บาทพิสูจน์แล้ว แต่ภาษีของแต่ละบรรทัดเปลี่ยน

### L5 — กุญแจงวดนับเอกสารที่ถูกลบด้วย ทำให้งวดนั้นไม่ได้ออกใบ

  ทำให้งวด พ.ย. ไม่มีใบแจ้งหนี้ และข้อความเขียนว่า "ตรวจว่าใบนั้นอนุมัติ/ส่งแล้วหรือยัง" ซึ่งไม่ตรงความจริง

### L6 — ข้ามงวดปิดได้กระดิ่งหนึ่งครั้งต่อหนึ่งงวด

- **RecurringRunKey แข่งกัน:** ล็อกต่อรายการด้วย `JobLock.RunExclusiveAsync(RecurringRun, id)` ทั้งปุ่ม "สร้างทันที" และงานตามรอบ คีย์มี id ของรายการ จึงชนข้ามรายการไม่ได้
  คีย์ถูกประทับใน INSERT เดียวกับใบ และใบแทน/clone ไม่สืบทอดคีย์ (40d76dde) คีย์คิดจาก `ThaiDate.CalendarDateUtc(NextRunDate)` จึงคงที่
- **งวดปิด:** ใช้ `JournalEntryBuilder.ClosedPeriodReasonAsync` ซึ่งเป็นเงื่อนไขเดียวกับ `AccountingService.ValidateFiscalPeriodOpenForDateAsync`
  การไล่ย้อนหลังจำกัด 24 งวดต่อรอบ งวดที่เหลือไปรอบถัดไปใน 15 นาที จึงไม่มีช่องว่างที่ข้ามไปเงียบ ๆ

  SoD ถือว่า `system:recurring` เป็นผู้ทำที่รู้ตัว (ไม่ใช่ผู้ใช้) เหมือน `"System"` เดิม
