### H1 — งวดภาษีขาย/วันที่รับชำระของใบ ถูกตัดสินจาก "วันรับเงิน" โดยไม่ดู "เหตุผล" ของเงิน ⇒ เงินโอนเกิน/ยังไม่ทราบ ถูกรายงาน VAT ผิดงวด + ธง LATE-VAT เท็จ

- สถานการณ์ ข (ธงเท็จ): โอนเกิน ส.ค. นำมาตัดใบบริการ ธ.ค. ⇒ ลงงวด ธ.ค. (ถูก) แต่ประทับ `[DEPOSIT-LATE-VAT] … ภาษีถึงกำหนดงวด 08 … อาจมีเงินเพิ่ม ม.89/1` ลง InternalNotes + audit (`CC-LATE-VAT`) = หลักฐานในระบบว่ากิจการยื่นช้า ทั้งที่ไม่ได้ช้า
- กติกา ม.78/1 ถูกเฉพาะ `UninvoicedSupply` (เงินเป็นค่าของงานนั้นตั้งแต่วันรับ) — เงินโอนเกินเป็นหนี้คืนลูกค้าจนวันที่ตกลงหักกลบ (= วันจัดสรร)
- แก้ขั้นต่ำ: ส่ง `UnappliedReason` เข้า `AfterCreditAllocatedAsync`; ใช้วันรับเงิน + ประทับ `PaymentDate` เฉพาะ `UninvoicedSupply`; `Overpaid`/`Unknown`/`Advance` ⇒ tax point = `applyDate` ไม่มีธง (หรือถามผู้ใช้ในกล่องจัดสรร "เงินก้อนนี้เป็นค่าของใบนี้ตั้งแต่วันรับเงินใช่ไหม") + เทสต์สองทิศ

- L2 `OverdueDunningJob`: `notify == null` ⇒ `continue` โดยไม่ประทับ/ไม่แจ้ง = ระงับเงียบ · มี notify ⇒ แจ้งทีมซ้ำทุก 7 วันต่อใบไม่มีที่สิ้นสุดสำหรับเงิน "โอนเกินรอคืน" (ไม่มีปุ่มรับทราบ) · ไม่ใช่การปิดเสียงถาวร (เงินหมด ≤ 7 วันกลับมาทวงระดับเดิม)
- L3 รายงานอายุลูกหนี้: ยอดรวมเงินรอจัดสรรรวมลูกค้าที่ไม่มีใบค้าง (ไม่อยู่ในตาราง) และเป็นยอด "ณ ปัจจุบัน" แม้ `asOfDate` ย้อนหลัง (มีข้อความบอก) · ไม่ถูกหักซ้ำใน bucket/ใบแจ้งยอด — ผ่าน
- L4 ยกเลิกการจัดสรรคืนสถานะผ่าน `DocumentSettlementState.Apply` — ใบที่เคย Overdue/Sent กลับเป็นสถานะตามสูตร (พฤติกรรมเดียวกับยกเลิกการชำระเดิม)
- L5 รายการที่จัดสรรครบถูกซ่อน (ต้องติ๊ก "รวมที่จัดสรรครบ") ⇒ ปุ่ม "ยกเลิกการจัดสรร" หายาก · คำตอบ undo ที่มี notice ภาษีแสดงเป็น success
- L6 สิทธิ์: ยกเลิกการชำระ P ใช้สิทธิ์ของชนิดใบหลัก แต่กลับการจัดสรรของใบชนิดอื่นด้วย (ยอมรับได้ — จดไว้)
- L7 เงินเกิน 0.01 ทาง API ตรง (allocations รวม = ยอด − 0.01): เดิมลงผังพักเงียบ ๆ ตอนนี้ต้องมีเหตุผล (หน้าเว็บไม่ชน เพราะ `Excess` ใช้ `WouldOverpay` เดียวกัน)

## ตรวจแล้วไม่ใช่บั๊ก (ไม่ต้องรายงานซ้ำ)
- แข่งกันจัดสรรสองคำขอ: `FOR UPDATE` ใบ→การชำระ + `ReloadAsync` + `Check` ใต้ล็อก + `RecomputeUnappliedAsync` จากแถวจริง ⇒ ยอดติดลบไม่ได้ · ลำดับล็อกตรงกับ `VoidPaymentAsync`/`CreateMultiDocPaymentAsync`
- ยกเลิกการชำระหลังจัดสรรทีหลัง: JE `{เลข}/A{n}` + JE ภาษีถูกหักที่อ้างเลขเดียวกันถูกกลับ · ยอดธนาคารกลับเท่า `Amount` · `UnappliedAmount = 0` · ถอยภาษีขายรายใบ · ธง e-Tax kept-original รายใบ
- กลับซ้ำ: ตัวเลือก JE กรอง `Posted && OriginalEntryId == null (&& ReversedByEntryId == null)` · undo ตรวจ `IsDeleted` ใต้ล็อก
- ภาษีถูกหัก ณ ที่จ่าย: ยอดค้างเป็นยอดเงินสด; รับรู้ 11910 เมื่อปิดครบ (GL-first idempotent) — สอดคล้อง 258-1-17
- ปัดเศษ: ทุกจุดใหม่ `MidpointRounding.AwayFromZero` · ยอดจัดสรรต้อง 2 ตำแหน่งพอดี
- Tenant/สิทธิ์: `TenantAccessMiddleware` + ทุก query/`FromSqlRaw` มี `CompanyId` · จัดสรร = Approve ของชนิดใบ · ยกเลิก = Void · อ่าน = เห็นฝั่งขาย
- หน้าเว็บ: ทุกค่าจาก server/ผู้ใช้ผ่าน `Layout.esc` · ป้าย/เหตุผล/ยอดเสนอมาจากเซิร์ฟเวอร์ · `Document.PaymentDate` พิมพ์เฉพาะใบรับรองแทนใบเสร็จ (ไม่กระทบใบแจ้งหนี้ที่ออกแล้ว)
- JE ย้ายภาษี: ด่านงวดปิด/ยื่นแล้วครบทั้งวันจัดสรร (`CCS:280-287`) และวันรับเงิน (`DepositReceiptPeriodLockedAsync`)

## เทสต์ — ด่านที่ถอดออกแล้วไม่มีเทสต์ใดแดง (ค้นใน `CustomerCreditDbTests.cs` + `CustomerCreditRound258Tests.cs` ไม่พบ)

5. ภาษีถูกหัก ณ ที่จ่ายตอนปิดครบด้วยการจัดสรร + การกลับตอน undo
6. การระงับทวงใน `OverdueDunningJob`/`ScanDueSoonAndOverdueAsync` (มีแต่เทสต์ pure ของ `Decide`; จุดเรียกล็อกด้วย checker ข้อความเท่านั้น) และเคสหลายใบ (M1)

9. แปลงใบหลังจัดสรร (M3) · บรรทัดปรับ + เงินเกิน (M2) · เหตุผลของเงินกับงวดภาษี (H1)

## คำตอบ 3 คำถามมาตรฐาน
1. ทางเข้าอื่น: เขียนเงินเกินได้ทางเดียว (เว็บ/REST `payments` พร้อม `allocations`) · เส้นใบเดียว/Integration/นำเข้าไฟล์ ยังปฏิเสธจ่ายเกินด้วย `WouldOverpay` · "นำมัดจำจากสมุดรายวัน" ถูกปิดไม่ให้หยิบ JE เงินเกิน ⇒ ผ่าน · ผู้อ่านที่ไม่เดินด่านเดียวกัน = ทวงหนี้ (M1)
2. ทิศตรงข้าม: (ก) หลายใบ + ค่าธรรมเนียม ถูกปฏิเสธ (เดิมทิ้งเงียบ) — มีทางไปต่อ · (ข) ฝั่งจ่ายเกิน ถูกปฏิเสธ — มีทางไปต่อ · (ค) กิจการจด VAT + "เงินรับล่วงหน้า" ถูกปฏิเสธ — มีทางไปต่อ · (ง) **ใบแจ้งหนี้ VAT จ่ายเต็ม + เงินเกิน เสียใบกำกับอัตโนมัติ (H2)** · (จ) ยกเลิกใบ B ข้อความชี้ทางผิด (L1)
3. สถานะปลายทางที่ระบบประทับเอง: `OutputVatDueAt`/`PaymentDate`/ธง LATE-VAT ถูกประทับจากข้อสันนิษฐานว่าเงินเป็นค่าของใบตั้งแต่วันรับ (H1) · `LastDunningSentAt` ถูกประทับทั้งที่ไม่ได้ส่งทวง (L2 — ตั้งใจ แต่ชื่อช่องไม่ตรงความหมาย)
