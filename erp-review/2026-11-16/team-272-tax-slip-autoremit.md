## 0. สรุปสั้น (อ่านแค่ส่วนนี้ก็ตัดสินได้)

**สิ่งที่เจ้าของขอ:** NextAcc (สำนักงานบัญชี = บริษัทผู้ให้บริการของแพลตฟอร์ม) ส่งเอกสารชำระภาษี (ภ.ง.ด.1/2/3/53/54 · ภ.พ.30/36 · ภ.ง.ด.50/51 · สปส.1-10) ให้ลูกค้าในกลุ่ม LINE/อีเมล ⇒ ลูกค้าจ่ายผ่าน bill payment/e-Filing แล้วส่งสลิปกลับ ⇒ ระบบอ่านสลิป เข้าไปบันทึกการนำส่งใน**บัญชีของบริษัทลูกค้า** ปิดงานให้จบ และ**ตอบผลกลับทุกครั้ง**

**สภาพระบบวันนี้ (ยืนยันจากโค้ด):**
1. **กลุ่ม LINE ของ NextAcc (OA กลาง) ไม่รับรูปเลย** — `LineGroupBindRule.CentralGroupEventActionable` (`Helpers/LineGroupBindRule.cs:131-136`) รับเฉพาะคำสั่ง #HeyNextAcc/#ByeNextAcc · leave · สมาชิกเข้าออก ⇒ สลิปที่ลูกค้าโยนในกลุ่มวันนี้ "เงียบ" (ไม่อ่าน ไม่เก็บ ไม่ตอบ)
2. เส้นสลิปแชตรอบ 260/268 (`LineChatSlipService`) มีอยู่ แต่ทำงานเฉพาะ **OA ของบริษัทเอง** (`Controllers/CustomerLineWebhookController.cs:79,188`) และจับคู่กับ**ใบแจ้งหนี้ขาย** (ลูกค้าจ่ายเรา) — ไม่ใช่การจ่ายภาษีของลูกค้า
3. **ไม่มีเส้นอีเมลขาเข้า** ในเรพเลย (ไม่มี IMAP/MailKit/inbound webhook · DOCUMENT_FLOW บรรทัด 3901 จด "อีเมลขาเข้า" เป็น backlog 255-WP12B-9)
4. **ไม่มีที่เก็บ Control Code / comp code / Ref1-Ref2** ในระบบ (`git grep` = 0 จุด) และไม่มีตารางกรมสรรพากร/สปส. ใดเลย
5. บันทึกนำส่งมีครบ: `StatutoryRemittance` + `StatutoryRemittanceService.RemitAsync` (ทุกแบบ รวมเงินเพิ่ม/เบี้ยปรับ §65 ตรี(6)) — **เส้นสลิปเรียกตัวนี้ตัวเดียว ไม่เขียน JE เอง**
6. **ไม่มีแนวคิด "สำนักงานบัญชีทำแทนลูกค้า"** ระดับระบบ — มีแค่สมาชิกบริษัท (`CompanyUser` + `UserRole.ExternalAccountant/PlatformSupport`) และความยินยอมระหว่างคู่ค้า `PartnerAutomationConsent` (ผูกกับ `TradingPartnership`)
7. การอ่านสลิปทั้งหมด **ในเครื่อง ไม่มี AI** (QR → OCR Tesseract → `OcrSlipText`) ⇒ kill-switch ปลอดภัยโดยโครงสร้าง

**ข้อเสนอหลัก:**
1. **ใบขอชำระ (`TaxPaymentRequest`) เป็นตัวคาดหวัง** — ตอน NextAcc ส่งเอกสารชำระให้ลูกค้า ระบบเก็บ "แบบ · งวด · ยอด · Control Code/Ref ที่อยู่บนใบแจ้งชำระของกรม · ช่องทาง" ไว้ในบริษัทลูกค้า ⇒ สลิปจับคู่ด้วย **Control Code ตรงตัว** (ไม่ต้องเดาจากยอด) · ไม่มีใบขอชำระ ⇒ จับคู่กับยอดค้างใน dashboard นำส่งได้เฉพาะเมื่อ "ยอด + เลขภาษี + แบบเดียวที่ยอดตรง" เป็นหนึ่งเดียว
2. **ตัวตัดสิน pure 3 ตัว**: `GovPaymentSlip` (สลิปนี้จ่ายหน่วยงานรัฐอะไร — ตาราง comp code ที่ยืนยันแล้วเท่านั้น) · `TaxSlipMatch` (จับกับงวดค้าง: ตัวเดียว/หลายตัว/ไม่มี + เหตุ) · `TaxSlipReplyCard` (ข้อความการ์ดทุกผล + ปิดบัง)
3. **ผ่านทุกด่าน ⇒ นำส่งทันที (272-0-1)** ผ่าน `RemitAsync` + แนบสลิปเป็นหลักฐาน (`ReceiptAttachmentId`) · ตอบการ์ด "นำส่งแล้ว" ในกลุ่ม/อีเมล · ด่านไหนไม่ผ่าน ⇒ คิวพนักงาน NextAcc + การ์ดบอกเหตุจริง (ห้ามเงียบ)
4. **ความยินยอม (272-0-2)** = ตาราง append-only คู่แฝดของ `PartnerAutomationConsents` ต่อ (บริษัทลูกค้า × บริษัทผู้ให้บริการ) · ระบบขอเองที่ 3 จังหวะ · ผู้ให้ = เจ้าของ หรือผู้มีสิทธิ์ `Tax.File` + `CompanySettings.Edit` ของบริษัทลูกค้า · ยืนยันบนหน้าเว็บหลังล็อกอิน พิมพ์ "ยินยอม" ครั้งเดียว
5. **ไม่มี AI** ในเส้นนี้ทั้งหมด (ตัวเลขล้วน · F2 ข้อ 3) ⇒ ไม่มี `AiFeatureKey` ใหม่ · ระบุไว้ในตัวตัดสิน `UsedAi => false`

6. ตรวจรูปร่าง: Ref1 ของ RD ต้องผ่าน `ThaiTaxId.IsWellFormed` (`Helpers/ThaiTaxId.cs:75`) + checksum (`ThaiTaxIdValidator`) — ไม่ผ่าน ⇒ "อ่านเลขผู้เสียภาษีบนสลิปไม่ชัด" · Control Code ต้องเป็นตัวเลขล้วนตามความยาวในแถวตาราง (15 — ยังไม่ยืนยันทุกแบบ ⇒ ความยาวอยู่ในแถวตาราง ไม่ hard-code)

## 3. จับคู่กับงวดที่รอชำระของบริษัทลูกค้า — `Helpers/TaxSlipMatch` (pure · ใหม่)

### 3.1 หาบริษัทลูกค้า (ก่อนจับคู่ — ห้ามค้นข้ามผู้เช่า)

```
กลุ่ม (LineIdHash · scope nextacc) ─► ContactNotifyEndpoints ที่ผูกอยู่ (บริษัท NextAcc เท่านั้น)
   ─► Contacts ที่ ExternalSystem = "NextAccTenant" ─► ExternalId = CompanyId ลูกค้า (ชุด "บริษัทที่กลุ่มนี้ผูก")
   ─► เลือกบริษัทด้วย Ref1 (เลขผู้เสียภาษี) == Company.TaxId  **ภายในชุดนี้เท่านั้น**
```

- **ห้าม** `WHERE Companies.TaxId = ref1` ทั้งฐาน (กฎ M · ช่องรั่วข้ามผู้เช่า: ใครก็ส่งสลิปที่มีเลขภาษีบริษัทอื่นมาได้)
- ชุดว่าง (กลุ่มผูกกับผู้ติดต่อที่ไม่ใช่ผู้เช่า) ⇒ "ผู้ติดต่อนี้ไม่มีบัญชีในระบบ — บันทึกให้ไม่ได้" + คิวพนักงาน
- Ref1 ไม่ตรงบริษัทใดในชุด ⇒ `TaxIdNotInGroup` (ไม่เดาบริษัท · บอกในการ์ดแบบปิดบัง `PiiMask.TaxId`)
- Ref1 ตรงมากกว่า 1 บริษัท (สาขาต่างกันเลขเดียวกัน) ⇒ ใช้ Control Code ตัดสิน (3.2) · ไม่ได้ ⇒ `Many`

### 3.2 ตัวคาดหวัง: ใบขอชำระ `TaxPaymentRequest` (ใหม่ · ในบริษัทลูกค้า)

**เหตุผล:** ยอดค้างใน dashboard อย่างเดียวชนกันได้ (ภ.ง.ด.3 กับ 53 ยอดเท่ากัน · ภ.พ.30 สองงวดที่ยังค้าง) และเลขอ้างอิงที่แข็งที่สุดบนสลิปคือ Control Code ซึ่งระบบไม่เคยเก็บ ⇒ ตอนที่ NextAcc **ส่งเอกสารชำระ** ให้ลูกค้า (ขั้นที่ 1 ของเจ้าของ) คือจังหวะที่ระบบรู้ทุกอย่าง

| ช่อง | ความหมาย |
| --- | --- |
| `CompanyId` | บริษัทลูกค้า (tenant isolation) |
| `ProviderCompanyId` | บริษัท NextAcc ผู้ส่ง |
| `RemittanceType` · `PeriodYear` · `PeriodMonth` | ชื่อเดียวกับ `StatutoryRemittance` (`Meta` ตัวเดียว) |
| `Amount` · `Surcharge` · `Penalty` | ยอดที่ลูกค้าต้องจ่ายตามใบแจ้งชำระของกรม (ภาษี + เงินเพิ่ม + เบี้ยปรับที่กรมคิดบนใบ) |
| `ControlCodeHash` + `ControlCodeLast4` | **เก็บแฮช** (HMAC ด้วยคีย์ระบบ — ตัวเดียวกับ `LineIdHash`) + 4 หลักท้ายไว้แสดง · ไม่เก็บค่าเต็ม (ไม่จำเป็น · PDPA ม.22) |
| `ControlCodeExpiresAt` | วันหมดอายุบนใบแจ้งชำระ (ถ้ามี) |
| `IsAmendment` | ยื่นเพิ่มเติม (§8.3) |
| `SentVia` · `SentAt` · `SentByUserId` | ช่องทางที่ส่ง (กลุ่ม LINE/อีเมล) |
| `Status` | `Open` · `Paid` (มีแถวนำส่ง) · `Cancelled` · `Expired` |
| `StatutoryRemittanceId` | ผลปลายทาง |
| `FileAttachmentId` | ใบแจ้งชำระที่ส่งให้ลูกค้า |

- ผู้สร้าง: หน้าใหม่ฝั่ง NextAcc "ส่งเอกสารชำระภาษี" (§9.1) — **กรอก Control Code ครั้งเดียว** (หรืออ่านจากไฟล์ใบแจ้งชำระของกรมด้วยตัวอ่าน PDF ข้อความในเครื่อง — แพ็ก P5 · ยังไม่ยืนยันรูปแบบไฟล์)
- ยอดในใบขอชำระ ≠ ยอดค้างใน dashboard ของลูกค้า (สมุดยังไม่ครบ) ⇒ **บล็อกตอนสร้าง** พร้อมเหตุ "ยอดในสมุดของลูกค้า X ≠ ยอดบนใบแจ้งชำระ Y — ตรวจรายการของงวดก่อนส่ง" (ทางไปต่อ: แก้สมุด หรือติ๊ก "ส่งไปก่อน · ให้สลิปเข้าคิวพนักงาน" ⇒ `Status=Open` + ธง `BooksMismatch` ⇒ สลิปไม่บันทึกเอง)

### 3.3 กติกาการตัดสิน `TaxSlipMatch.Decide(slip, company, requests, pending, alreadyRemitted)`

ลำดับ (ทุกข้อเป็นเลขล้วน — ตรงตัว ไม่มี fuzzy · F2 ข้อ 3):

1. `GovPaymentSlip` = Identified (RD) · มิฉะนั้นจบ
2. Ref1 = TaxId ของบริษัทที่เลือกจาก 3.1 (13 หลักตรงตัว)
3. **มีใบขอชำระที่ ControlCodeHash ตรง** ⇒ ผู้สมัครตัวเดียว (Control Code ตรง = ตัวตน) แล้วตรวจ:
   - ยอดบนสลิป **= `Amount + Surcharge + Penalty` ของใบขอชำระทุกสตางค์** (ค่าธรรมเนียมธนาคาร `Fee` ไม่รวม — §6.3)
   - ใบขอชำระ `Status = Open` · ไม่ `BooksMismatch` · ยังไม่หมดอายุ ณ วันที่บนสลิป (ถ้ามีวันหมด)
   - ยอดค้างของงวดใน dashboard (`PendingRemittanceItem.Amount`) = `Amount` ของใบขอชำระ (ตรวจซ้ำตอนบันทึก — สมุดเปลี่ยนหลังส่ง ⇒ คิว)
   - ⇒ `One`
4. **ไม่มีใบขอชำระที่ตรง** (ลูกค้าจ่ายเองโดยไม่ผ่านใบของเรา · ใบเก่าก่อนรอบนี้) ⇒ ทางสำรองจากยอดค้าง:
   - ผู้สมัคร = `Pending` ทุกแถวของบริษัท (แบบที่ตาราง GovBillers บอกว่าจ่ายผ่าน agency นี้ได้) ที่ `Amount + LateFeePreview(ณ วันที่บนสลิป)` = ยอดบนสลิป **หรือ** `Amount` = ยอดบนสลิป
   - เดือนบนสลิปต้องอยู่ในช่วง [เดือนถัดจากงวด, กำหนดยื่น + 6 เดือน] (จ่ายก่อนงวดสิ้นสุดเป็นไปไม่ได้)
   - ผลเป็น `One` **เฉพาะเมื่อเหลือแถวเดียว** — แต่ **ไม่บันทึกเอง** (ยังไม่มีตัวตน: control code ไม่ได้ยืนยันว่าเป็นแบบไหน) ⇒ `OneWithoutControlCode` = ถามในกลุ่ม/คิวพนักงาน 1 คลิก (ข้อเสนอ — §10 D-3 ถ้าเจ้าของอยากให้บันทึกเองด้วยก็เปลี่ยนจุดเดียว)
   - หลายแถว ⇒ `Many` · ไม่มี ⇒ `None`
5. **กันซ้ำ** (§7) ก่อนทุกผล
6. ทุกผลมี `RuleCode` (`TAX-SLIP-ONE` / `-NOCC` / `-MANY` / `-NONE` / `-AMOUNT` / `-TAXID` / `-EXPIRED` / `-DUP` / `-UNKNOWN-AGENCY` / `-NO-CONSENT`) + `LegalReference` (ป.รัษฎากร ม.52 / ม.83 / ม.69 ทวิ · พ.ร.บ.ประกันสังคม ม.47) + เหตุภาษาไทย

### 3.4 สิ่งที่สลิป **ไม่** ยืนยัน

- **ไม่ใช่เลขรับการยื่นแบบ** ⇒ `TaxReport.Status` ไม่ถูกยกเป็น `Filed` และไม่ล็อกงวด (`TaxFilingLockPolicy.Judge` รับเฉพาะเลขรับ) · ข้อเสนอ: ถ้ารายงานยังเป็น `Draft` ⇒ **ไม่แตะ** และหน้าภาษีขึ้น "มีหลักฐานชำระแล้ว แต่ยังไม่ได้บันทึกการยื่นแบบ/เลขรับ" (D-4 · ทางเลือก: ยกเป็น `Submitted` เพราะ control code ออกหลังยื่นแบบ — ยังไม่ยืนยันว่าจริงทุกแบบ ⇒ ไม่แนะนำ)
- ไม่ยืนยันว่าแบบยื่นถูกต้อง/ครบรายชื่อผู้ถูกหัก (ด่าน `WhtUnissuedCertGate` ใน `RemitAsync` ยังทำงาน — ด่านนี้ไม่ผ่าน ⇒ คิวพนักงาน ไม่ข้ามด่าน)

## 4. บันทึกอะไร (ผ่านทุกด่าน ⇒ ทันที · 272-0-1)

### 4.1 ลำดับใน `TaxSlipRemitService.ApplyAsync` (ใหม่ · ผู้เขียนตัวเดียว)

```
ล็อกแถวใบขอชำระ (FOR UPDATE) + pg_advisory_xact_lock(StatutoryRemit, type:year) ตัวเดียวกับ RemitAsync
 → ตรวจความยินยอม ProviderConsent.Allows(...) ซ้ำใต้ล็อก (ถอนระหว่างทาง ⇒ AwaitingConsent)
 → ตรวจซ้ำ TaxSlipMatch กับข้อมูลใต้ล็อก (ยอดค้าง · ยังไม่นำส่ง)
 → เก็บไฟล์สลิปเป็น FileAttachment ในบริษัทลูกค้า (หมวดหลักฐานนำส่ง · AttachmentAccessGate เดิม)
 → RemitAsync(clientCompanyId, RemitRequest{ type, year, month, PayDate=วันที่บนสลิป(เวลาไทย),
        BankAccountId=§4.2, ReceiptAttachmentId, FilingNumber=null, IncludeLateFee, LateSurcharge/Penalty=§4.3,
        Note="บันทึกจากสลิป · Control Code ••1234 · Txn ••5678 · โดย NextAcc (ความยินยอม <id>)" },
        performedBy="provider-slip:auto")
 → ประทับใบขอชำระ Paid + StatutoryRemittanceId · แถวสลิป Status=Remitted
 → audit ×2 (บริษัทลูกค้า: TaxSlipRemitted + RuleCode + consentId · บริษัท NextAcc: ProviderActedForClient)
 → การ์ดผล (§5.6/§6)
```

- **ไม่มีเส้นที่สอง** ในการเขียน JE/แถวนำส่ง — `RemitAsync` ตัวเดียว (เส้นมือ/เส้นสลิปเดินด่านเดียวกัน · F3 ข้อ 8) · ล็อกจุดเรียกด้วย `tools/required_call_site_check.py` (ห้ามสร้าง `StatutoryRemittance` เองในเส้นนี้)
- ฟิลด์ใหม่บน `StatutoryRemittance` (ADD COLUMN IF NOT EXISTS · echo กลับใน DTO ประวัติ · F4-B): `Source` (`Manual`/`Slip`/`SettledOutside`) · `SlipEvidenceId` · `ActedByProviderCompanyId` · `ProviderConsentId` — **ไม่ยืมช่อง `Note`/`FilingNumber`** (กฎ #4 E)
- `RemitAsync` ล้มด้วย `BusinessRuleException` (ยอดค้างเปลี่ยน · 50 ทวิ ไม่ครบ · นำส่งงวดนี้ไปแล้ว) ⇒ แถวสลิป `ToStaff` พร้อม `RuleCode` เดิมของด่านนั้น + การ์ดบอกเหตุ — **ไม่ catch {} กลืน** (กฎ #4 E)

### 4.2 บัญชีธนาคาร (ฝั่ง Cr) — ใช้เลขปิดบางบนสลิป

ตัวตัดสิน `TaxSlipBankAccount.Decide` (pure · ลำดับชั้นแบบ `PartnerPaySourceAccount.Precedence`):

| ชั้น | ที่มา | บันทึกเองได้ (272-0-1) |
| --- | --- | --- |
| 1 | บล็อก "จาก" บนสลิป ⇒ `SlipAccountMatch.Match` = `Unique` ในบัญชีธนาคารของ**บริษัทลูกค้า** | ✅ ใช่ — **ข้อยกเว้นที่ตั้งใจต่อ 264-4-9** (เหตุ §6.4) |
| 2 | บัญชีชำระภาษีที่ลูกค้าระบุไว้ในความยินยอม (`DefaultTaxPayBankAccountId`) **และ** ธนาคารบนสลิปตรงธนาคารของบัญชีนั้น **และ** เลขที่เห็นไม่ขัด | ✅ ใช่ |
| 3 | `Many` / `Unreadable` / ไม่มีบล็อก "จาก" (บัตรเครดิต · e-Payment) | ❌ ⇒ `NeedsAccount` — การ์ด "ได้รับสลิปแล้ว รอพนักงานเลือกบัญชีที่จ่าย" + คิวพนักงาน 1 คลิก (บัญชีที่เป็นไปได้ preselect) |
| 4 | `NotOurs` (เลขชัดแต่ไม่ใช่บัญชีของบริษัท — เช่นกรรมการจ่ายจากบัญชีส่วนตัว) | ❌ ⇒ คิวพนักงาน พร้อมทางไปต่อ "บันทึกเป็นเงินทดรองกรรมการ" (เลือกผัง Cr อื่นได้ผ่าน `BankGlAccountId` ของ `RemitRequest`) |

- ชั้น 3–4 = **ยังไม่ "จบ"** ตามความหมายของ 272-0-1 เพราะ JE ไม่มีฝั่ง Cr ที่มีหลักฐาน — ระบบ**ไม่**ลงบัญชีพักเอง (ไม่สร้างสถานะปลายทางที่ประทับเอง · F2 ข้อ 3) · ข้อเสนอทางเลือก D-5: ลงผัง "เงินจ่ายรอระบุบัญชี" แล้วพนักงานย้ายทีหลัง (ไม่แนะนำ — เพิ่ม JE ปรับปรุงทุกใบ + ยอดพักค้างเงียบ)
- **ตัวตรวจทานหลังนำส่ง:** เมื่อ statement ของบัญชีนั้นเข้ามา ⇒ ตัวจับ `BankPaymentLineMatch` (ยอด ±0.00 · ±3 วัน · เงินออก) ผูก `MatchedJournalEntryId` กับ JE นำส่ง · ไม่พบภายใน 10 วันหลังวันที่สลิป หรือพบในบัญชีอื่น ⇒ ธง "ตรวจบัญชีที่จ่าย" บนหน้านำส่ง + กระดิ่งพนักงาน NextAcc (**ไม่กลับรายการเอง**)

### 4.3 เงินเพิ่ม / เบี้ยปรับ (§65 ตรี(6) รายจ่ายต้องห้าม)

- ยอดบนสลิป − ยอดภาษีค้าง = ส่วนที่จ่ายเกิน ⇒ **ห้ามเดาเอง** ว่าเป็นเงินเพิ่มหรือเบี้ยปรับ:
  - มีใบขอชำระ ⇒ ใช้ `Surcharge`/`Penalty` บนใบขอชำระ (มาจากใบแจ้งชำระของกรม = ตัวเลขของกรม) → `RemitRequest.LateSurcharge` / `Penalty`
  - ไม่มีใบขอชำระ ⇒ ส่วนต่างต้อง **= `SuggestPenalties(...)` ณ วันที่บนสลิปทุกสตางค์** (`LatePaymentPenaltyPolicy` ตัวเดียว · ม.27 1.5%/เดือน · ปกส. ม.49 2%/เดือน) ⇒ จึงยอมรับเป็นเงินเพิ่ม · ไม่ตรง ⇒ คิวพนักงาน ("ยอดเกินภาษี X บาท ระบบแยกไม่ได้ว่าเป็นเงินเพิ่มหรือเบี้ยปรับ")
- ผังค่าปรับ = `PenaltyExpenseAccount` (54820) · บวกกลับ ภ.ง.ด.50 อัตโนมัติผ่าน `ComputeSection65TerAddBackAsync` (อ่านจากแถวนำส่ง — ไม่ต้องเพิ่มอะไร)
- ค่าธรรมเนียมธนาคาร (`Fee` บนสลิป ≠ 0) ⇒ **ไม่อยู่ในยอดนำส่ง** · v1 = คิวพนักงาน (ไม่มีช่องค่าธรรมเนียมใน `RemitRequest` · backlog)

### 4.4 แนบสลิปเป็นหลักฐาน

- ไฟล์สลิป ⇒ `FileAttachment` ของบริษัทลูกค้า → `StatutoryRemittance.ReceiptAttachmentId` · เก็บตาม**ระยะเก็บของเอกสารบัญชี** (พ.ร.บ.การบัญชี ม.14 ≥ 5 ปี · ป.รัษฎากร ม.87/3) ⇒ `legal_hold` · **ไม่** ถูกงานลบรูปแชต 90 วันลบ (คนละถัง — F2 ข้อ 9)
- สำเนาในแถวสลิปแชตลบทันทีหลังแนบ (แบบ `DropFileAsync`)

### 5.2 ใครให้ความยินยอมได้ (ฝั่งลูกค้า)

**แนะนำ:** ผู้ใช้ที่มี `CompanyUser` ในบริษัทลูกค้า และ (`Role = Owner`) **หรือ** (มีสิทธิ์ `Tax.File` **และ** `CompanySettings.Edit`) — แปลงเป็น `Need` ผ่าน `PartnerConsent.GrantProblem` ตัวเดิม (ไม่เขียนกติกาสิทธิ์ซ้ำ)
- **ไม่นับ** `ExternalAccountant`/`PlatformSupport` ของ NextAcc เอง แม้มีสิทธิ์ Tax.File ในบริษัทลูกค้า (**ผู้ขอให้เองไม่ได้** — ผลประโยชน์ขัดกัน · F9 ของ 264 "คู่ค้าได้แค่ขอ") ⇒ ตรวจ: ผู้ให้ต้องไม่เป็นสมาชิกบริษัท NextAcc
- บริษัทที่ไม่มีผู้ใช้เข้าเว็บเลย (`CompanyKind.Connected` หรือ NextAcc ทำทุกอย่างแทน) ⇒ ทาง C (5.3) เป็นทางเดียว — ดู D-6
- ข้อเสนอเพิ่ม (D-7): เจ้าของคนเดียวพอ ไม่ต้องสองคน

### 5.7 ถอน + สลิปที่มาก่อนยินยอม

- **ถอน**: ที่การ์ดในศูนย์บิล/หน้า partner-automation (ผู้มีสิทธิ์ให้ = ผู้มีสิทธิ์ถอน · เจ้าของถอนได้เสมอ) · ประทับ `WithdrawnAt` ครั้งเดียว (trigger append-only) · ผลทันที: ทุกการเขียนตรวจ `Allows` ใต้ล็อก (§4.1) ⇒ สลิปที่กำลังประมวลไม่ถูกบันทึก · **รายการที่บันทึกแล้วไม่ถูกกลับเอง** (ยกเลิกเองได้ที่หน้านำส่งตามเส้นเดิม) · คำสั่งในกลุ่ม `#หยุดบันทึกภาษี` = แสดงวิธีถอน (คนในกลุ่มไม่ใช่ผู้มีอำนาจ) — แต่ #ByeNextAcc/เตะบอท ⇒ หยุดรับสลิปจากกลุ่มนั้นทันที (ปลายทางถูกปลด)
- **สลิปก่อนยินยอม**: เก็บในแถวสลิป `AwaitingConsent` (ไฟล์ในถังรอ · RoPA ระบุ "รอการอนุญาต ≤ 30 วัน") · ข้อความยินยอมระบุ **จำนวน + แบบ/งวด** ของสลิปที่พักไว้ และติ๊ก "รวมสลิปที่รออยู่" (เปิดเป็นค่าเริ่มต้น · เอาออกได้) ⇒ หลังยินยอม งานเบื้องหลังประมวลใหม่**ทั้งชุดด่าน** (ข้อมูลอาจเปลี่ยนระหว่างรอ) · ไม่ติ๊ก/หมดอายุ ⇒ คิวพนักงาน (ไม่ลบเงียบ)

### 5.8 ที่เก็บ — ใช้แพตเทิร์น PartnerConsent ซ้ำ

| ทางเลือก | ผล | แนะนำ |
| --- | --- | --- |
| (i) ขอบเขตใหม่ใน `PartnerAutomationConsent` + บังคับสร้าง `TradingPartnership` NextAcc⇄ลูกค้า | ได้ทุกอย่างฟรี แต่การยอมรับ partnership เปิดงานข้ามผู้เช่าอื่น ๆ ที่เป็นค่าตั้งระดับบริษัท (`PurchaseDrafts` `CompanyWideToggle=true` — ใบแจ้งหนี้ค่าบริการ NextAcc กลายเป็นใบซื้อร่างเอง) = ผลข้างเคียงเงียบ | ❌ |

## 8. Kill-switch + กรณีขอบ

### 8.1 Kill-switch AI

- ไม่มีจุดเรียก AI ⇒ ปิด provider ทุกตัวแล้วทำงานเหมือนเดิม 100% (QR → Tesseract → กติกา) · เทสต์ระบุชัด: `TaxSlipMatch` ทุกเคสรันโดยไม่มี orchestrator ใน DI
- Tesseract ไม่มี tessdata (`ISlipImageReader.IsAvailable=false`) ⇒ QR อย่างเดียวไม่พอ (ไม่มียอด/Ref) ⇒ ทุกสลิป `NoMatch` + แถวความพร้อมบนหน้าตั้งค่า NextAcc "อ่านสลิปไม่ได้ในเครื่องนี้" (ล้มดัง · ไม่ใช่เงียบ)
- สวิตช์ระดับระบบของเส้นนี้: `SiteSettings.TaxSlipIntakeEnabled` (แอดมิน) + ต่อบริษัทผ่านความยินยอม · ปิด ⇒ รูปในกลุ่มกลับไปพฤติกรรมเดิม (ไม่อ่าน) **และ** การ์ดตอบ T3 ถูกแทนด้วย "ระบบปิดรับสลิปชั่วคราว — ส่งพนักงานโดยตรง" สำหรับกลุ่มที่เคยยินยอม (ไม่ให้ลูกค้าคิดว่าส่งแล้วจบ)

### 8.2 กรณีขอบ

| กรณี | ออกแบบ |

## 9. UX

### 9.1 ฝั่ง NextAcc — "ส่งเอกสารชำระภาษี" (หน้าใหม่ หรือแท็บในหน้าผู้ติดต่อ)

- เลือกลูกค้า (ผู้ติดต่อ `NextAccTenant`) ⇒ ระบบดึงยอดค้างจาก dashboard ของบริษัทลูกค้า (อ่านข้ามผู้เช่าผ่าน service ที่ตรวจความสัมพันธ์ผู้ให้บริการ — ไม่ใช่ query ตรง) · กรอก Control Code + แนบใบแจ้งชำระ ⇒ ส่งการ์ดเข้ากลุ่ม/อีเมลของผู้ติดต่อ + สร้าง `TaxPaymentRequest`
- การ์ดใบแจ้งชำระในกลุ่ม: "ใบแจ้งชำระ ภ.พ.30 งวด ต.ค. 2569 · ยอด 12,345.67 · ชำระภายใน 15 พ.ย. 2569 · จ่ายแล้วส่งสลิปกลับในกลุ่มนี้" (+ บรรทัด T2 ถ้ายังไม่ยินยอม)

### 9.2 ฝั่ง NextAcc — คิว "สลิปภาษีรอตรวจ"

- ที่วาง: หน้ารายการรับชำระออนไลน์ของบริษัท NextAcc มีคิวสลิปแชตอยู่แล้ว ⇒ **แท็บใหม่ "สลิปภาษีของลูกค้า"** (ตัวนับแยก · คนละตาราง)
- แถว: รูปสลิป (เปิดดู · สิทธิ์) · ลูกค้า · หน่วยงาน · ยอด · Control ••4321 · **เหตุ (ป้ายจาก RuleCode)** · ผู้สมัคร (ถ้ามี) · บัญชีที่ preselect
- การกระทำ: [บันทึกนำส่ง] (เลือกงวด/บัญชี · เงินเพิ่มที่ระบบเสนอ — ปุ่มเดียว · ใต้ล็อกเส้นเดียวกัน · ต้องเป็นสมาชิกบริษัทลูกค้าที่มีสิทธิ์ `Tax.File` **หรือ** บริษัทลูกค้ายินยอมแล้ว) · [ไม่ใช่สลิปภาษี] · [ส่งคำขออนุญาตอีกครั้ง] · ทุกการกระทำ ⇒ การ์ดผลตามหลังในกลุ่ม
- ช่องที่ server ไม่รับ (เช่นเปลี่ยนยอด) ⇒ ล็อกช่อง + บอกเหตุ (ห้าม silent no-op)

### 9.3 ฝั่งลูกค้า — หน้าภาษี/นำส่ง (`tax-remittance.html` · `tax-calendar.html`)

- ประวัตินำส่ง: ป้าย **"ยืนยันจากสลิป · NextAcc"** (`Source=Slip`) + ลิงก์หลักฐาน + Control ••4321 + ผู้ทำแทน + เลขความยินยอม · ธงตรวจทาน "รายการเดินบัญชียืนยันแล้ว ✓ / ยังไม่พบในรายการเดินบัญชี ⚠" (4.2)
- ปฏิทินยื่น: ช่องงวดนั้นเป็น "ชำระแล้ว (สลิป)" · ถ้ารายงานยังไม่มีเลขรับ ⇒ บรรทัดรอง "ยังไม่ได้บันทึกเลขรับการยื่นแบบ" (3.4 · ไม่โกหกว่า "ยื่นแล้ว")
- ป้ายทั้งหมดคำนวณที่ server (`TaxSlipRemitView`) · JS แสดงเท่านั้น
