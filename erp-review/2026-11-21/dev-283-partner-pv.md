# รอบ 283 — ท่ออัตโนมัติคู่ค้าของผู้ซื้อออก "ใบสำคัญจ่าย" เป็นเอกสาร (คำสั่งเจ้าของ)

> คำสั่งเจ้าของ: เส้นอัตโนมัติคู่ค้า (รอบ 264 P3/281 · ท่อผู้ซื้อ B) บันทึกการจ่ายใบซื้อพร้อม JE + 50 ทวิ แต่ไม่ออกใบสำคัญจ่ายเป็นใบ ⇒ ต้องการให้ออกด้วย
> ผ่านเส้นเดียวกับทางมือ · เลขออกตอนอนุมัติ · ผูก 50 ทวิ ใบเดิม · ไม่ลงบัญชีซ้ำ · ป้าย "ระบบสร้างจากคู่ค้า" + audit · ใบเก่า ⇒ รายงาน + ออกย้อนหลัง
>
> คำตัดสิน `283-1…283-6` ใน `erp-review/2026-09-29/DECISIONS.md` · สถานะปัจจุบัน `DOCUMENT_FLOW.md` §2.12g-281 (บล็อก "รอบ 283") · เทสต์ `TEST_PLAN.md` T283-01…04 ·

## 1. ทางมือทำอย่างไร (ยืนยันจากโค้ด)

| ทาง | ผล | JE | 50 ทวิ |
| --- | --- | --- | --- |
| "💰 บันทึกชำระเงิน" บนใบซื้อ (`DocumentService.CreatePaymentAsync`) | แถว `Payment` เท่านั้น — **ไม่มีเอกสาร PV** (ข้อความบนหน้าเอกสาร "ระบบจะออกใบสำคัญจ่าย" ไม่ตรงความจริง) | Dr เจ้าหนี้ / Cr ธนาคาร + Cr ภาษีหักค้างจ่าย | ต่องวดจ่าย (`SourcePaymentId` · `DocumentId` = ใบซื้อ) |
| "แปลงเป็นใบสำคัญจ่าย" (`ConvertCoreAsync` → PV `RelatedDocumentId` → อนุมัติ) | เอกสาร PV | PV ลงเอง + ตัดหนี้ใบซื้อ (`ApplySourceDocumentAdjustmentsAsync`) | ตอนอนุมัติ PV (`DocumentId` = PV) · ผูกใบมือได้ (`WhtCertLinkPlan` รอบ 271) |
| ท่อคู่ค้า (`PartnerPayablePipeline.ProcessAsync`) ก่อนรอบนี้ | ทางแรก (`PaymentEntrySource.PartnerAuto`) | เหมือนทางแรก | เหมือนทางแรก |

ถ้าให้ท่อ "แปลง + อนุมัติ PV" **เพิ่ม**จากการจ่าย = JE เงินออกสองครั้ง + 50 ทวิ ใบที่สอง · ถ้าให้ท่อใช้ PV **แทน**การจ่าย = ต้องรื้อทุกส่วนที่อ้าง `Payment`
(การแจ้ง `RecordedPaymentId` · ผูกรายการเดินบัญชี · ผู้ขายยกเลิก · กันซ้ำด้วย `Reference` · ส่ง 50 ทวิ ให้คู่ค้า · เส้นทางของใบ) — เสี่ยงเกินรอบเดียว

## 2. ทางที่เลือก (283-1)

คงการจ่ายเดิม + ออก PV เป็น **"หลักฐานคู่การจ่าย"** ในธุรกรรมเดียวกัน — รูปแบบที่ระบบมีอยู่แล้วฝั่งขาย (ใบเสร็จหลักฐาน `IsSettlementReceipt` + `SettlementPaymentId`)
ซึ่งทุกเส้นแกนข้ามอยู่แล้ว: อนุมัติไม่ลง JE/ไม่ตัดหนี้ · ไม่นับเป็นเอกสารปลายทาง · ลบพร้อมใบแม่ · ตรวจ JE หายไม่ฟ้อง

- ยอดบนใบ = เงินออก 10,400 · **VAT = ภาษีหัก = 0 บนใบ** ⇒ ผู้อ่านภาษีทุกตัว (ภ.ง.ด.3/53 · `WhtRemitScope.SettledSourceIds` · ลิสต์รอออก 50 ทวิ · ภ.พ.30) ไม่เห็นใบนี้ —
  ถ้าใบถือ 300 ผู้อ่านจะถือว่า PV "คลุม" ใบซื้อแล้วฟ้องว่า PV ไม่มี 50 ทวิ (ด่านนำส่งบล็อก) · ภาษีหัก + เลข 50 ทวิ แสดงในบรรทัด (`DocumentLabels` th/en)
- 50 ทวิ: ใบเดิมของการจ่าย ผูกด้วยกุญแจการจ่าย (`PV.SettlementPaymentId == cert.SourcePaymentId`) — ไม่ย้าย `DocumentId` · ไม่ออกใหม่
- ป้าย `OriginLabel` (server computes) บนรายการเอกสาร · audit `SettlementPaymentVoucherIssued` / `…Backfilled` / `…VoidedWithPayment`

## 4. ยังไม่ทำ / ข้อสังเกต

- ปุ่ม "ออกใบสำคัญจ่ายย้อนหลัง" บนหน้า (เช่น `partner-automation.html`) — รอบนี้มี API + สิทธิ์ + เทสต์ แล้ว · หน้าเว็บเป็นงานต่อ
- ทางมือ "บันทึกชำระเงิน" ของใบซื้อไม่ออก PV แต่ข้อความชี้ทางบนหน้าเอกสารบอกว่าออก — ข้อเสนอ: ตัวเลือก "ออกใบสำคัญจ่าย" ในโมดัล (ใช้ `IssuePaymentVoucherDocument` ตัวเดียวกัน) หรือแก้ข้อความ
- รายการการจ่ายของใบซื้อ (`payments` ของเอกสาร) จะแสดงเลข PV ในช่องเอกสารหลักฐาน (ตัวหาใบเสร็จของการจ่ายอ่าน `SettlementPaymentId` ไม่กรองชนิด) — ถูกความหมาย แต่ป้ายช่องเขียน "ใบเสร็จ"
