## 0. คำตัดสินโดยย่อ

| รูปแบบการใช้ | คำตัดสิน | ความเชื่อมั่น |
| --- | --- | --- |
| **A.** OA กลางส่ง**ข้อความธุรกรรม** (เอกสาร/ทวงชำระ/ใบเสร็จ/50 ทวิ/ลิงก์เซ็น) แบบ 1:1 ถึงผู้ใช้ที่**เพิ่มเพื่อน @nextacc และผูกด้วยรหัสเอง** โดย NextAcc เป็นผู้ควบคุมบัญชีแต่เพียงผู้เดียว · มีป้าย "ในนาม {บริษัท} · ผ่าน NextAcc" | **ได้ แบบมีเงื่อนไข** (§3) | กลาง |
| **B.** แบบ A แต่ส่งเข้า**กลุ่ม LINE ของผู้ติดต่อ** ที่เชิญบอทเข้าเองและผูกด้วยรหัส `GB-…` | **ได้ แบบมีเงื่อนไข** (เงื่อนไขมากกว่า A) | กลาง–ต่ำ |
| **C.** ผู้เช่าส่ง**ข้อความโปรโมชัน/การตลาด** ของตัวเองผ่าน OA กลาง (broadcast/narrowcast/ข้อความเลือกเนื้อหาเอง) | **ไม่ได้** · ขัดข้อห้าม "ใช้บัญชีเป็นสื่อโฆษณาของบุคคลภายนอกโดยไม่ได้รับความยินยอมจากบริษัท (LINE)" | สูง |
| **D.** ให้ผู้เช่า**เข้าถึง/ควบคุม OA กลาง** (ล็อกอิน OA Manager · token · ตอบแชตเอง) | **ไม่ได้** · ขัดข้อห้ามโอน/ให้ยืม/แบ่งปันบัญชี และข้อห้ามให้บุคคลอื่นนอกจาก Operator ใช้ ID | สูง |
| **E.** ส่งให้ผู้ใช้ LINE ที่**ยังไม่เป็นเพื่อน** OA กลาง | **ทำไม่ได้ทางเทคนิค** ด้วย Messaging API · มีทางเดียวคือ LINE Official Notification (โปรแกรมพาร์ตเนอร์ ต้องสมัคร) | สูง |
| **F.** การใช้งานรอบ 211/212 ที่มีอยู่แล้ว (แจ้งลูกค้าร้านเรื่องการจอง/คำสั่งซื้อ · สรุปรายวันพนักงาน · สลิปเงินเดือน · บิลแพลตฟอร์ม) | **ได้ แบบมีเงื่อนไข** เหมือน A · ไม่มีข้อที่ต้องปิด แต่ต้องเติมเงื่อนไข 2 ข้อ (§5) | กลาง |

**คำแนะนำสถาปัตยกรรม:** คงโมเดล "OA ของบริษัทก่อน · OA กลางเป็นทางถอย" ตาม design §3.a และ**ผลักให้ผู้เช่าที่ใช้กลุ่ม/ปริมาณมากเชื่อม OA ของตัวเอง** (§6) · ขอหนังสือยืนยันจาก LINE ประเทศไทยว่าการใช้งานแบบ A/B ทำได้ (§7) · ไม่ต้องสมัครโปรแกรมพาร์ตเนอร์สำหรับ A/B แต่ถ้าจะส่งถึงคนที่ไม่เป็นเพื่อน ต้องใช้ LINE Official Notification (§4.5)

## 1. ขอบเขตคำถาม

NextAcc มี OA หนึ่งบัญชี (@nextacc · `SiteSettings`/`NextAccLineConfig`) ใช้ส่งข้อความในนามบริษัทผู้เช่าหลายราย ถึงลูกค้า/ผู้ขายของผู้เช่า ทั้ง 1:1 และกลุ่ม โดยมีป้าย "ในนาม {บริษัท} ผ่าน NextAcc" (design §6.2)
คำถามย่อย: (1) ข้อกำหนดห้ามการใช้ OA เดียวแทนหลายธุรกิจไหม (2) ต้องมีความยินยอม/การเป็นเพื่อนก่อนไหม (3) ข้อมูล userId ใช้ข้ามผู้เช่าได้ไหม (4) ต้องเป็นพาร์ตเนอร์/ใช้ Module channel ไหม (5) PDPA (6) การใช้งานรอบ 211/212

## 4. ประเด็นเฉพาะ

### 4.1 OA เดียวแทนหลายธุรกิจ
ไม่พบข้อความที่ห้ามโดยตรง · T4 แสดงว่า "ให้บริษัทอื่นใช้บัญชี" ทำได้เฉพาะบริษัทที่เกี่ยวข้อง ⇒ โมเดลที่ปลอดภัยคือ **NextAcc ไม่ได้ให้ผู้เช่าใช้บัญชี แต่ให้บริการส่งเอกสารภายใต้แบรนด์ของ NextAcc เอง** (ผู้เช่าเป็นลูกค้าของบริการ ไม่ใช่ผู้ใช้บัญชี) — เงื่อนไข C1–C3 คือสิ่งที่ทำให้คำอธิบายนี้เป็นจริง

### 4.2 ส่งถึงผู้ที่ยังไม่เป็นเพื่อน
ทำไม่ได้ด้วย Messaging API (D4) · LINE Official Notification (ส่งด้วยเบอร์โทร hash SHA-256 ถึงผู้ไม่เป็นเพื่อน) มีในไทยเท่านั้น **ต้องเป็นพาร์ตเนอร์ที่ได้รับคัดเลือก + บัญชี Verified + ข้อความผ่านการตรวจ + ผู้รับยินยอมรับ LON** (lineforbusiness.com/th-en/service/line-official-notifications · developers `line-notification-messages`) ⇒ ไม่อยู่ในขอบเขต L2–L3 · ถ้าในอนาคตต้องการ ต้องสมัครกับ LINE ประเทศไทย

### 4.3 กลุ่ม
เทคนิคทำได้ (D3 · push `to = groupId`) · ข้อกำหนดไม่มีข้อเฉพาะเรื่องกลุ่มที่พบ · ความเสี่ยงเพิ่มคือสมาชิกกลุ่มบางคน**ไม่ได้เลือกรับเอง** ⇒ C4 (ประกาศในกลุ่ม + ผู้ดูแลบริษัทรับรอง) และ C10 · ระดับความเสี่ยงสูงกว่า 1:1

### 4.4 ต้องเป็นพาร์ตเนอร์/Module ไหม
- สำหรับ A/B (OA ของ NextAcc เอง): **ไม่พบข้อกำหนดว่าต้องเป็นพาร์ตเนอร์**
- สำหรับ "NextAcc ส่งผ่าน OA ของผู้เช่า": โมเดลปัจจุบัน (ผู้เช่าใส่ channel token ของตัวเอง) สอดคล้อง A1 (NextAcc = Operator) และคำเตือน D2 (channel อยู่ใต้ provider ของผู้เช่า) · Module channel (D7) เป็นทางเลือกที่สะอาดกว่า (OAuth · ผู้เช่ากดอนุญาต · ไม่ต้องคัดลอก token) แต่ต้องสมัคร และหลักฐานเป็นของญี่ปุ่น ⇒ **ขอข้อมูลจาก LINE ประเทศไทยว่ามี Module/Partner program ในไทยหรือไม่** (§7)
- ทางเลือกเชิงพาณิชย์: LINE ประเทศไทยมีโปรแกรมพาร์ตเนอร์/เอเจนซี (และประกาศ reply API 2570 ที่อ้างถึง "Agency Global Platform") ⇒ การเป็น Technology/Sales Partner อาจช่วยทั้งเรื่องคำยืนยันและราคา (ไม่ใช่เงื่อนไขบังคับที่พบ)

## 6. สถาปัตยกรรมที่แนะนำ

1. **OA ของบริษัทเป็นช่องหลัก · OA กลางเป็นทางถอย** (design §3.a เดิม) · หน้าตั้งค่าแนะนำผู้เช่าให้เชื่อม OA ของตัวเองเมื่อ: ใช้กลุ่ม · ส่ง > ~600 ข้อความ/เดือน · ต้องการโลโก้/ชื่อร้านเป็นผู้ส่ง · ต้องการตอบแชตลูกค้าเอง · ต้องการส่งข้อความการตลาด (ทำได้**เฉพาะ** OA ของตัวเอง)
2. **คู่มือเชื่อม OA ของผู้เช่า:** สร้าง Messaging API channel ใต้ provider **ของผู้เช่าเอง** (D2) · NextAcc เป็น Operator (A1) · เปิด "Allow bot to join group chats" ถ้าจะใช้กลุ่ม (D3)
3. **OA กลางจำกัดไว้ที่ข้อความธุรกรรมตามแม่แบบ** (C2) · ไม่มี API ให้ผู้เช่าส่งข้อความอิสระ
4. **แยก OA กลางเป็นสองบัญชี (ข้อเสนอ · ลดความเสี่ยง T6):** `@nextacc` (บอทบัญชี ERP + แจ้งพนักงาน + บิล · ข้อความของ NextAcc เอง) และ `@nextacc-docs` (ส่งเอกสารในนามผู้เช่าถึงผู้ติดต่อ) — ถ้าบัญชีส่งเอกสารถูกระงับ บอทบัญชีของผู้ใช้ทุกคนยังทำงาน · ⚠ ข้อเสีย: userId ต่างกันถ้าอยู่คนละ provider (D2) ⇒ ให้อยู่ provider เดียวกันของ NextAcc · ผู้รับต้องเพิ่มเพื่อนบัญชีที่สอง · และระวัง T6 ซึ่ง LINE อาจห้ามผู้ดูแลชุดเดียวกันเปิดบัญชีอื่นเมื่อบัญชีหนึ่งผิด ⇒ การแยกบัญชีลดความเสียหายทางเทคนิค แต่ไม่ได้ลดความเสี่ยงทางข้อกำหนด
5. **สวิตช์ระงับทันที** ที่หน้าแอดมิน: ปิด OA กลางสำหรับผู้ติดต่อทั้งระบบ / รายบริษัท / เฉพาะกลุ่ม (design §5.4 มีสวิตช์ทั้งระบบแล้ว ⇒ เพิ่มรายบริษัท)
6. **ไม่ต้องสมัครโปรแกรมพาร์ตเนอร์เพื่อเริ่ม L2–L3** · พิจารณาสมัครเมื่อ (ก) ต้องการ LON ส่งถึงผู้ไม่เป็นเพื่อน (ข) ต้องการ Module channel แทนการคัดลอก token (ค) reply API เริ่มคิดเงินและราคาผ่านเอเจนซีถูกกว่า

## 7. สิ่งที่ต้องทำก่อนเปิดสวิตช์กลุ่มผ่าน OA กลาง

1. ฝ่ายกฎหมายเปิดอ่านตัวบทเต็ม 3 ฉบับ (OA Terms TH · OA Guideline TH · OA API Terms TH) และยืนยันแถว T1–T7 · G1–G3 · A1–A3 (ทีมนี้อ่านได้แค่ข้อความบางส่วน)
2. ส่งคำถามเป็นลายลักษณ์อักษรถึง LINE ประเทศไทย (ผ่านผู้ดูแลบัญชี/ฝ่ายขาย LINE for Business หรือแบบฟอร์มติดต่อใน OA Manager): *"NextAcc เป็นซอฟต์แวร์บัญชี ต้องการใช้ OA ของเราส่งใบแจ้งหนี้/ใบเสร็จ/ทวงชำระ ในนามบริษัทลูกค้าของเรา ถึงผู้ติดต่อที่เพิ่มเพื่อนและผูกรหัสเอง ทั้ง 1:1 และในกลุ่มที่เขาเชิญบอทเข้า โดยมีป้าย 'ในนาม {บริษัท} ผ่าน NextAcc' ไม่มีเนื้อหาโฆษณา — ขัดข้อ 17(1)/(6) ของข้อกำหนดหรือไม่ และต้องขออนุญาตล่วงหน้าตามข้อ 17(6) หรือไม่"* · เก็บคำตอบไว้ใน `erp-review/` (ถ้าต้องขออนุญาต ⇒ ขอก่อนเปิด)
3. เติมเงื่อนไข C2 (ห้ามลิงก์ภายนอก · ปิดข้อความอิสระ) · C5 (บรรทัดยกเลิกในการ์ด) · C7 (เพดานต่อผู้รับข้ามบริษัท) · C8 (คัดกรองผู้เช่า + ระงับรายบริษัท) · C9 (ข้อตกลงผู้เช่า + DPA) ลงในแผน L2/L3
4. ตรวจแม่แบบของ `BookingNotifier` (รอบ 211) ตาม §5
