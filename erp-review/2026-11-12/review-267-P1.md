## HIGH

### H1 — ออก Rev ใหม่แล้วลิงก์เดิมยัง "ยอมรับ/เซ็นรับ" ได้ + ยอมรับฉบับที่ลูกค้าไม่เคยเห็น (TOCTOU)
- `DocumentService.cs:3094-3104` — เส้น revision ล้าง `QuotationAcceptToken`/`DeliverySignToken` (ลิงก์รุ่นก่อน) + `ClearOn` แต่ **ไม่แตะ `PayLink*` และไม่ล้าง `SignLinkIssuedAt`**
  (คอมเมนต์ตรงนั้นยังเขียนว่า "ลิงก์เดิมต้องใช้ต่อไม่ได้ (ขอลิงก์ใหม่ให้คู่ค้ายืนยัน Rev ปัจจุบัน)")
- `PQC:167-169, 198-202` — เปิดด้วย token ของหน้าเอกสาร: ด่านมีแค่ช่วงตอบรับ + "ลิงก์ไม่ถูกเพิกถอน" · เงื่อนไขจอง `QuotationAcceptToken == doc.QuotationAcceptToken` เป็น `null == null` เสมอ
  ⇒ ไม่มีอะไรผูกกับ Rev ที่ลูกค้าเห็น · คำขอ `AcceptRequest` (`PQC:150`) ไม่ส่งเลข Rev/hash เนื้อหาที่เห็น
- `CDP:150-160` — ใบเสนอราคาที่มี `DueDate`: ช่วงตอบรับ = ถึงวันยืนราคา ไม่ดูวันส่งลิงก์เลย

สถานการณ์: ลูกค้าเปิดหน้ายอมรับ (เห็น Rev 0 ราคา 100,000) → ผู้ขายแก้เป็น Rev 1 ราคา 130,000 → ลูกค้ากด "ยอมรับ" บนหน้าที่ค้างอยู่ →
`Accept` โหลดใบปัจจุบัน คำนวณ `contentHash` ของ Rev 1 แล้วบันทึก "ยอมรับ Rev 1" พร้อมหลักฐาน ม.9 — ลูกค้าไม่เคยเห็นฉบับนั้น ·
ก่อนรอบ 267 กรณีนี้ตอบ 404 (token ถูกล้างตอนออก Rev) · ใบส่งของเหมือนกัน (เซ็นรับได้ต่อภายใน 14 วันหลัง Rev)
ไม่มีเทสต์ครอบ (`CustomerDocPageRound267DbTests` ไม่มีเคส revision)

แก้ขั้นต่ำ: (ก) เส้น revision ตั้ง `SignLinkIssuedAt = null` (ต้องส่งใหม่ถึงจะตอบรับได้) (ข) `Accept`/`SignDelivery` รับ `revisionNumber` (หรือ content hash) ที่หน้าแสดง
แล้วใส่ `d.RevisionNumber == seen` ในเงื่อนไขจอง — ไม่ตรง = 409 "เอกสารถูกแก้ไข กรุณาเปิดดูใหม่" (ค) เทสต์สองทิศ (Rev ใหม่ = ยอมรับไม่ได้จนส่งใหม่ · ไม่มี Rev = ยอมรับได้ตามเดิม)

### H2 — ไม่มีทางเพิกถอนลิงก์ของใบที่ "จ่ายไม่ได้" จากหน้าจอ และ "ออกลิงก์ใหม่" ไม่เพิกถอนลิงก์เดิมอีกแล้ว
- `SignRequestKinds.cs:93-100` (`MarkIssued`) — ไม่หมุน token (267-1-20) · คอมเมนต์ชี้ไปที่ "ปุ่มเพิกถอนลิงก์ของใบ"
- `documents.html:13812-13825` — ปุ่ม "ยกเลิกลิงก์" วาดเฉพาะกิ่ง `!s.refusal` · `StatusAsync` (`PLS:423`) คืน `Refusal` ของ**ชั้นจ่าย** ⇒ ใบเสนอราคา · ใบส่งของ · ใบเสร็จ ·
  ใบแจ้งหนี้ชำระครบ/ออกใบกำกับแล้ว/ยกเลิก = มีแต่ข้อความปฏิเสธ ไม่มีปุ่ม (เส้น API `pay-link/revoke` ยังมี แต่ไม่มีทางกดถึง)
- `DocumentsV1Controller.cs:352` — doc ของ `regenerate` ยังเขียนว่า "ออก token ใหม่ (ลิงก์เดิมเพิกถอน)"

สถานการณ์: ส่งลิงก์ใบเสนอราคาผิดอีเมล → พนักงานกด "ออกลิงก์ใหม่" (เดิม = ลิงก์เก่าตายทันที) → ตอนนี้ได้ URL เดิม · ผู้รับผิดคนยังเปิดดูได้ 400 วัน
ดาวน์โหลด PDF + ใบที่เกี่ยวข้อง และ**กดยอมรับแทนลูกค้าได้จนถึงวันยืนราคา** — ไม่มีปุ่มใดบนหน้าพนักงานปิดได้

แก้ขั้นต่ำ: แผงลิงก์บน documents.html แสดงปุ่มเพิกถอนเมื่อ "ลิงก์ระดับหน้ายังใช้ได้" (ใช้ `CustomerDocPage.StateOf` ไม่ใช่ `Refusal` ชั้นจ่าย — เพิ่มช่องใน `StatusAsync`) ·
`Regenerate` ของเส้นลิงก์เซ็น = หมุน token จริง (หรือเปลี่ยนชื่อปุ่ม/ข้อความ + แก้ doc API v1 ให้ตรง แล้วเพิ่ม `revoke` ใน v1)

## ตรวจแล้วไม่พบปัญหา (ไม่ต้องรายงานซ้ำ)

- **IDOR ทาง `relId`** — ต้องอยู่ในชุดที่หน้าแสดง: บริษัทเดียวกัน + ผู้ติดต่อเดียวกัน + ไม่ถูกลบ + ยังมีผล + ลูกค้าเห็นได้ (`PLS.CP:191-207, 263-271`) · ข้ามบริษัท/ผู้ติดต่อไม่ได้ · ใบสั่งซื้อไม่มีชุดที่เกี่ยวข้อง
- **ข้าม tenant** — ทุก query กรอง `CompanyId` · PDF เรนเดอร์ด้วย `companyId` ของ route
- **token** — 256 บิต · ฐานเก็บ hash · ยืนยันซ้ำ `FixedTimeEquals` (`DocumentPayLinkPolicy.cs:263-268`) · ลิงก์รุ่นก่อนค้นด้วย hash (varchar(80) พอสำหรับ `h1:`+64)
- **เส้นจ่าย/สลิปของใบที่จ่ายไม่ได้** — ใบค่าบริการผู้เช่า · ใบกำกับอ้างแล้ว · ยกเลิก · ชำระครบ · ชนิดอื่น: ปิดทั้ง intent และสลิป (ยกเว้นข้อ M3)
- **ร่าง/รออนุมัติ/ถูกลบ/คืนเป็นร่าง** — ออกลิงก์ไม่ได้และเปิดไม่ได้ (`CDP:122-123`, `PLS:148`) · หมายเหตุภายในไม่อยู่ใน view model/PDF
- **กลุ่ม LINE ซ่อนยอด** — เปิดหน้าไม่ได้ (`LineDocumentViewController.cs:66`) และไม่ได้ลิงก์ชำระ (`DocumentLineSendService.cs:62`)
- **พรีวิว** ต้องล็อกอิน + ปุ่มปิดหมด · **พอร์ทัล** ตรวจเจ้าของใบด้วย `GetDocumentAsync` ก่อน · **innerHTML** ทุกค่าผ่าน `esc`
