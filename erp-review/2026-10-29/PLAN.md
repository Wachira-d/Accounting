## คำตัดสิน (ข้อ 168) — หลัก: ค่าเริ่มต้น = พฤติกรรมเดิม · ทิศปลอดภัยทางภาษี/PDPA

| # | ประเด็น | ตัดสิน |
| --- | --- | --- |
| ก | สวิตช์ฟีเจอร์ต่อไซต์ | ตัวตัดสินกลางตัวเดียว `Helpers/CmsFeatureFlags` อ่านคอลัมน์เดิมของ `SiteCommerceConfig` (+ คอลัมน์ใหม่เท่าที่จำเป็น) · ค่าเริ่มต้นทุกตัว = พฤติกรรมปัจจุบัน · ฟิลด์ที่ไม่ควรปิดได้ (`AutoSyncToErp` — บัญชีต้องลงเสมอ · `AutoDeductStock`) **ไม่เปิดเป็นสวิตช์** — ซ่อนจาก UI + ระบุเหตุผลใน resolver |
| ข | หน้าสถานะออเดอร์ของแขก | โทเคนสุ่มต่อออเดอร์ (`SiteOrder.PublicToken` แบบ `SiteBooking.PublicToken`) · DTO จำกัดฟิลด์ (ไม่มีหมายเหตุภายใน/ต้นทุน) |
| ค | COD | ทำเป็นวิธีชำระ "เก็บเงินปลายทาง" ค่าเริ่มต้นปิด · ออเดอร์ COD = ยังไม่ชำระ · ชำระเมื่อพนักงานบันทึกรับเงิน (ปุ่มบันทึกรับเงินหน้าร้าน/ปลายทาง) · ใบกำกับตามเส้นเดิมตอนรับเงิน/ส่งมอบ |
| ง | ฟอร์มสั่งซื้อ | `Helpers/OrderFormFields` แบบเดียวกับ `BookingFormFields` (บังคับ/ไม่บังคับ/ซ่อน + ช่องเพิ่มเอง) · **ตรวจที่เซิร์ฟเวอร์** · ขั้นต่ำบังคับเสมอ: ชื่อ + (เบอร์ หรือ อีเมล) · ไม่ตั้ง = ฟอร์มเดิม |
| จ | วันรับที่ลูกค้าเลือก | `RequestedReadyDate` ≥ `EarliestReadyDate` และไม่ใช่วันปิดร้าน (ตัวตัดสิน `MtoLeadTime`) · ไม่เลือก = เดิม |
| ฉ | คืนค่าส่งเมื่อยกเลิกหลังส่งแล้ว | ไม่คืนอัตโนมัติหลังสถานะ "จัดส่งแล้ว" (ใบลดหนี้ร่างไม่รวมบรรทัดค่าส่ง) · ก่อนส่ง = คืนเต็มเดิม |
| ช | อีเมลกู้ตะกร้า | ต้อง `EnableAbandonedCartRecovery` **และ** ลูกค้ายินยอมการตลาด (`AcceptMarketing`) — PDPA ม.19/24 |
| ซ | แจ้งเตือน | ช่องทางเดิม (`IBookingNotifier`: อีเมล → LINE) · ร้าน: ออเดอร์ใหม่/สลิปเข้า/การจองใหม่/lead ใหม่ · ลูกค้า: ยืนยันออเดอร์/การจอง · จัดส่งแล้ว(+เลขพัสดุ) · พร้อมรับ · คลาสยกเลิก · ล้ม = ไม่ล้มคำสั่ง แต่ประทับบนรายการ (ไม่เงียบ) |
| ฌ | คลาสเรียน | ต่อยอดเครื่องจอง CMS (ไม่สร้างเครื่องที่สอง): `SiteClassTerm` (ตารางซ้ำรายสัปดาห์ + ช่วงเทอม) ⇒ `SiteClassSession` (รอบจริง · ครู · ยกเลิก · หมายเหตุ) · คีย์ = บริการ + เวลาเริ่ม (ตรงกับที่ engine นับ "รอบเดียวกัน") |
| ญ | นโยบายยกเลิกสายของบัตร | กติกาของแพ็กเกจชนะเมื่อจองด้วยบัตร · หน้าเว็บแสดงกติกาของบัตรเมื่อใช้บัตร |
| ฎ | สมาชิกไม่จำกัด | รับรู้รายได้เส้นตรงรายวัน · freeze เลื่อนวันหมดอายุ (ไม่รับรู้ช่วงพัก) · ขยายอายุ = บันทึก + audit (ไม่มีเงิน) · โอน = ปิดบัตรเดิม/เปิดบัตรใหม่ยอดเท่าเดิม |
| ฏ | ค่าตอบแทนครู | `SiteBookingResource.EmployeeId` + กติกาต่อรอบ/ต่อหัว ⇒ ฐานคอมมิชชัน (ทางเดียวกับคอมมิชชัน POS) · การจองที่ปิดนอก POS นับด้วย (D8) |
| ฐ | สาขาของเว็บ | `Document.BranchId = Site.BranchId` บนเอกสารของออเดอร์/การจอง (ภาษีขายรายสาขา) · ไม่ตั้ง = สำนักงานใหญ่เดิม |
| ฑ | PDPA | checkbox ยินยอม + ลิงก์นโยบายบนฟอร์มเช็กเอาต์/จอง/lead ⇒ `ConsentRecord` · DSR ครอบ `SiteCustomer/SiteOrder/SiteBooking/CmsLead` (ลบ = anonymize ยกเว้นที่กฎหมายบัญชีถือ) · QR PromptPay สร้างฝั่งเซิร์ฟเวอร์ (เลิกส่งเลข/ยอดไป api.qrserver.com) |
