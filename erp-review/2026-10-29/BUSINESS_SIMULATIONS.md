## §6 ประเด็นข้ามธุรกิจ

### 6.1 Onboarding — ต้องเปิดกี่หน้าถึงขายได้
เบเกอรี่ (เส้นสั้นสุด): ① สินค้า ERP (สร้างสินค้า/VAT) → ② `cms-sites` สร้างเว็บ → ③ `cms-edit` หน้า/บล็อกสินค้า + เผยแพร่ + lead time → ④ `pos-modifiers` ตัวเลือก + ผูกสินค้า →
⑤ `cms-orders` ⚙️ วิธีรับเงิน → ⑥ `cms-orders` ⚙️ การรับสินค้า/มัดจำ → ⑦ ตั้งค่าบริษัท (วันหยุด · VAT) = **7 หน้า · 3 เมนูหลัก** ·
ซาลอน: `cms-edit`(บริการ) → `cms-booking-providers` → ตั้งค่าเวลาไซต์ → วิธีรับเงิน → POS (สินค้า/พนักงาน) → แผนคอม = 6+ หน้า ·
**ไม่มี checklist ความพร้อมขาย** — `getting-started.html`/`js/onboarding.js` ไม่กล่าวถึงเว็บ/ร้านออนไลน์/จองคิวเลย (grep cms|เว็บไซต์|ร้านออนไลน์ = 0) · ร้านเปิดเว็บได้ทั้งที่ยังไม่ตั้งวิธีรับเงิน (หน้าออเดอร์ขึ้นกล่องเหลือง "ติดต่อร้าน" แทน)

มี `viewport` + `@media` สำหรับส่วนที่พัก/แกลเลอรี (`storefront.html:26,125-172`) · ฟอร์มเช็กเอาต์/ตัวเลือก/ตารางเวลาจองเป็น inline style + `flex-wrap` ส่วนใหญ่ ⇒ น่าจะใช้ได้ แต่ไม่มีการทดสอบจอจริง (ไม่ได้รันแอป) · จุดเสี่ยง: QR 220px + ฟอร์มสลิปในกรอบ 780px

### 6.5 PDPA
ไม่พบ checkbox ความยินยอม/ลิงก์นโยบายในฟอร์มเช็กเอาต์ · จอง · ส่ง lead (grep `consent|pdpa` ใน `storefront.html` = 0) ทั้งที่เก็บชื่อ/โทร/ที่อยู่/รูป ·
`CMS_FEATURE_ROADMAP.md §3` บอก "cookie consent ✅" แต่ไม่พบใน `storefront.html` (ให้ทีม D ยืนยันว่าฉีดจากฝั่ง rendering หรือไม่) · `UpdateConsentAsync`/`ProcessDataDeletionAsync` มี API แต่ไม่มีทางเข้าของเจ้าของข้อมูล ·
QR พร้อมเพย์ส่ง id+ยอดไป `api.qrserver.com` (`storefront.html:1444`) = ส่งข้อมูลให้บุคคลที่สามโดยไม่จำเป็น (สร้าง QR ในเครื่องได้ — payload สร้างในเครื่องอยู่แล้ว)

### 6.6 หลายสาขา
เว็บผูก `Site.BranchId` ได้ แต่ใบขายจากออเดอร์แค่ประทับข้อความ `InternalNotes = "Branch: {guid}"` — **ไม่ตั้ง `Document.BranchId`** ⇒ เลขเอกสาร/รายงานภาษีขายรายสาขา (§86/4 รหัสสาขา) ไม่ตามเว็บ ·

## §8 คำตัดสินเจ้าของ (ต้องถามก่อนทำ)

1. **บัญชีลูกค้า (E1)**: บังคับล็อกอินเฉพาะ "จองด้วยบัตร/ดูประวัติ" แล้ว guest checkout คงเดิม — หรือให้ร้านเลือก (`RequireCustomerAccount`)? ใช้ OTP อีเมล/LINE Login แทนรหัสผ่านไหม?
2. **Variant (E5)**: ลงทุนทำ variant จริง (สต็อกต่อไซซ์/สี) หรือประกาศว่า "ตัวเลือก = modifier · สต็อกแยก = สินค้าแยก" แล้วซ่อนแท็บ Variants?
3. **COD (E7)**: เปิดรับ COD ไหม — ถ้าเปิด ใบขายออกตอนจัดส่ง (§78(1) ส่งมอบ) และรับเงินเมื่อผู้ขนส่งโอนคืน (ต้องมีเส้นกระทบยอดผู้ขนส่ง)
4. **วันรับที่ลูกค้าเลือก (E6)**: จำกัดจำนวนออเดอร์ต่อวันรับ (กำลังผลิต) ด้วยไหม — ถ้าใช่ ใช้ engine ความจุของระบบจองตัวเดิม?
5. **ระบบคลาสสองชุด (E10)**: ยุบ `CreditClassSession` เข้า booking engine (มี waitlist/เวลาทำการ/หน้าเว็บ) หรือคงสองชุด? (ทีม C ให้ข้อมูลประกอบ)
6. **มัดจำการจอง × POS (E9)**: ยอมให้ POS "ตัดมัดจำ" (แตะ JE ขายของ POS) หรือคงกติกา "ปิดงานที่หน้าการจองเท่านั้น"?
7. **แจ้งเตือน (E2)**: ช่องเริ่มต้น LINE OA ของร้าน หรืออีเมล? ข้อความยืนยันออเดอร์/นัดพิมพ์ยอด+ลิงก์จ่ายเงินได้ไหม (ลิงก์ token = capability URL)

> หมายเหตุวิธีตรวจ: ไม่ได้รันแอป (ไม่มี SDK/DB) — ทุกผลจากการอ่านโค้ด · ข้อที่ระบุ "ทีม D ตรวจ" คือจุดที่ต้องรู้พฤติกรรม runtime ของเส้น ERP (void ถอยสต็อก · แผนคอมอ่านส่วนแบ่งการจอง · VAT สินค้าของบริษัทไม่จด)
