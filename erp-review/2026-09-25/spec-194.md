# รอบ 194 — สเปกที่ main agent ตัดสินแล้ว (ทุกชุดงานต้องทำตาม)

อ้างอิง: `plan-deposit-kind.md` (แผนที่ file:line) · `legal-L1-forfeit.md` · `legal-L2-classification.md`
คำสั่งเจ้าของ: (1) ตั้งทีมวิเคราะห์ว่าต้องคิด VAT ไหม (2) integration แบบเดิมใช้ได้ — เปลี่ยนถ้าดีขึ้น ·
คำตัดสินเดิม #34: "ต้องตั้งค่าได้ทั้งหมด" ⇒ **ไม่ปิดตัวเลือกโหมด** แต่ผูกคำเตือน/เหตุผล/ด่านตาม "ลักษณะเงิน"

## S1. แกน — ลักษณะเงิน (ใหม่) กำหนด VAT · โหมดเป็นแค่วิธีบันทึก
`enum DepositNature { PartOfPrice = 1, RefundableSecurity = 2, NonVatSupply = 3 }` (persist — เลขคงที่)
- **PartOfPrice** มัดจำ/เงินจอง/ชำระล่วงหน้าที่เป็นส่วนหนึ่งของราคา (สินค้า §78(1)(ข) · บริการ §78/1 · ป.73/2541) ⇒ ภาษีถึงกำหนดตอนรับเงิน
- **RefundableSecurity** เงินประกันที่ต้องคืน (ความเสียหาย/กุญแจ/ภาชนะ/ประกันการปฏิบัติตามสัญญา) ⇒ ไม่ใช่ tax point
- **NonVatSupply** สิ่งที่ขายไม่อยู่ในระบบ VAT (ค่าเช่าอสังหาฯ §81(1)(ต) · ขายอสังหาฯ ที่เสียภาษีธุรกิจเฉพาะ §81(1)(น) · สินค้า/บริการยกเว้นอื่นตาม §81) ⇒ VAT 0 เสมอ
- ใบเดิม (`Document.DepositNature` = NULL) = **ไม่ทราบ** — ห้าม backfill · ตัวอ่านที่ต้องใช้ลักษณะ (ริบ) ต้องให้ผู้ใช้เลือก โดยค่าเริ่มต้น = ทิศปลอดภัย (คิด VAT)

## S2. ด่าน (ระดับตามผลกฎหมาย L2 + คำตัดสิน #34)
| ลักษณะ × โหมด | ด่าน | รหัสกฎ |
|---|---|---|
| PartOfPrice × VatImmediate | ผ่าน | — |
| PartOfPrice × FullDeposit/VatPendingUndue | **อนุญาตแต่บังคับเหตุผล** (`PolicyReason` ตอนบันทึกประเภท — ว่าง = ปฏิเสธ) + คำเตือนแรง **ทั้งสินค้าและบริการ** (เดิมสินค้าเป็น ℹ️ — แก้) ที่หน้าตั้งค่า · หมายเหตุบนใบ · คำเตือนตอนอนุมัติ | `RD-78/1` บริการ · `RD-78(1)(b)` สินค้า |
| RefundableSecurity × FullDeposit | ผ่าน (ค่าแนะนำ) | — |
| RefundableSecurity × VatImmediate/VatPendingUndue | เตือน (ออกใบกำกับก่อนเกิด tax point) | `RD-PO73-SEC` |
| NonVatSupply × ใด ๆ | รูปใบบังคับ VAT 0 (+ deferred=true แบบ FullDeposit) · ถ้า client ส่งบรรทัด VAT>0 มากับประเภท NonVat ⇒ เซิร์ฟเวอร์ตั้ง 0 และบันทึกหมายเหตุ | `RD-81` |
| RefundableSecurity ถูกหักเป็นฐาน (`DepositBaseDeducted`)/หักเป็นราคาในเส้นขับ JE | **บล็อก** พร้อมทางไปต่อ ("ตัดชำระด้วยเงินประกัน" = ApplyDeposit เป็นการรับชำระหนี้ ไม่ลดฐานภาษี) | `DEP-SEC-DEDUCT` |

## S3. ริบ/หัก — VAT ตามลักษณะเงิน ไม่ใช่ตามโหมด (แก้ C-2/C-3 ของ L1)
- **PartOfPrice ที่ออกใบกำกับ+VAT แล้ว** ริบ ⇒ VAT คงเดิม (เสียไปแล้วเดือนที่รับ) ไม่ออกใบลดหนี้ — พฤติกรรมเดิม
- **PartOfPrice ที่ยังไม่เคยเสีย VAT** (FullDeposit/Undue ที่ยังไม่รับรู้) ริบ ⇒ ต้องเกิดภาษีขายพร้อม**ใบกำกับจริง** (ไม่ใช่แค่ขา JE):
  Undue = ย้าย 21913→21911 (มีอยู่แล้ว — ยืนยัน) · Full = **ห้ามลงรายได้ไม่มี VAT เงียบ ๆ** — สร้างใบกำกับภาษีของยอดที่ริบ (VAT-inclusive
  แยก 7/107 ตามอัตราบริษัท · บริษัทไม่จด VAT ⇒ 0) แล้วตัดชำระด้วยมัดจำผ่านเส้นเดิม `ApplyDepositToInvoiceCoreAsync` · ทั้งสองกรณีติดธง
  `[DEPOSIT-LATE-VAT]` บนใบ: "ภาษีถึงกำหนดตั้งแต่เดือนที่รับเงิน (dd/MM/yyyy) — ต้องยื่น ภ.พ.30 เพิ่มเติมของเดือนนั้น" (มองเห็น ไม่เงียบ)
- **RefundableSecurity** มี 3 ทาง: คืน (เส้นเดิม) · ตัดชำระใบแจ้งหนี้ค่าของที่เสีย/ใช้ไป (ใบนั้นคิด VAT ตามปกติ — เส้นเดิม ApplyDeposit) ·
  **ริบเป็นค่าเสียหาย** = รายได้อื่นไม่มี VAT ไปบัญชี `ForfeitAccountCode` (ความมั่นใจกฎหมายกลาง-ต่ำ ⇒ UI ต้องบอกว่า "ถ้าเป็นค่าของที่ใช้ไป/ค่าบริการ/ค่าธรรมเนียมยกเลิก ให้เลือกแบบมี VAT")
- **ใบเดิม Nature=NULL** ริบ ⇒ request ต้องระบุ `ForfeitAs` (`PriceOrFee` | `Compensation`) · ไม่ระบุ ⇒ `PriceOrFee` (ทิศปลอดภัย: จ่ายเกินมองเห็นและแก้ได้ · จ่ายขาดโดนเงินเพิ่ม 1.5%/เดือน)
- คืนมัดจำที่เสีย VAT แล้ว ⇒ ใบลดหนี้ §86/10 — **มีอยู่แล้ว** (`RefundDepositAsync` ออก CN) ห้ามถอด

## S4. ลำดับตัดสินประเภท (ผ่าน `DepositPolicyResolver` ตัวเดียว)
ประเภทที่เลือกบนใบ → ประเภทของช่องทาง (ที่พัก/หน้าจอง) → ค่าเดิมของช่องทาง (`LodgingProperty.DepositVatTreatment`) → ประเภทเริ่มต้นบริษัท →
`CompanySettings.DepositVatTreatment` → ประเภทธุรกิจ · **payload ที่ไม่ระบุประเภท (คู่ค้า/OCR/ฟอร์มเก่า) ⇒ ไม่แตะรูปใบเลย** (พฤติกรรมเดิมทุกตัวอักษร)
- `NatureOf(RealEstate)` เดิม = Service ⇒ แก้เป็น `Unknown` (อาจเป็นให้เช่ายกเว้น/ขาย SBT/นายหน้า) — ต้องให้เจ้าของเลือก

## S5. integration (เจ้าของ: "แบบเดิมก็ได้ ถ้าเปลี่ยนแล้วดีขึ้นก็เปลี่ยน")
payload เดิมทำงานเหมือนเดิมทุกกรณี · เพิ่มฟิลด์เสริม `DepositKindCode` (ไม่รู้จัก ⇒ 400 ข้อความไทย ไม่ตกเงียบ) · หมายเหตุ mismatch เดิมคงไว้แต่คำนวณผ่าน `ResolveKind`

## S8. seed ต่อประเภทธุรกิจ (tenant ใหม่ห้ามว่าง — กฎเหล็ก #1 ข้อ 3 ทำนองเดียวกัน)
