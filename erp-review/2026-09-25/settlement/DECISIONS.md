# รอบ 198 — คำตัดสินเจ้าของ (2026-09-25 ผ่าน AskUserQuestion)

1. **รายได้ marketplace** = ยอดเต็ม (gross) + ค่าธรรมเนียม/ค่าคอมเป็นค่าใช้จ่าย (ตัวการ · TFRS NPAEs) ✅
2. **ใบกำกับขายของออเดอร์ marketplace** = สรุปยอดขายรายวันต่อแพลตฟอร์ม (1 เอกสาร/วัน/แพลตฟอร์ม ลงรายงานภาษีขายทัน 3 วันทำการ) · ออกใบเต็มรูปรายออเดอร์เฉพาะลูกค้าที่ขอ ✅
3. **บรรทัดขายใน settlement ที่จับคู่ใบขายไม่ได้** = สร้างเอกสารขายสรุปให้อัตโนมัติ + ติดป้ายให้ตรวจ ✅
4. **บัญชีพัก wallet** = ผังย่อยแยกต่อแพลตฟอร์ม 11341–11349 ✅

ค่าเริ่มต้นที่ main agent ใช้ระหว่างรอคำตัดสินข้ออื่น (report-S1 D2–D11 · report-S2 §5 ข้อ 4–11) — ทุกข้อ **ตั้งค่าได้ต่อช่องทาง** และไม่ทำอะไรที่ย้อนไม่ได้:
- tax point marketplace = วันส่งมอบ (D2) · OTA ยังไม่ทำในเฟส 1 (เฟส 4)
- WHT ค่าธรรมเนียม ค่าเริ่มต้น None + เตือนบริษัทนิติบุคคล (D5) · ผังค่าธรรมเนียมรับชำระ 53170 (สร้างเมื่อผูกช่องทาง · ไม่ย้ายย้อนหลัง) (D6) · chargeback แพ้ 57140 (D8)
- adapter เฉพาะเจ้าเขียนเมื่อมีไฟล์จริงเท่านั้น (ข้อ 9) · เฟส 1 ใช้ GenericColumnMapAdapter (ผู้ใช้จับคู่คอลัมน์ · ระบบจำ)
- migration ซ่อม JE เก่า I-1/P-1 = ไม่ทำจนกว่าเจ้าของอนุมัติ (ข้อ 11)

## คำตัดสินเจ้าของรอบสอง (2026-09-28 ผ่าน AskUserQuestion)
5. **gate แพ็กเกจ/ระงับบริษัทบนหน้าเว็บ** (SubscriptionMiddleware ข้ามคำขอที่ไม่มี `X-Company-Id` · api.js ไม่ส่ง) = **ทำรายงานก่อน แล้วค่อยเปิดบังคับ**:
   เปิดโหมดเงา (ตัดสินแต่ไม่บล็อก + บันทึก) + รายงานแอดมินว่าบริษัทไหนจะถูกบล็อกเพราะอะไร → เจ้าของตรวจ → เปิดสวิตช์บังคับเอง ✅
6. **API v1 อนุมัติใบสแกนที่ VAT ไม่ได้พิมพ์บนกระดาษ** (`[VAT-DERIVED]`/ไม่มีข้อความให้ตรวจ) = **ปฏิเสธผ่าน API** พร้อมเหตุผล · ให้คนยืนยันคำเตือนบนเว็บเหมือนเว็บ/มือถือ ✅
7. **ผู้อนุมัติใบค่าธรรมเนียมที่ออกอัตโนมัติตอนลงบัญชีรอบโอน** = **บันทึกชื่อผู้ที่กดลงบัญชี** (ไม่ใช่ system) ✅
8. **VAT ค่าธรรมเนียมค้าง 11630 เกิน 6 เดือน** = **เตือนอย่างเดียว** (นักบัญชีตัดสินและลงรายการเอง) — ไม่ตัดเป็นค่าใช้จ่ายอัตโนมัติ ✅
