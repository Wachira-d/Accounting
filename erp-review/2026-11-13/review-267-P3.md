## สรุป

ไม่พบ HIGH · พบ MED 3 ข้อ · LOW 9 ข้อ · ตรวจแล้วไม่ใช่บั๊ก 7 ข้อ (อยู่ท้ายรายงาน)

คำถามทั้ง 7 ข้อที่สั่งมา ตอบสั้น ๆ:
1. **`s` ปลอม/ใช้ซ้ำ** — ปิดได้ครบ: ตรวจบริษัท + ใบเดียวกัน + ปลายทาง 1:1 + การ์ดที่มีลิงก์หน้าเอกสาร + สถานะ Sent ทั้งตอนตอบรับและตอนเข้าคิว · Id เป็น `Guid.NewGuid()` (สุ่ม ไม่ใช่ sequential) ·
   ปลายทางถูกตรวจซ้ำตอนส่งจริง (ยกเลิกผูก/บล็อก/ถอนเรื่อง ⇒ ข้าม) ⇒ ฉบับเซ็นไปได้แค่ผู้รับที่ผู้ขายส่งใบนี้ให้เองแล้ว (เหลือ LOW-1 ส่วนเรื่องถ้อยคำ)
2. **กลุ่มที่ซ่อนยอด** — ไม่พบทางรั่วทาง LINE (ตรวจซ้ำตอนส่ง · ลิงก์ดู PDF และปุ่มชำระปิด · ฉบับเซ็นส่งได้เฉพาะ 1:1) · ไทม์ไลน์และพรีวิวเป็นหน้าของพนักงาน · อีเมลไม่ผูกกับกลุ่ม
3. **ด่าน 4 endpoint** — share-options และ share ใช้ด่านเดียวกับ send-email/line-send (`DenyDocAsync Create` + `DenySensitiveAsync`) · API key ผ่าน `ApiKeyScopeFilter` (GET = อ่าน · POST = เขียน) แล้วสิทธิ์ของผู้สร้างคีย์ ·
   customer-timeline ใช้ด่านอ่าน (ชั้นความลับ) · ทุก query ผูก CompanyId
4. **อีเมลล้มไม่ลาก LINE** — จริงในทางปกติ (เทสต์ Db ล็อกไว้) · เหลือ LOW-3 (DbContext ใช้ร่วมกัน) · ไม่พบเคสที่ส่งไม่สำเร็จแล้วขึ้นว่า "ส่งแล้ว" (LINE = queued) · มีเคสกลับด้าน "ส่งไปแล้วแต่ขึ้นว่าล้ม" (LOW-3)
5. **JS** — ไม่มีตารางชนิดหรือป้ายที่ควรอยู่ฝั่งเซิร์ฟเวอร์ (มีแค่ map สีของรหัสสถานะ) · escape ครบ · baseline ที่ลดจาก 385 เป็น 381 ยืนยันได้ (ดูหัวข้อ "ตรวจแล้ว") · เหลือ MED-2 (ช่องติ๊กที่ไม่มีผล) และ LOW-6
6. **migration รอบ 259** — ถูกต้อง: กลุ่มตัด Sign/Other · 1:1 ตัดแค่ Other · ค่าลิงก์เซ็นของ 1:1 ที่เคยถูกตัดไปแล้วไม่ถูกเติมกลับ (ตรงคำตัดสิน 267-1-61) · เหลือ LOW-7 (ช่วง rolling deploy)
7. **endpoint เดิม** — send-email รับ `IncludePageLink` ใหม่ แต่เดินผ่าน `ManualPageBlockAsync` → `EnsureCustomerLinkAsync` ตัวเดียวกัน (ไม่ออกลิงก์ใหม่ทับลิงก์ที่ถูกยกเลิก) ·
   line-send ไม่เปิด `includePageLink` ⇒ ไม่มีทางอ้อม `PageLinkAllowed` · แต่การถอดปุ่มเดิมออกจากหน้าเว็บทำให้เอกสารบางชนิดส่งทาง LINE จากหน้าเว็บไม่ได้อีก (MED-3)

## MED

### MED-1 — ป้ายปุ่มบนการ์ด LINE "ดู/ยอมรับ" / "ดู/เซ็นรับ" ไม่ดูว่าช่วงตอบรับเปิดอยู่หรือไม่ (ฝั่งอีเมลดู · สองฝั่งไม่ตรงกัน)

- `ContactLineQueueService.cs:531` ส่งแค่ type และ outstanding เข้าไป ไม่ได้ส่งสถานะช่วงตอบรับ
- ฝั่งอีเมล `CustomerShareRule.EmailPageButton(en, type, respondOpen, outstanding)` (`CustomerShareRule.cs:117-122`) ดู `respondOpen` ผ่าน
  `SignRequestKinds.LinkUsable` (`DocumentEmailService.ManualPageBlockAsync`) · ผิดหลัก F2 ข้อ 1 (คู่สมมาตรสองฝั่ง) และ F2 ข้อ 7 (ข้อความต้องตรงกับสิ่งที่เกิดจริง)
- **สถานการณ์ที่พัง:** พนักงานส่งใบเสนอราคาให้ลูกค้าทาง LINE 1:1 โดยไม่ติ๊ก "เปิดให้ลูกค้ายอมรับ" (ค่าตั้งต้น = ดูอย่างเดียว ตาม 267-1-25) หรือส่งซ้ำหลังลูกค้ายอมรับไปแล้ว ·
  การ์ดขึ้นปุ่ม "ดู/ยอมรับ" ลูกค้ากดเข้าไปไม่เจอปุ่มยอมรับ แล้วโทรมาถาม · ใบส่งของที่เซ็นรับไปแล้วก็ยังขึ้น "ดู/เซ็นรับ"
- **ทางแก้:** ให้ `PageButtonLabel` รับ `respondOpen` (และสถานะว่าตอบแล้ว) จากตัวเดียวกับที่อีเมลใช้ · คำนวณใน `BuildCardAsync` ตอนส่ง ไม่ใช่ตอนเข้าคิว ·

### MED-2 — ช่อง "ใส่ปุ่มชำระเงินบนการ์ด" ในหน้าต่าง "ส่งให้ลูกค้า" ติ๊กแล้วไม่มีผล แต่ทำให้การ์ดถูกข้ามหรือถูกปฏิเสธได้ (silent no-op · กฎเหล็ก #4 §A)
- หน้าต่างแสดงช่องนี้ตาม `N.payLinkOffered` (`documents.html:12320`) และส่งค่า `linePayLink` (`:12345`)
- `CustomerShareService.SendLineAsync` เรียก `SendAsync(..., includePageLink: true)` เสมอ (`CustomerShareService.cs:205`)
- ปลายทางที่ได้ลิงก์หน้าเอกสาร (1:1 ทุกตัว · กลุ่มที่ไม่ซ่อนยอดของใบแจ้งหนี้/ใบกำกับ) ⇒ `BuildCardAsync` ตัดปุ่มชำระทิ้งเมื่อ `pageUrl != null` (`ContactLineQueueService.cs:522`)
- ปลายทางที่ไม่ได้ลิงก์หน้าเอกสาร = กลุ่มซ่อนยอด (ปุ่มชำระก็ไม่ได้อยู่แล้ว) หรือกลุ่มของใบเสนอราคา/ใบส่งของ (ไม่มียอดให้จ่าย) ⇒ ในเส้นนี้ปุ่มชำระไม่ขึ้นบนการ์ดใดเลย
- แต่ค่านี้ยังมีผลข้างเคียงสามอย่าง:
  1. `SendAsync` ออกลิงก์ชำระด้วย `EnsureLinkAsync` (`DocumentLineSendService.cs:~83`)
  2. ผู้ส่งคิวข้ามแถวด้วย `PayLinkGoneAtSend` เมื่อลิงก์ชำระใช้ไม่ได้แล้ว (`ContactLineQueueService.cs:362`) ทั้งที่การ์ดนั้นไม่มีปุ่มชำระ
  3. ถ้าเลือกกลุ่มซ่อนยอดไว้ด้วย `PayLinkProblem` จะปฏิเสธช่องทาง LINE ทั้งช่อง รวม 1:1 ที่ส่งได้
- **สถานการณ์ที่พัง:** พนักงานติ๊ก LINE 1:1 + กลุ่มบัญชี (ซ่อนยอด) + "ใส่ปุ่มชำระเงิน" ⇒ ช่องทาง LINE ล้มทั้งช่องด้วยเหตุ "ปุ่มชำระไม่เข้ากลุ่มซ่อนยอด" ·
  ถ้าไม่ได้เลือกกลุ่ม การ์ด 1:1 ก็ไม่มีปุ่มชำระที่ติ๊กไว้ (ต้องกดผ่านหน้าเอกสาร) · ถ้าลิงก์ชำระถูกเพิกถอนระหว่างรอส่ง การ์ดถูกข้ามด้วยเหตุเรื่องลิงก์ชำระ
- **ทางแก้:** ถอดช่องนี้ออกจากหน้าต่างและ `CustomerShareRequest` (เพราะหน้าเอกสารมีปุ่มจ่ายอยู่แล้ว) หรือเซิร์ฟเวอร์ปฏิเสธพร้อมเหตุเมื่อ `includePageLink && includePayLink` ·
  ให้ด่านตอนส่ง (`:362`) ข้ามการตรวจลิงก์ชำระเมื่อ `IncludePageLink == true`

### MED-3 — ใบที่ออกลิงก์หน้าเอกสารไม่ได้ ส่งทาง LINE จากหน้าเว็บไม่ได้อีก (ถอดปุ่มเดิมแต่ไม่มีทางไปต่อ · F2 ข้อ 8)

  (ก่อนคอมมิตนี้ส่งได้) · ใบลดหนี้ที่ไม่รู้ฝั่ง: ส่งอีเมลได้ทางลิงก์ที่ซ่อนอยู่เท่านั้น
- **ทางแก้:** (ก) ถ้าลิงก์ออกไม่ได้ ให้ดำเนินช่องทางที่ไม่ต้องใช้ลิงก์ต่อไปด้วย `IncludePageLink=false` แล้วบอกเหตุของแต่ละช่องทาง หรือ (ข) คงปุ่มหรือหน้าต่างเดิม

1. **`s` ทายได้หรือใช้ข้ามใบ** — `LineSourceAsync` (`CustomerDocumentResponseService.cs:~123`) กรอง `CompanyId` + `!IsDeleted` แล้วตรวจ `LineSourceValid`
