1. อ่าน `CLAUDE.md` ส่วน "กฎเหล็ก #4" (defect classes) — ทุก finding ให้ระบุว่าอยู่ใน defect class ไหน (ถ้ามี)
2. อ่าน `SYSTEM_REVIEW_2026-09.md` **§9 (ตรวจแล้วไม่ใช่บั๊ก — ห้ามรายงานซ้ำ)** และ grep ID ที่มีอยู่แล้ว —
   ถ้าเรื่องที่พบมีอยู่ในไฟล์นั้นแล้ว ให้เขียนว่า "ซ้ำกับ <ID>" (ไม่นับเป็น finding ใหม่ แต่บอกว่ายังเปิดอยู่จริงไหม)
3. `git log --oneline -40` ก่อน — 40 คอมมิตล่าสุดแก้ไปเยอะ ห้ามรายงานสิ่งที่แก้แล้ว
4. **ทุก finding ต้องมี file:line + ข้อความโค้ดที่ยกมา (quote) + เหตุผลที่พังเป็นขั้น ๆ + ผลกระทบต่อผู้ใช้/เงิน/ภาษี**
   "สงสัย" ให้เขียนว่าสงสัยและบอกว่าต้องเช็คอะไรต่อ — ห้ามเขียนให้ดูมั่นใจเกินหลักฐาน
5. **"มีคลาสนี้อยู่" ≠ "โค้ดเส้นนี้ถูกเดินจริง"** — ทุกครั้งที่อ้างว่า X ป้องกัน Y ให้ grep call site ของ X ก่อน
6. ห้ามแก้โค้ด (ทีมตรวจอ่านอย่างเดียว) — ยกเว้นเขียนสคริปต์ simulation ลง scratchpad ของตัวเอง
7. ผลตรวจจะถูกทีม "ฝ่ายค้าน" พยายามหักล้างทุกข้อ — เขียนหลักฐานให้พอที่คนอื่นจะเปิดไฟล์แล้วเห็นตามได้
