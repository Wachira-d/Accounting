## สรุป 5 บรรทัด

1. **ด่านอนุมัติเอกสาร (G-01/03/04/05 รอบก่อน) ปิดแล้วจริง** — `CanApproveAsync` มีผู้เรียก 17 จุดครอบ
   เว็บ/LINE/มือถือ/ลายเซ็น/OCR · แต่ **"ใครกำหนดว่าใครอนุมัติได้" ยังไม่มีด่านเลย** (G2-03) และ
   **"ใครออกกุญแจที่ข้ามด่านทั้งหมดได้" ก็ยังไม่มีด่าน** (G2-01) ⇒ ด่านที่ใส่ไว้ถูกเดินอ้อมได้ 2 ทาง
2. **ช่องที่ร้ายที่สุดรอบนี้คือ integration API key**: สมาชิกคนไหนก็ POST ขอคีย์ได้ · คีย์นั้น
   middleware ตั้ง `CanRead/CanWrite/CanDelete = true` ตายตัว · แถมส่ง header `X-Acting-User: <อีเมล Owner>`
   แล้ว `NameIdentifier` กลายเป็น Owner ⇒ **ยกระดับสิทธิ์จาก "ดูอย่างเดียว" เป็น Owner ในบริษัทตัวเอง**
3. **XSS → ขโมย JWT ยังเปิดอยู่จริง** — HTML renderer หนี 51 จุดแต่ **ตก 5 จุดที่เป็นข้อความอิสระ**
   (อ้างอิงเอกสาร · เลขผู้เสียภาษีคู่ค้า · URL โลโก้แบรนด์ · วิธีชำระ/อ้างอิงใบเสร็จ) และปลายทางคือ
   `documents.html:11873 innerHTML` บน origin เดียวกับที่เก็บ token · CSP มี `unsafe-inline` (ทีมเขียนเองว่า
   "CSP ไม่ใช่ชั้นกัน XSS ต้องพึ่ง output encoding")
4. **PDPA: ด่าน mask ถูกทิศแต่ไม่ครบวง** — รายชื่อพนักงาน mask ถูก แต่ (ก) รายงาน ภ.ง.ด.1/ปกส. คืนเลขบัตร
   13 หลัก + เลข ปกส. เต็มโดยไม่ดู `Pii.View` และไม่เขียน `PiiAccessLog` (ข) ฟอร์มแก้ไขพนักงาน hydrate
   ค่า **ที่ถูก mask** แล้วส่งกลับ ⇒ เบอร์/อีเมลจริงของพนักงานถูกทับด้วย `08X-XXX-XX99` ถาวร
5. **multi-instance ผ่าน** (advisory lock deterministic 0 จุด · คิวอีเมล claim ด้วย `FOR UPDATE SKIP LOCKED` ·
   idempotency มี unique index จริง) · **hash chain ของ audit ไม่ผ่าน**: มีตัว verify **สองตัวที่ไม่ตรงกัน**
   ตัวหนึ่งลอก canonical มาเขียนซ้ำ + ไม่กรอง `RowHash != null` ⇒ แถวก่อน migration ถูกฟ้องว่า "ถูกแก้" ทุกแถว

**ลำดับที่แนะนำ**: G2-01 (ปิดทันที — S) → G2-02 (5 จุด หนีให้ครบ + เทสต์) → G2-04 (กันข้อมูลจริงถูกทับ
ทุกนาทีที่ผ่านไป) → G2-03 → G2-05/06/07 → G2-10 (ขยาย WATCHED เป็น deny-list)

## ที่ยังไม่ได้ตรวจ (ขอบเขตที่เหลือ)

1. **ยังไม่ได้ยิงจริง** — ทุกข้อเป็นการอ่านโค้ด ไม่มี .NET SDK · G2-01 และ G2-02 ควรทำ PoC บน staging ก่อนแก้
   เพื่อยืนยันว่าเส้นทางจบที่ผลลัพธ์ตามที่เขียน (และเพื่อให้มีเคสเทสต์ที่ "ใส่บั๊กกลับแล้วต้องแดง")
2. **`wwwroot/pages/*.html` ฝั่ง XSS** — ตรวจครบเฉพาะ `wwwroot/js/` (20 ไฟล์) + สอง checker ที่มีอยู่ ·
   `documents.html` ~12,000 บรรทัด · `cms-edit.html` 2,733 บรรทัด · `pos-*.html` ยังไม่ได้ไล่ `innerHTML` ทีละจุด
3. **`CmsHtmlSanitizer` เนื้อใน** (allowlist ครอบ `style` / `href=javascript:` / `<svg>` ไหม) และ
   `theme.CustomCss` ที่ฉีดดิบ (`CmsRenderingService.cs:296-299`) — ค้างจากรอบก่อน ยังไม่ได้อ่าน
4. **อีก 55 controller ใน G2-10** — ยืนยันแล้วว่า "ไม่มี marker" แต่ยังไม่ได้เปิดทีละเมธอดเพื่อจัดลำดับว่า
   ตัวไหนอันตรายที่สุด (ตัวที่ยกมาในตารางคือที่เปิดดูแล้วว่าแตะเงิน/สต็อกจริง)
5. **`ImpersonationReadonlyMiddleware`** — G-08 รอบก่อน (P3, `imp_by` ไม่มีใครอ่าน) ยังไม่ได้ตรวจซ้ำว่าปิดหรือยัง
6. **`VendorPortalController` · `PublicPaymentController` · `ContactInquiryController` · `WebhookController`** —
   เส้น anonymous/token ที่ยังไม่ได้ไล่ทีละเมธอด
7. **PDPA retention / breach 72 ชม.** — `PdpaRetentionPurgeJob` และ workflow แจ้ง PDPC ยังไม่ได้เปิดอ่าน
