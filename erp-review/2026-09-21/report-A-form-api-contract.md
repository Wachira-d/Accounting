# ทีม A — สัญญาระหว่างหน้าเว็บกับ API (ฟอร์ม → payload → DTO → บันทึกจริงไหม)

## สรุป 5 บรรทัด

สมมติฐานของรอบนี้ถูกต้อง — defect class เดียวกับรอบ 187/188 **ยังอยู่ทั้งระบบ และหนักกว่าเดิม**:
พบ **6 หน้าที่ "กดสร้างแล้วไม่มีทางสำเร็จเลย"** (โปรเจกต์ · สกุลเงิน · แผนคอมมิชชัน · กฎอนุมัติ · Webhook · รายงานกำหนดเอง)
เพราะ payload ไม่มีช่องที่ DTO ประกาศเป็น non-nullable `string` (⇒ implicit `[Required]`), **1 หน้าที่บันทึกสำเร็จแต่ได้ตัวเลขผิด**
(อัตราแลกเปลี่ยนลง DB เป็น 0), และ **1 หน้าที่แก้ข้อมูลพนักงาน (ชื่อ/เลขบัตร/วันเริ่มงาน) แล้วหายเงียบ** ทั้งที่ขึ้น "แก้ไขสำเร็จ".
ที่สำคัญกว่ารายข้อ: **ด่านสองตัวที่รอบ 187 สร้างขึ้นมากันคลาสนี้ ครอบไม่ถึงของจริง** — `tools/dto_nullable_contract_check.py`
อ่าน positional record ได้แค่บรรทัดแรก ⇒ มองไม่เห็น DTO แบบหลายบรรทัด (ซึ่งคือเกือบทั้งหมด และคือที่ที่บั๊กอยู่) จึงตอบ "0 จุด";
และ `api.js describeFieldErrors` หาช่องด้วย `[name="…"]` ทั้งที่ input ทั้ง wwwroot มี `name=` แค่ **143 จาก 2,271 ช่อง (6%)**
⇒ ผู้ใช้ 94% ของหน้าจะได้ข้อความ "ไม่มีช่องนี้บนหน้านี้ — ฟอร์มส่งค่ามาเอง" ทั้งที่ช่องนั้นอยู่ตรงหน้าเขา (= โกหก, G3).

2. **`pos.html` · `pos-modifiers.html` · `pos-floorplan.html` · `pos-reservations.html` · `pos-kds.html`** — ดูเฉพาะผิวและไม่พบคลาส 1/2 ชัดเจน แต่ยังไม่ได้ไล่ `CreateOrderRequest`/`UpdateOrderRequest` (Create มี `Items`+`SessionId` ที่ Update ไม่มี)
3. **`lodging.html` · `lodging-settings.html`** — เป็นหน้าที่รอบ 187/188 เพิ่งแก้และเป็นสองหน้าเดียวที่มี `name=` ครบ จึงข้ามไปทำหน้าอื่นก่อน · ควรมีคนไล่ซ้ำว่าการแก้รอบก่อนครอบทุกโมดัลจริง
4. **`cms-edit.html` (2,700+ บรรทัด) แท็บอื่นนอกจากสินค้า** (บล็อกเนื้อหา · ฟอร์ม · redirect · ตัวแปรสินค้า)
5. **`bank.html` ฝั่งกระทบยอด/นำเข้า statement** (`ImportBankStatementRequest.FileFormat/Base64Content` non-nullable · `ReconciliationGroupItemRequest.ItemType`)
6. **คลาส 6 แบบเป็นระบบ** — "หน้าเว็บอ่านฟิลด์ที่ endpoint นั้นไม่เคยส่ง" ตรวจได้เฉพาะที่สะดุดตา (`webhooks` `lastDeliveryAt`/`eventTypes` · `approval` `ruleName`/`approverEmails` · `payroll` `bankAccount`) ยังไม่มีการกวาดทั้งเรพ เพราะต้อง map หน้า→endpoint→Response DTO ซึ่งทำอัตโนมัติไม่ได้ด้วย grep ล้วน — เสนอให้รอบหน้าสร้าง index `api.js method → route → controller action → DTO` เป็นเครื่องมือถาวร (จะปิดทั้งคลาส 3/4/6 พร้อมกัน)
7. **ยังไม่ได้คอมไพล์/รันจริง** — env นี้ไม่มี .NET SDK · ข้อสรุปเรื่อง implicit `[Required]` บน **positional record** อนุมานจากพฤติกรรมเดียวกับ `LodgingPropertyDto` (class) ที่ผู้ใช้เจอจริงในรอบ 187 + `Program.cs` ไม่ได้ตั้ง `SuppressImplicitRequiredAttributeForNonNullableReferenceTypes` · main agent ควรยืนยันด้วยเทสต์ 1 ตัวที่ POST payload ของ `projects.html` จริงเข้า `CreateProjectRequest` ก่อนแก้ยกชุด
