# โจทย์ทีมตรวจ รอบ 189 (2026-09-21) — "ไล่ตรวจทั้งหมด ทุกส่วน อีกครั้ง"

คำสั่งเจ้าของโปรเจกต์: **"ตั้งทีมไล่ตรวจสอบ ทั้งหมด ทุกส่วน อีกครั้ง"**

## บริบทที่ทำให้รอบนี้เกิด — อ่านก่อนเริ่ม

สองวันมานี้ผู้ใช้เจอบั๊ก **2 ตัวติดกันในหน้าเดียว** ที่ไม่มีเทสต์/checker ตัวไหนจับได้
และทั้งคู่เป็น **"สัญญาระหว่างหน้าเว็บกับ API ไม่ตรงกัน"**:

1. รอบ 187 — ช่อง "รหัส" ไม่บังคับบนฟอร์ม แต่ DTO ประกาศ `string` (ไม่ใช่ `string?`)
   ⇒ ASP.NET ใส่ `[Required]` โดยปริยาย ⇒ บันทึกไม่ได้ พร้อมข้อความอังกฤษที่อ้าง
   ชื่อ property C# ซึ่งไม่ตรงกับป้ายใด ๆ บนจอ
2. รอบ 188 — ช่องตัวเลขที่เว้นว่างถูกส่งเป็น `null` ⇒ System.Text.Json แปลงเข้า
   `int` ไม่ได้ ⇒ **โยน body ทิ้งทั้งก้อน** ⇒ ไม่มีอะไรถูกบันทึกเลย และ error ชี้ไปที่
   "dto" ที่ไม่มีบนหน้าจอ · กระทบ **6 modal** ในหน้าเดียว

⇒ **สมมติฐานของรอบนี้: ยังมีของแบบนี้อีกทั้งระบบ** งานของทีมคือหาให้เจอก่อนผู้ใช้

## กติกา (บังคับทุกข้อ — ผิดข้อใดข้อหนึ่ง = รายงานใช้ไม่ได้)

1. **เปิดไฟล์จริงทุกข้อ** — ทุก finding ต้องมี `path:line` ที่เปิดแล้วเห็นของจริง
   `grep` ที่ตอบว่า "ไม่มี" **ไม่ใช่หลักฐาน** ต้องเปิดไฟล์ตรงจุด
2. **ห้ามรายงานซ้ำของที่ตรวจแล้วไม่ใช่บั๊ก** — อ่าน § "ตรวจแล้วไม่ใช่บั๊ก / ห้ามแก้" ใน
   `SYSTEM_REVIEW_2026-09.md` §9 · `ERP_REVIEW_2026-09-05.md` · `DECISION_AUDIT_2026-09-18.md` §5 §7 ·
   `DECISION_DOCTRINE.md` §5 · `REGRESSION_ROOT_CAUSE_2026-09-18.md` §6 ·
   `OCR_PIPELINE_REVIEW_2026-09-06.md` §"ตรวจแล้วไม่ใช่บั๊ก" **ก่อนเขียนรายงาน**
3. **ห้ามรายงานของที่ติ๊ก ✅ ไปแล้ว** ในไฟล์ review ข้างต้น
4. **ต้องเขียน "ผู้ใช้เห็นอะไร"** ทุกข้อ — ถ้าเขียนไม่ได้ว่าผู้ใช้เจออาการอะไร แปลว่ายัง
   ไม่ได้พิสูจน์ว่ามันเป็นปัญหาจริง ตัดออก
5. **จัดลำดับ P0–P3**: P0 = ข้อมูลผิด/เงินผิด/กฎหมายผิด/ผู้ใช้ทำงานไม่ได้เลย ·
   P1 = ผิดในบางเคสที่เกิดจริง · P2 = คุณภาพ/ความสม่ำเสมอ · P3 = ปรับปรุง
6. **คุณภาพ > จำนวน** — 5 ข้อที่ยืนยันแล้วดีกว่า 30 ข้อที่เดา · เขียนเฉพาะที่เปิดไฟล์ยืนยันเอง
7. **ห้ามแก้โค้ด** — รอบนี้ตรวจอย่างเดียว main agent จะ verify แล้วแก้เอง

## รูปแบบรายงาน

เขียนลงไฟล์ที่ระบุในโจทย์ของทีมคุณ (`erp-review/2026-09-21/report-<X>.md`) ด้วยรูปแบบ:

```
# ทีม <X> — <ชื่อด้าน>

## สรุป 5 บรรทัด
<อะไรคือภาพรวมที่เจอ>

## ตาราง finding
| ID | P | หัวข้อ | file:line | ผู้ใช้เห็นอะไร | ทำไมถึงผิด | ทางแก้ที่เสนอ |
|----|---|--------|-----------|----------------|-------------|----------------|

## ที่ตรวจแล้วไม่ใช่บั๊ก (กันรอบหน้าเสียเวลาซ้ำ)
| เรื่อง | ทำไมถึงไม่ใช่ |

## ที่ยังไม่ได้ตรวจ (ขอบเขตที่เหลือ)
```

ตอบกลับ main agent เป็น **สรุปสั้น ≤ 25 บรรทัด**: จำนวน finding แยกตาม P + หัวข้อ P0/P1
ทุกข้อพร้อม file:line (รายละเอียดเต็มอยู่ในไฟล์)
