# ทีม F — โมดูลที่พัก · CMS/เว็บไซต์ · ร้านค้าออนไลน์ · payment gateway

_รอบ 189 · 2026-09-21 · เปิดไฟล์ยืนยันทุกข้อ · ไม่แก้โค้ด_

## สรุป 5 บรรทัด

1. **สมมติฐานของรอบนี้ถูก และของจริงยังอยู่ในหน้าเดียวกับที่ผู้ใช้เพิ่งรายงาน** — `lodging-settings.html`
   มี **7 `<select>` ที่สัญญากับ API ไม่ตรงกัน** อีกชุดหนึ่ง คนละกลไกกับรอบ 187/188 (เป็น `<select>`
   ไม่ใช่ `type="number"`) จึงหลุดทั้ง `blank_number_null_check` และ `enum_number_compare_check`
2. **ตัวหนักสุดคือ regression จากรอบ 159** (`196fec1` แปลง `PRICE_MODE`/`EXTRA_CAT`/`SEASON_TYPE` จาก
   "ตารางป้าย" เป็น "ฟังก์ชัน" แต่ไม่ได้ตามไปแก้ `sel(...)` ที่กิน 3 ตัวนี้เป็นตาราง) ⇒
   `Object.entries(ฟังก์ชัน)` = `[]` ⇒ **dropdown ไม่มีตัวเลือกเลย** ⇒ บันทึกแล้ว "วิธีคิดราคา"
   ของบริการเสริมกลายเป็นค่า `0` ที่ไม่มีในระบบ ⇒ **เก็บเงินแขกผิดจำนวน**
3. **แก้ที่พักที่มีอยู่แล้วบันทึกไม่ได้เลย** — ช่อง "ประเภท" เป็น `<option value="1|2|…">` แต่ API
   คืน `"Hotel"` ⇒ select ว่าง ⇒ ส่ง `propertyType: null` เข้า enum ที่ไม่ nullable ⇒ body ถูกโยนทิ้ง
   ทั้งก้อน (อาการเดียวกับที่ผู้ใช้รายงานเมื่อวาน แต่คนละสาเหตุ ยังไม่ถูกแก้)
4. **เส้นเงิน**: ทางแขกจ่ายออนไลน์ (LDG-P0-01) ปิดจริงและออกแบบดี · VAT มาจาก
   `EffectiveVatRateAsync` แหล่งเดียว · **แต่ "คืนเงิน" ประทับสถานะปลายทางเอง** — แขกกดยกเลิกเอง
   แล้ว JE `Cr 111 เงินสด` + ใบลดหนี้ ออกทันทีทั้งที่ยังไม่มีใครโอนเงินคืน และไม่มีคิวงานคืนเงินที่ไหนเลย
5. **หน้าจองสาธารณะ escape ครบ · token เดาไม่ได้ (128-bit CSPRNG)** แต่ `/lodging/info` ที่
   `[AllowAnonymous]` **ปล่อยเลขห้อง · หมายเหตุภายใน · สถานะแม่บ้าน (มีแขก/ห้องเสีย) ทุกห้อง**
   ออกไปให้ใครก็ได้ และหน้าจองคิดจำนวนผู้ใหญ่ต่อห้องด้วยสูตรที่ปัดขึ้น ⇒ คิดเงินเกินจำนวนคนจริง
